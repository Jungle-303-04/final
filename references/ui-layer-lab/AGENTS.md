# Product frontend contract

This directory contains two deliberately separate surfaces and one immutable source snapshot.

- `src/product/` is the production frontend.
- `src/shadcn-lab/` is the backend-independent catalog host served under `/`.
- `src/components/ui/` is generated by the official shadcn CLI for the Base Nova host.
- `vendor/shadcn/upstream/` is byte-preserved official source. Never edit it manually.

Production code must never import from the lab, `src/components/ui`, or vendored registries. Copying an example into the product means rebuilding it behind the production boundaries below, not importing the Preview module.

## Official lab source of truth

- `vendor/shadcn/inventory.json` locks the upstream commit, item counts, source URLs, styles, and SHA-256 hashes.
- The catalog is generated from official Component MDX `ComponentPreview` references, not a handwritten example list.
- `base-nova`, `base-rhea`, `radix-nova`, and `new-york-v4` remain separate namespaces.
- Next.js-only imports are handled by adapters under `src/shadcn-lab/shims/`; upstream files remain unchanged.
- Update the snapshot only with `npm run sync:shadcn -- /absolute/upstream/checkout`, then run all shadcn checks.

## Source of truth

- Backend routes and Pydantic contracts under `../../src/` are authoritative.
- Do not recover, inspect, or copy the deleted `../../frontend/` implementation.
- Do not invent response fields, counts, timestamps, statuses, permissions, or successful states.
- Runtime product code contains no fixture or demo data. Browser tests may mock network responses in test-only files.
- Missing measurements render as unavailable; they are never replaced with synthetic values.

## Dependency direction

```text
product/app -> product/pages -> product/features -> product/shared
product/api  -> product/shared
shadcn lab   -X-> product
product      -X-> shadcn lab / generated UI / vendor
```

- Pages compose features; they do not own transport logic.
- Feature components may import only their own feature, `product/api`, and `product/shared`.
- API calls and runtime response validation live under `product/api`.
- Shared UI has no product-domain knowledge.
- A page or component over 250 lines is a review signal: split by responsibility before adding more behavior.

## Design system

- Raw color values are allowed only in `product/styles/tokens.css`.
- Spacing, typography, radius, shadow, z-index, and motion use named tokens.
- New tokens must express reusable meaning, not a page name or a one-off coordinate.
- Inline `style` is forbidden except for runtime geometry passed through typed CSS custom properties.
- `!important` is forbidden.
- Reuse a shared primitive before adding a new visual variant.
- New global CSS files require an explicit layer: tokens, foundation, shared component, or named page layout. Do not create a stylesheet just to finish one local request.
- Light/dark behavior, keyboard focus, reduced motion, loading, empty, error, stale, and permission-denied states are part of the component contract.

## Data and security

- Requests use same-origin `/api` URLs and `credentials: "include"`.
- Every JSON boundary is parsed from `unknown` with a runtime schema.
- State-changing requests send `x-service-csrf: same-origin`.
- UI visibility is not authorization. Backend 401/403 responses must remain first-class states.
- Direct `fetch` calls outside `product/api` are forbidden.

## Required workflow

Before implementation:

1. Read this file and `PRODUCT_FRONTEND.md`.
2. Read the relevant backend route and response contract.
3. Search production shared UI and tokens for reuse.
4. List the files, API fields, states, and responsive behavior being changed.
5. Call out every proposed dependency, token, or primitive addition.

Before completion:

1. Run typecheck, lint, unit tests, production build, and the design guard.
2. Verify at 390px, 768px, and 1440px.
3. Verify keyboard focus and reduced motion.
4. Capture light/dark screenshots for changed product routes.
5. Report reused and newly introduced tokens/components, plus any unavailable backend capability.

For lab changes, also run `npm run check:shadcn`, `npm run visual:shadcn`, and `npm run audit:shadcn`. The invariant is:

```text
documented item count = catalog item count = source panel count = successful preview count
```
