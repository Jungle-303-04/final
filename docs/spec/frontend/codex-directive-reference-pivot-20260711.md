# 전면 피벗 — 외부 기준 저장소 기능 동등 + 벤치마크 최소선 디자인

## 0. 사용자 확정 결정 (2026-07-11)

1. **treemap/focus-sankey 뷰 계획 전면 철회.** 그 자리(중앙 뷰)는 **미정(TBD)** — 새 커스텀
   뷰를 임의로 설계하지 않는다. 구축된 구조(API 계층·게이트·프록시·등록 플로우)는 유지.
2. **기능·레이아웃·인터랙션·이벤트의 정본 = 외부 기준 저장소** (`로컬 비교 실행 스크립트`로 우리 클러스터에
   연결되어 http://127.0.0.1:9280 에 실행 중인 인스턴스 + 그 소스 저장소).
   RCA가 들어갈 논리 영역만 제외(외부 기준 저장소에 없음 — 우리 RCA 삽입은 후속 별도 지시)하고
   **기능 동등하게** 가져와 **우리 백엔드 API 계약으로** 작동시킨다.
3. **디자인 시스템의 정본 = 벤치마크 최소선**. 두 정본의 역할을 섞지 않는다:
   무엇이 어디에 있고 어떻게 반응하는가 = 외부 기준 저장소, 어떻게 생겼는가 = 벤치마크 최소선.
4. **하드코딩·목업·synthetic 절대 금지** 유지. 우리 백엔드가 계약을 제공하지 못하는 기능은
   가짜로 채우지 않고 §5 갭 대장에 blocked로 올린다.

폐기된 계획은 "폐기 표기"가 아니라 **문서에서 제거**한다(git 이력이 보존하므로 손실 없음).

| `topology-visual-motion-tokens.md` | focus-sankey·treemap·fold 관련 절 전부 제거. 디자인 정본이 벤치마크 최소선으로 바뀌므로 자체 색/치수 토큰 표도 제거하되, **대비 기준(4.5:1/3:1)·reduced-motion·키보드 게이트 원칙은 새 문서로 승계** |

## 2. 두 정본의 사용 규칙

**외부 기준 저장소 (기능·레이아웃·인터랙션)**
- 관찰 원천: 실행 인스턴스 `127.0.0.1:9280` (로컬 비교 실행 스크립트 — game-server·mgmt 연결 상태)
  + 소스 checkout. 화면·동작·이벤트는 실행 인스턴스에서 실측하고 소스로 확정한다.
- 가져오는 것: 라우트/IA, 각 화면의 레이아웃 구조, 목록/상세/드릴 상호작용, 키보드 단축키,
  실시간 갱신 동작(SSE→우리 WS/폴링으로 치환), 필터/검색 문법.
- 가져오지 않는 것: 외부 기준 저장소의 시각 스타일(색·타이포·컴포넌트 룩 — 벤치마크 최소선으로 대체),
  외부 기준 저장소 이름·로고·브랜드 문자열 전부, 외부 기준 저장소의 Go 백엔드(우리 백엔드 사용).

**벤치마크 최소선 (디자인)**
- 제품 전용 UI 생성물을 `src/product` 소유 경로에 설치한다.
  AGENTS.md의 "제품은 lab/vendor 생성물 import 금지" 경계는 **"제품 소유 UI 생성물은
  허용"으로 개정**하고 개정 커밋을 먼저 만든다(기존 lab/vendor를 import하는 것은 여전히 금지).
- 테마 토큰은 벤치마크 최소선 표준 CSS 변수 체계를 따르고, 자체 병렬 토큰 체계를 만들지 않는다.

**라이선스 (필수 절차)**
- 외부 기준 저장소는 Apache-2.0: 코드/구조 이식 시 LICENSE 동봉, `THIRD_PARTY_NOTICES`에 저장소·
  커밋·파일 매핑·변경 요약 기록, 수정 파일에 고지, 상표(이름·로고) 사용 금지.
- 벤치마크 최소선은 MIT: 고지 유지. "100% 동일"은 기능·레이아웃 동등을 뜻하며 브랜드 복제가 아니다.

## 3. 실행 절차 (P1→P4, 각 단계 게이트 통과 후 진행)

**P1 — 외부 기준 저장소 전수표** (산출물: `docs/spec/frontend/reference-feature-inventory.md`)
실행 인스턴스와 소스에서: 전체 라우트/화면 목록, 화면별 구성 요소와 상호작용(클릭/키보드/
실시간 갱신), 그리고 **각 화면이 호출하는 API 전수**(메서드·경로·요청/응답 형태 — 네트워크
관찰 + 소스 확인). RCA 삽입 예정 지점을 표기해 두되 구현하지 않는다.

**P2 — 계약 매핑표** (산출물: `docs/spec/frontend/reference-contract-map.md`)
P1의 API 전수 각각에 대해: `외부 기준 저장소 endpoint ↔ 우리 endpoint(routes.py 근거) ↔ 판정`.
판정은 세 가지뿐 — `직결 가능` / `어댑터 필요(형태 변환)` / `백엔드 갭(BE-Gap-n 등재)`.
갭을 목업으로 메꾸는 선택지는 없다. **P2 커밋 후 검토자 확인을 받고 P3로 진행한다**
(갭 규모가 백엔드 작업량과 범위 결정을 좌우하므로).

**P3 — 벤치마크 최소선 스캐폴드**: AGENTS.md 경계 개정 → 제품 소유 UI 생성물 설치 → 외부 기준 저장소 IA 기준
라우터/셸(사이드바·검색바)을 벤치마크 최소선 컴포넌트 체계로 구축. 기존 `npm run check` 게이트 유지,
design guard는 벤치마크 최소선 체계에 맞게 갱신.

**P4 — 화면별 포팅**: 우선순위는 P2 매핑표에서 `직결 가능` 비율이 높은 화면부터.
각 화면 완료 조건: (a) 우리 실 API(game-server)로 렌더, (b) 외부 기준 저장소 인스턴스와 나란히 놓고
동일 조작 → 동등 결과 확인(체크리스트를 progress 파일에 기록), (c) `npm run check`,
(d) 하드코딩·synthetic 스캔 0건, (e) 백엔드 갭 기능은 UI에 존재하지 않음(disabled도 금지).
