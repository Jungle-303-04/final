# VP-014 — 남은 화면

`references/ui-layer-lab/src/product/`에는 **Home · Resources · Issues** 세 화면만
구현돼 있다. 나머지는 라우트 슬롯이거나 아예 없다. 이 문서가 그 전부의 정본이다.

---

## 0. 제품의 뼈대 — 화면이 왜 나뉘는가

Opsia는 **하나의 루프**다.

```
        PR ──────▶ Git ──────▶ 클러스터 ──────▶ 장애 ──────▶ 복구 PR
                                                                │
                    └───────────────────────────────────────────┘
```

각 화면은 이 루프의 **한 정거장**이다. 그래서 중복이 생기지 않는다.

| 화면 | 렌즈 | 답하는 질문 |
|---|---|---|
| **Home** | 요약 | 지금 내가 봐야 할 게 뭔가 |
| **Resources** | **낱개 리소스** | 클러스터에 뭐가 있나 (파드·디플로이먼트·서비스…) |
| **Applications** | **앱 단위 묶음** | 내 앱들이 건강한가. 어떤 버전이 떠 있나 |
| **GitOps** | **변경** | 무엇이 바뀌려 하는가. 승인할까 |
| **Issues** | **사건** | 뭐가 왜 터졌나. 어떻게 고치나 |
| **Checks** | **위험** | 터지기 전에 뭐가 위험한가 |
| **Settings** | 설정 | |

### 0.1 중복 금지 — 두 규칙 (절대)

**규칙 1. 한 사실은 한 화면이 소유한다.**
다른 화면은 **요약 + 링크**만 한다. 같은 목록을 두 번 렌더하지 않는다.

**규칙 2. 드릴다운은 소유 화면으로 이동한다.**
필터를 걸어서 보낸다. 화면 안에 다른 화면을 임베드하지 않는다.

| 사실 | 소유 화면 | 다른 화면의 표현 |
|---|---|---|
| 파드·리소스 목록·상세 | **Resources** | Applications는 종류별 개수 + "전체 보기 →" |
| 앱의 헬스·버전·구성 | **Applications** | Home은 카드 요약, Issues는 링크 |
| PR·승인·변경 diff | **GitOps** | Applications는 "최근 배포" 링크 |
| 인시던트·RCA | **Issues** | Applications·Home은 개수 + 링크 |
| 정책 위반·위험 | **Checks** | Home은 개수 + 링크 |

### 0.2 화면을 잇는 다리 = 필터 (VP-010)

공통 축 4개가 **화면을 바꿔도 유지된다**:
```
클러스터 · 네임스페이스 · 애플리케이션      ← 구조적 축 (유한, 목록화)
라벨                                       ← 발견형 축 (블로그 태그처럼 검색, AND 결합)
```

**애플리케이션이 이미 필터의 한 축이다.** 그래서 드릴다운이 자연스럽다:

```
Applications > checkout-api > [리소스 탭] > "전체 보기 →"
  → /resources?applications=checkout-api

그 상태로 Issues로 이동하면
  → checkout-api의 인시던트만 보인다 (칩이 유지된다)
```

## 1. Applications — 앱 단위로 묶어 보는 화면

### 1.1 정체

쿠버네티스는 리소스가 낱개로 흩어진다:
```
Deployment/checkout-api · Service/checkout-api · ConfigMap/checkout-api-config
Secret/checkout-db · HPA/checkout-api · Ingress/checkout
```
사람은 이렇게 생각하지 않는다. **"checkout-api"** 하나로 생각한다.

**Applications = 흩어진 리소스를 의미 있는 덩어리로 묶어 보여주는 화면이다.**
Applications는 **입구**고, Resources는 **작업대**다.

### 1.2 목록 (앱 카드)

VP-010 필터 바 아래에 카드 그리드. 표 모드도 제공(토글).

```
┌─ checkout-api ─────────────────────── prod ─┐
│  ● 정상            파드 5/5                  │
│  배포   v2.4.1 (a3f9c2) · 2시간 전 · 김민수  │
│  ⚠ Git과 다름   replicas 3 → 1 (수동 변경)   │
│  리소스 6개                                  │
│  인시던트 없음                                │
└──────────────────────────────────────────────┘
```

카드에 담기는 것 (전부 서버 계약 필수. 없으면 렌더하지 않는다):

| 항목 | 설명 |
|---|---|
| 이름 · 환경 | |
| 헬스 | 준비된 파드 / 전체 파드. 색은 status 토큰 |
| 배포 | 현재 떠 있는 버전 + git SHA + 시각 + 배포자 |
| **드리프트** | Git과 다르면 **한 줄로** 요약. 같으면 이 줄을 렌더하지 않는다 |
| 리소스 개수 | 종류별 합계 |
| 인시던트 | 열린 인시던트 개수. 0이면 "없음" |

**드리프트는 카드의 한 줄일 뿐이다. 화면의 정체성이 아니다.**

**목록 정렬 기본값**: 문제 있는 것 먼저 (인시던트 > 드리프트 > 헬스 저하 > 정상).

### 1.3 상세 — 5탭

```
checkout-api                                     [prod]

[개요]  [리소스]  [배포 이력]  [차이]  [인시던트]
```

**개요**
- 헬스 (파드 상태, 재시작 횟수)
- 현재 버전 (이미지 digest, git SHA, 배포 시각)
- 엔드포인트 (Ingress/Service 주소)
- 최근 활동 3줄 (배포·인시던트·변경 혼합 타임라인)

**리소스** — **목록을 다시 그리지 않는다** (규칙 1)
```
Deployment   1
Service      1
ConfigMap    2
Secret       1
HPA          1
Ingress      1
─────────────────────────
[Resources에서 전체 보기 →]   /resources?applications=checkout-api
```
종류별 개수만. 클릭하면 필터가 걸린 Resources로 이동.
**표·정렬·그래프·시간 스크럽 바를 두 번 만들지 않는다.**

**배포 이력**
- 언제 무엇이 배포됐나 (시각 · git SHA · 배포자 · 결과)
- 각 항목 클릭 → **GitOps의 해당 변경**으로 이동
- 목록은 요약만. diff는 GitOps가 소유한다.

**차이** — 드리프트 diff
- **Git(desired) ↔ 클러스터(live)** 의 정책 스코프 시맨틱 diff
- 필드 단위로: `spec.replicas: 3 → 1`
- **누가·언제 바꿨는지** (감사 로그에서 상관)
- 액션 두 개:
  - **[Git대로 되돌린다]** — 클러스터를 desired로 되돌린다. 즉시 적용 가능.
  - **[현재 상태를 Git에 반영한다]** — **반드시 PR로만.** Git을 직접 고치지 않는다.
    (단일 writer 불변식. Opsia는 Git에 직접 커밋하지 않는다.)
- 차이가 없으면 "Git과 일치합니다" 한 줄. **빈 diff를 그리지 않는다.**

**인시던트**
- 이 앱에서 난 인시던트 목록 (요약 3줄)
- [Issues에서 전체 보기 →] `/issues?applications=checkout-api`

## 2. GitOps — 변경을 보는 화면

### 2.1 정체

**Applications는 뒤를 본다** (Git → 클러스터로 이미 나간 결과).
**GitOps는 앞을 본다** (Git에 들어오려는 변경).

```
        PR ──────▶ Git ──────▶ 클러스터
           GitOps        Applications
          (들어올 것)      (나간 결과)
```

### 2.2 목록

```
🔍 Filter...   [상태 ▾] [유형 ▾] [Labels]      [표] [그래프]

┌──────────────────────────────────────────────────────────┐
│ ⏳ PR #42   checkout-api  replicas 3 → 5                  │
│    사람 · 김민수 · 10분 전            [검토 →]            │
├──────────────────────────────────────────────────────────┤
│ 🤖 PR #43   payment-api   image v2.1 → v2.0 (되돌리기)    │
│    **Opsia 자동 복구** · 인시던트 #17  [검토 →]           │
├──────────────────────────────────────────────────────────┤
│ ✅ PR #41   auth-api      env 추가                        │
│    사람 · 병합됨 · 2시간 전                               │
└──────────────────────────────────────────────────────────┘
```

컬럼: 상태(대기/승인/병합/거부) · **유형(사람 / Opsia 자동 복구)** · 앱 · 요약 · 작성자 · 시각

**유형 배지가 중요하다.** Opsia가 만든 복구 PR은 시각적으로 구별돼야 한다.
그게 우리 제품의 핵심 산출물이다.

### 2.3 상세 — 이 화면의 심장

```
PR #42  ·  checkout-api  ·  replicas 3 → 5

┌ 변경 내용 ────────────────────────────────────┐
│  spec.replicas:  3  →  5                       │
│  (정책 스코프 시맨틱 diff. 원본 YAML 보기 토글) │
└────────────────────────────────────────────────┘

┌ ⚠ 3-way 경고 ─────────────────────────────────┐
│  클러스터의 현재 값은 **1** 입니다.             │
│  이 PR을 병합하면 그 수동 변경이 5로 덮어써집니다. │
│                                                │
│  Git      3                                    │
│  클러스터  1   ← 07-13 03:12, kubectl 수동 변경 │
│  이 PR    5                                    │
│                                    [차이 보기 →] │
└────────────────────────────────────────────────┘

[승인]  [거부]
```

**3-way 경고가 우리 차별점이다.**
일반 GitOps 도구는 Git↔PR만 본다. 우리는 클러스터의 현실까지 알기 때문에
"이 병합이 무엇을 조용히 덮어쓰는가"를 경고할 수 있다.

**경고 조건**: PR이 건드리는 필드 중 **클러스터 값이 Git과 다른 필드**가 있을 때만.
없으면 이 블록을 **렌더하지 않는다.** (경고를 남발하면 아무도 안 본다.)

**Opsia가 만든 복구 PR이면 추가로:**
```
┌ 왜 이 PR인가 ──────────────────────────────────┐
│  인시템트 #17 · payment-api CrashLoopBackOff    │
│  근본 원인: 이미지 v2.1의 잘못된 env 참조        │
│  증거 4건 (로그·이벤트·메트릭·변경 상관)         │
│                          [인시던트 보기 →]      │
└────────────────────────────────────────────────┘
```
이것이 **verified revert PR**이다. 증거 없는 자동 PR은 만들지 않는다.

## 3. Checks — 아직 안 터진 위험

### 3.1 정체

**Checks = 터지기 전. Issues = 이미 터진 후.**

Checks는 정책·구성·모범사례 위반을 찾는다. 장애가 아니다. **장애의 씨앗**이다.

예:
```
⚠ 높음   checkout-api    replicas 1 — 단일 장애점
⚠ 높음   payment-api     이미지 태그가 :latest — 재현 불가능
⚠ 중간   auth-api        리소스 limits 없음 — 노드 전체를 굶길 수 있음
⚠ 중간   checkout-api    PodDisruptionBudget 없음 — 노드 드레인 시 전면 중단
⚠ 낮음   payment-api     livenessProbe 없음
🔴 높음  auth-api        Secret이 평문 env로 노출
```

### 3.2 목록

VP-010 필터 + 심각도·카테고리 축.
카테고리: `가용성` · `보안` · `재현성` · `리소스` · `관측성`

각 항목:
- 심각도 · 앱 · 리소스 · 규칙 이름 · 한 줄 설명
- **왜 위험한가** (사람 말로. "replicas 1" 이 아니라 "파드 하나가 죽으면 서비스가 멈춥니다")
- **어떻게 고치나** → **[수정 PR 만들기]**

### 3.3 액션 — Checks의 출구는 GitOps다

```
[수정 PR 만들기]  →  Opsia가 PR을 만든다  →  GitOps 화면으로 이동
```

**Checks는 스스로 고치지 않는다.** 항상 **PR을 만들어 GitOps로 보낸다.**
이것이 단일 writer 불변식이다. 그리고 이게 루프를 닫는다:

```
Checks(위험 발견) → GitOps(PR) → Git → 클러스터 → Applications(반영 확인)
```

### 3.4 백엔드 계약

| ID | 계약 | 규칙 |
|---|---|---|
| BQ-049 | `GET /checks` — 점검 결과 목록 | VP-010 필터 + 심각도·카테고리. **규칙 ID·설명·수정 가능 여부 포함** |
| BQ-050 | `GET /checks/rules` — 규칙 카탈로그 | 프론트가 규칙 목록을 하드코딩하지 않는다 |
| BQ-051 | `POST /checks/{id}/fix` — 수정 PR 생성 | **PR만 생성.** 직접 적용 금지. 생성된 change ID 반환 |

**BE-Gap 규율**: 백엔드에 규칙이 없으면 그 카테고리를 렌더하지 않는다.
"곧 지원 예정" 같은 빈 칸을 만들지 않는다.

## 4. Settings

좌측 하위 내비게이션 + 우측 내용. 모두 shadcn `sidebar` + `form`.

| 절 | 내용 |
|---|---|
| **워크스페이스** | 이름, 기본 클러스터, 시간대 |
| **클러스터** | 등록된 클러스터 목록, 연결 상태, **에이전트 설치 명령**(한 줄 복사), 삭제 |
| **저장소** | 연결된 Git 저장소, 브랜치, 경로, 재연결 |
| **멤버·권한** | 멤버 목록, 역할, 초대, 그룹 |
| **알림** | 채널(외부 메시징/이메일/Webhook), 규칙, **Webhook 검증 흐름 보존** |
| **정책** | 자동 복구 허용 범위, 승인 필수 조건, 점검 규칙 on/off |

**클러스터 등록이 데모의 시작점이다** (코치 피드백: "설치·연결부터 보여줘라").
한 줄 설치 명령을 **크게, 복사 버튼과 함께** 보여준다.

기존 `features/org/**`, `features/notifications/{AlertChannelsView,OpsView}` 를
여기로 흡수한다. **shadcn으로 재작성한다.**

### 4.1 백엔드 계약
기존 org/notifications API를 재사용한다. 신규 계약은 **정책** 절에만 필요할 수 있다.
착수 전에 실측하고 없는 것만 BQ로 등록하라.

## 5. AI — 우하단 상시 플로팅 버튼 (우녕 확정)

### 5.1 형태

**어느 화면에 있든 우하단에 동그란 아이콘이 상시 떠 있다.**

```
                                            ┌─────┐
```

- `position: fixed; right: 24px; bottom: 24px`

- 크기 56px 원형. 아이콘은 lucide (`sparkles`).

- **모바일에서도 유지.** 단 하단 내비와 겹치지 않게 위치 조정.

### 5.2 열면 — 맥락을 물고 온다

클릭하면 우측에서 패널이 열린다 (shadcn `sheet`).
**핵심: 지금 보고 있는 것을 안다.**

```
┌ Opsia AI ──────────────────────────────┐
│                                          │
│  지금 보고 있는 것:                       │
│  [Resources] [prod-eks] [checkout-api]   │  ← 현재 화면 + 필터 칩
│                                          │
│  제안:                                   │
│  · 이 앱에 최근 무슨 변경이 있었어?        │
│  · 왜 replicas가 1이야?                   │
│  · 이 파드가 왜 재시작했어?                │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ 질문하세요...                       │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**맥락으로 넘기는 것:**
- 현재 화면 (`resources` / `issues` / `applications` …)
- 현재 필터 (VP-010 URL 상태 전체)
- 선택된 항목 (열려 있는 상세 시트의 리소스·인시던트·앱 ID)
- 시간 스크럽 위치 (VP-012의 `t.at`)

**제안 질문은 맥락에서 파생된다.** 하드코딩하지 않는다.
인시던트 상세를 보고 있으면 "이 장애의 원인이 뭐야?"가 뜬다.

### 5.3 답변 규율 (BE-Gap의 AI 버전)

- **증거 없이 답하지 않는다.** 답변에는 항상 **근거 링크**가 붙는다
  (로그·이벤트·메트릭·변경·인시던트로 이동).
- **추측을 사실처럼 말하지 않는다.** 모르면 "그 데이터가 없습니다"라고 한다.
- **행동을 자동 실행하지 않는다.** 제안만 하고, 실행은 사용자가 버튼을 누른다.
  (복구 제안 → GitOps PR 생성 버튼)

### 5.4 별도 메뉴는 만들지 않는다

기존 `features/chat/**` (사이드바의 "AI 채팅" 메뉴)를 **폐기한다.**
AI는 메뉴가 아니라 **어디에나 있는 도구**다.
맥락 없는 챗은 쓸모가 적다. 맥락을 문 챗이 쓸모 있다.

`⌘K` 커맨드 팔레트에서도 같은 패널을 연다.

```
Home          위젯 대시보드 (VP-011)
Resources     낱개 리소스 · 필터 · 그래프 · 시간 스크럽 (VP-012)

Checks        위험 · 수정 PR (VP-014 §3)
Settings      워크스페이스 · 클러스터 · 저장소 · 멤버 · 알림 · 정책 (VP-014 §4)

              ✦  ← 우하단 상시 AI 버튼 (VP-014 §5)
```

**제거되는 것:**
- `AI 채팅` 메뉴 → 우하단 플로팅 버튼으로 대체
- `카탈로그` → Resources에 흡수
- `메트릭` → Resources 스파크라인·차트에 흡수
- `Topology` · `Timeline` · `Live Traffic` → Resources 그래프에 흡수 ([D-028])

## 7. 구현 순서

```
1. Applications  ← 가장 큰 가치. 앱 단위 렌즈가 없으면 리소스가 흩어져 보인다
2. GitOps        ← 3-way 경고가 우리 차별점. 데모의 클라이맥스
3. AI 플로팅 버튼 ← 작고, 어디서나 보이고, 인상적
4. Settings      ← 클러스터 등록이 데모의 시작점
5. Checks        ← 루프를 닫는다
```

**각 화면 = 여러 개의 작은 커밋.** 화면 하나를 통째로 들고 있지 마라.
목록 먼저 → 상세 → 액션 순으로 쪼개서 착륙시켜라.

**계약이 없는 것은 렌더하지 않는다.** BQ-039~053을 병렬로 착륙시켜라.

## 8. 금지 사항

- **같은 목록을 두 화면에서 렌더하지 않는다.** 요약 + 링크만.
- **Applications 상세에 리소스 표를 만들지 않는다.** 개수 + "전체 보기 →".
- **Git에 직접 커밋하지 않는다.** 모든 쓰기는 PR이다 (단일 writer).
- **3-way 경고를 남발하지 않는다.** live ≠ desired인 필드가 있을 때만.
- **AI가 행동을 자동 실행하지 않는다.** 제안 + 버튼.
- **AI가 증거 없이 답하지 않는다.** 근거 링크 필수.
- **계약 없는 필드를 0·disabled로 렌더하지 않는다** (BE-Gap 규율).
- **차이가 없을 때 빈 diff를 그리지 않는다.** "일치합니다" 한 줄.
- 색·간격·모서리·duration 하드코딩 금지. 토큰만.
- primitive는 `frontend/src/components/ui/` 한 곳뿐.
