# VP-016 — 실행 계획

## 0. 원칙

### 0-1. 수직 슬라이스 (Vertical Slice)

**절대 금지: "백엔드 계약을 다 만들고 나서 프론트를 만든다."**
그러면 몇 주 동안 화면에 아무 변화가 없다. 팀원이 진행을 볼 수 없다.

**모든 슬라이스는 세로로 자른다:**
```
백엔드 계약 1개  →  계약 테스트  →  프론트 소비  →  게이트  →  push  →  자동 배포
                                                                          ↓
                                                        팀원이 URL 열어서 눈으로 확인
```

**한 슬라이스가 끝나면 배포된 화면이 실제로 달라진다.** 이게 유일한 완료 기준이다.

### 0-2. 슬라이스 크기

| 항목 | 기준 |
|---|---|
| 커밋 | **한 슬라이스 = 3~6 커밋** (계약 / 테스트 / 프론트 / 통합) |
| 시간 | **한 슬라이스 = 반나절 이내** |
| 사이클 | **한 커밋 = 30분 이내.** 넘으면 더 쪼갠다 |
| 배포 | **슬라이스 완료 시 반드시 배포.** 배포 안 된 슬라이스는 완료가 아니다 |

### 0-3. 팀원 확인 경로

**`docs/auto/deploy-status.md`를 세션이 자동 갱신한다:**

```markdown
## 지금 배포된 것

배포 SHA : a3f9c2e  (2026-07-15 14:32)
URL      : https://k8s.woonyong.org

### 완료된 슬라이스
- [x] S1  Clusters 목록          ← 클러스터 카드가 보입니다
- [x] S2  클러스터 연결 위자드    ← ＋ 버튼 → 한 줄 명령 복사
- [x] S3  태그형 검색            ← 검색창에 타이핑 → 타입별 제안
- [x] S4  물리 뷰 그래프          ← BQ-074 + ELK/@xyflow + FLIP, public 배포 추적 중
- [x] S5  표 + 스파크라인          ← BQ-030 batch + canonical smart columns, public 배포 추적 중

### 이번 슬라이스에서 확인할 것
1. https://k8s.woonyong.org/clusters 접속
2. 검색창에 "check" 입력 → [애플리케이션] 그룹에 checkout-api가 뜨는가
3. 선택 → 칩이 [앱: checkout-api] 로 붙는가
4. 표가 좁혀지는가
```

**팀원은 이 파일만 보면 "지금 뭐가 되는지"와 "어떻게 확인하는지"를 안다.**

### 0-4. 실패 방지 규율

- **계약 없이 프론트를 만들지 않는다.** BE-Gap 규율.
- **프론트 없이 계약만 만들지 않는다.** 소비되지 않는 계약은 검증되지 않는다.
- **슬라이스 안에서 백엔드→프론트 순서.** 계약이 먼저 착륙하고, 같은 슬라이스 안에서 소비.
- **각 커밋은 초록.** dev = 배포다.
- **회귀 가드를 함께 만든다.** 슬라이스마다 "이게 깨지면 FAIL"을 테스트로 박는다.

## 1. 슬라이스 순서 — 데모 서사 순

**데모 서사(VP-015 §10) 순서로 만든다.** 그래야 언제 멈춰도 앞부분은 시연할 수 있다.

```
S0  모션 기반 (VP-017)     ★    ← 토큰·훅·테스트. 화면 변화 없음. 반나절.
S1  Clusters 목록                ← 첫 화면. 즉시 눈에 보인다.
S2  클러스터 연결 위자드          ← 데모의 첫 30초
S3  태그형 검색 (1층)            ← 모든 화면의 기반
S4  물리 뷰 그래프 (2층)         ← 코치의 핵심 요구
S5  표 + 스파크라인 (3층)        ← 골격 완성
S6  상세 패널 3단계              ← 드릴다운
S7  AI 패널 기하학               ← ✦ 버튼
S8  하단 독 + 로그 스트림        ← 로그
S9  관계 뷰 토글                 ← 앱이 어떻게 엮였나
S10 Applications                 ← 앱 단위 렌즈
S11 시간 스크럽 (TimelineStrip)  ← 과거로 돌아가기
S12 Issues + RCA + 증거          ← 장애 분석
S13 변경 적용 진행 (독 탭)  ★    ← 데모의 클라이맥스
S14 GitOps (변경 + 동기화 2탭)   ← Git 이력
S15 Checks (31개 감사)           ← 예방
S16 Settings + 정책              ← 마무리
S17 Home 위젯 조합 시스템        ← 마지막
```

**S1~S8이 끝나면 이미 시연 가능한 제품이다.**

## 2. 슬라이스 상세

각 슬라이스: **백엔드 계약 → 계약 테스트 → 프론트 → 회귀 가드 → 배포 → 확인 체크리스트**

### S0 · 모션 기반 ★ (유일하게 수직 슬라이스가 아닌 슬라이스)

**이것만 예외다.** 화면이 안 바뀐다. 하지만 **S1부터 모든 슬라이스가 이걸 쓴다.**
나중에 얹으려 하면 애니메이션이 컴포넌트마다 다르게 인라인되고, 그때는 못 고친다.

**백엔드: 없음.**

**프론트 (VP-017 전체)**
```
web/src/motion/
  tokens.css                ← VP-017 §1 토큰. theme.css가 import
  useCameraMorph.ts         ← FLIP. 순수 DOM 함수 + 훅
  useStagger.ts             ← 상한 클램프
  usePrefersReducedMotion.ts
  __tests__/camera-morph.test.ts
  __tests__/stagger.test.ts
```

**회귀 가드**
- 컴포넌트 안에 `@keyframes`나 `animate()` 인라인이 있으면 FAIL (motion/ 에서만)
- `prefers-reduced-motion` 처리가 없으면 FAIL
- `transform`/`opacity` 외의 속성을 애니메이션하면 FAIL (패널·AI의 `width` 예외만 허용)

**확인 체크리스트**
```
1. 유닛 테스트 초록
2. 배포되지만 화면은 그대로 (회귀 없음)
```

### S1 · Clusters 목록

**백엔드 (BQ-069)**
```
GET /clusters
→ [{ id, name, provider(aws|gcp|azure|onprem), connection_status,
     server_count, pod_count, app_count, open_incidents, last_seen_at }]
```
- **BE-Gap 규율**: 값을 모르면 `null`. 0으로 채우지 않는다.
- `provider`는 enum. 브랜드 문자열을 그대로 넘기지 않는다.

**프론트**
- `/clusters` 라우트 + 사이드바 최상단 메뉴
- 클러스터 카드 (provider 로고 · 연결 상태 · 서버/파드/앱 개수 · 인시던트)
- **★ 예고 블록**: 카드 안에 `server_count`만큼 20×14px 블록을 그린다 (5개 + `+N`).
  각 블록에 `data-morph-id="server:<cluster_id>:<i>"`. **S4의 카메라 모프가 이걸 짝으로 쓴다.**
- 카드는 `node-land` + `--stagger-node` 스태거로 착지 (VP-017 §3)
- 카드 클릭 → `/resources?clusters=<id>` (필터 칩 추가)
- 연결 끊김 카드는 회색 + "N시간 전 마지막 응답"

**회귀 가드**
- `null` 필드를 0으로 렌더하면 FAIL
- provider 로고가 하드코딩 문자열 매칭이면 FAIL (enum만)
- 예고 블록에 `data-morph-id`가 없으면 FAIL (S4가 깨진다)

**확인 체크리스트**
```
1. /clusters 접속 → 카드가 보이는가
2. 각 카드에 provider 로고가 맞게 나오는가
3. 카드 클릭 → /resources?clusters=... 로 가고 칩이 붙는가
4. 연결 끊긴 클러스터가 회색인가
```

### S2 · 클러스터 연결 위자드

**백엔드 (BQ-070, BQ-071)**
```
POST /clusters/connect  { name, provider }
→ { cluster_id, install_command, expires_at }     ← 한 줄 명령을 서버가 만든다

GET /clusters/{id}/connection
→ { status: "waiting"|"connected"|"expired", agent_version?, connected_at? }
```
- `install_command`는 **서버가 생성**한다. 프론트가 문자열을 조립하지 않는다.
- 토큰이 들어가므로 **일회용 + 만료**가 있어야 한다.

**프론트**
- `＋ 클러스터 추가` → 4단계 위자드 (shadcn `dialog` + `stepper`)
- STEP 3: 명령 + **복사 버튼** + 연결 대기 폴링 (2초 간격)
- 연결되면 STEP 4 → `[클러스터 보기 →]`

**회귀 가드**
- `install_command`를 프론트가 조립하면 FAIL
- 토큰이 로그·콘솔에 찍히면 FAIL

**확인 체크리스트**
```
1. ＋ 버튼 → 위자드가 열리는가
2. "연결하기" → provider 선택 → 명령이 나오는가
3. 복사 버튼이 동작하는가
4. (실제로 다른 클러스터에서 실행) → 자동으로 STEP 4로 넘어가는가
```

### S3 · 태그형 검색 (1층)

**백엔드 (BQ-073)**
```
GET /filter-facets?q=check&clusters=...&namespaces=...
→ {
    clusters:     [{ id, label, count, count_completeness }],
    namespaces:   [{ id, label, cluster_id, count, count_completeness }],
    applications: [{ id, label, count, count_completeness }],
    labels:       [{ key, value, count, count_completeness }],
    resources:    [{ id, label, kind, count, count_completeness }]
  }
```
- `q`가 비면 **구조적 축(클러스터/네임스페이스/앱)만** 반환 (유한하니까).
- `q`가 있으면 라벨·리소스도 검색해서 반환.
- `count`는 **이미 걸린 다른 필터를 적용한 뒤**의 결과 수.
- projection이 없거나 불완전하면 `count_completeness=unavailable|partial`로 내리고,
  미확인 수를 `0`으로 합성하지 않는다.

**프론트**
- 1층 검색창 (shadcn `command` popover)
- 타입별 그룹핑 제안 → 선택 → **타입이 붙은 칩**
- 칩 결합: 같은 타입 OR / 다른 타입 AND / **라벨끼리 AND** (popover에 고지)
- URL 동기화 (VP-010 canonical serializer)
- 현재 canonical URL에는 resource-id 집합 축이 없으므로 resource 제안은
  `resources.q=<server label>`로 좁힌다. 단일 리소스 identity는 상세 query에서만 사용한다.
- **모든 목록 화면에서 같은 컴포넌트, 같은 위치**

**회귀 가드**
- 축 목록을 프론트가 하드코딩하면 FAIL
- 검색창 위치가 화면마다 다르면 FAIL (레이아웃 테스트)

**확인 체크리스트**
```
1. 검색창 클릭 → 구조적 축이 목록으로 뜨는가
2. "check" 입력 → 앱·라벨·리소스가 타입별로 뜨는가
3. 선택 → [앱: checkout-api ✕] 칩이 붙는가
4. 표가 좁혀지는가 / URL이 바뀌는가
5. 다른 화면으로 가도 칩이 유지되는가
```

### S4 · 물리 뷰 그래프 (2층) ★

**백엔드 (BQ-074)**
```
GET /topology?view=physical&clusters=<id>&<filters>
→ {
    servers: [{ id, name, cpu_pct, mem_pct, status }],
    pods: [{ id, name, server_id, usage_pct, phase, restarts,
             matches_filter: bool }],          ← ★ 필터 매칭 여부를 서버가 준다
    truncated: { server_id: count }             ← 12개 초과분
  }
```
- **`matches_filter`가 핵심.** 흐리게 그릴지 선명하게 그릴지를 서버가 판정한다.
  프론트가 필터를 두 번 적용하면 반드시 어긋난다.
- `usage_pct`는 **requests 대비**. 없으면 `null` (0 아님).
- 축약(12개)은 **서버가 문제 우선으로 정렬해서** 자른다.

**프론트**
- @xyflow/react + ELK 레이아웃 (Radar `topology/layout.ts` 이식)
- **서버 카드** (아이콘 + CPU/MEM 막대)
- **파드** — 크기 고정 / 채움=사용률 / 배지=비정상 (VP-015 §4.2)
- 필터 안 맞는 파드는 opacity 20%, 클릭 불가
- `+N개` → 3층 표로 스크롤 (`?node=<id>`)
- 필터 0개 → **클러스터 격자** (§2.3의 줌)
- **★ 카메라 모프 (VP-017 §4)**: 클러스터 카드 클릭 시 S1의 예고 블록(`data-morph-id`)이
  서버 카드로 **커지며 전이**한다. 줌아웃은 역방향. `useCameraMorph`를 쓴다.
- **★ 골격 먼저**: 필터 칩이 붙는 즉시 서버 골격을 그린다 (개수는 S1에서 이미 안다).
  `/topology` 응답이 오면 파드가 `pod-pop`으로 착지, CPU 막대가 `--motion-value`로 보간.
  **스켈레톤 깜빡임 금지.**
- 브레드크럼(`전체 › prod-eks › checkout-api`) = 필터 칩의 다른 표현. 클릭 시 그 단계로 되감김.

**회귀 가드**
- 파드 크기가 데이터에 따라 변하면 FAIL
- 색이 상태를 뜻하면 FAIL (색 = 사용률만)
- 배지가 정상 파드에 붙으면 FAIL
- 파드를 12개 넘게 그리면 FAIL
- 프론트가 필터를 다시 적용하면 FAIL (`matches_filter`만 쓴다)
- 줌 전환 시 화면이 흰색으로 깜빡이면 FAIL
- 파드가 스태거 없이 동시에 나타나면 FAIL
- `/topology` 응답을 기다리며 서버 골격이 안 그려지면 FAIL

**확인 체크리스트**
```
1. 클러스터 선택 → 카드 안 작은 블록이 서버 카드로 커지며 전이하는가 (카메라 이동)
2. 서버 위에 파드가 같은 크기로 하나씩 톡톡 튀어나오는가
3. 부하 높은 파드가 빨갛게 채워지는가
4. CrashLoop 파드에 ✕ 배지가 뜨는가 (채움은 회색인데도!)
5. 필터를 걸면 → 안 맞는 파드가 흐려지는가 (사라지지 않고)
6. 서버 카드 하단에 "3 / 18"이 나오는가
7. 파드 12개 넘으면 "+N개"가 나오는가
8. 필터를 다 지우면 → 서버 카드가 클러스터 카드 안 블록으로 되감기는가
9. OS 설정에서 "동작 줄이기"를 켜면 → 애니메이션 없이도 정보가 다 보이는가
```

### S5 · 표 + 스파크라인 (3층)

**백엔드 (BQ-055, BQ-030)**
```
GET /resources?<filters>          → 목록 + kind별 필드
GET /metrics/history?ids=...      → 스파크라인 시계열
```
- BQ-055 count는 `GET /resources`의 `counts`가 정본이다.
- BQ-030 history는 stable pod ID 최대 100개를 한 요청으로 받고 같은 권한·필터·snapshot에
  다시 교차 검증한다. 데이터 없으면 빈 points/null. **0으로 그리지 않는다.**

**프론트**
- Radar의 `KNOWN_COLUMNS`/`CellContent` 패턴을 참고하되 raw Kubernetes detail renderer를
  목록에 섞지 않는다. Opsia canonical facts가 있는 pod/node/workload/service/event만 smart column.
- canonical fact 정렬 · snapshot-safe cursor 페이지네이션 · 행/스파크라인 상세 선택
- 단일 batch 추세 스파크라인 (Recharts). 실측 CPU가 2점 미만이면 빈칸.
- **2층 그래프와 같은 결과** — 필터가 둘 다에 적용

**확인 체크리스트**
```
1. 표가 kind별로 맞는 컬럼을 보여주는가
2. 스파크라인이 그려지는가 / 데이터 없으면 빈칸인가
3. 필터를 걸면 표와 그래프가 같은 개수를 보여주는가
```

### S6 · 상세 = **전체화면 덮기** (2상태) ★ 우녕 확정 2026-07-14

**이전 계획(3단계 패널)은 폐기됐다. VP-015 §5.2가 정본이다.**

**백엔드 (기존 + BQ-061)**
```
GET /resources/{kind}/{ns}/{name}   → 상세
GET /capabilities?resource=...      → ★ 권한 (어떤 버튼을 그릴지)
```

**프론트**
- 행/파드 클릭 → 상세가 **콘텐츠 영역 전체를 덮는다.** 목록은 안 보인다.
  480px 중간 상태 **없음**. 드래그 리사이즈 **없음**. 상태는 `닫힘 | 열림` 둘뿐.
- 사이드바 → **56px 레일**. 라벨은 `width:0 + overflow:hidden`으로 잘린다 (페이드 금지).
  레일에서도 **메뉴 이동이 된다.**
- 좌상단 `⤡`(`arrows-diagonal-minimize-2`) = 나가기. **패널에 부착.** `position:fixed` 금지.
- **URL: `?detail=<kind>/<ns>/<name>`.** 새로고침해도 열려 있다. 링크 공유 가능.
  **뒤로가기 = 닫기** (history push).
- 상단에 **1층 검색 칩이 읽기 전용 브레드크럼**으로 남는다 (맥락 유지).
- **`J` / `K`** — 닫지 않고 목록의 다음/이전 항목으로 이동. (480px 패널의 유일한 장점을 대체)
- 탭: 개요 · YAML · 관련 리소스 · 메트릭 · **이벤트** (로그는 독으로)
- **권한 없는 버튼은 렌더하지 않는다** (disabled 금지)
- 모션: VP-017 §5. 패널 슬라이드와 사이드바 축소가 **같은 320ms에 동시**.
- 포커스 트랩 + `Esc` 시 **원래 행으로 포커스 복귀**.

**회귀 가드**
- 상세 폭이 `100%`가 아닌 값을 가지면 FAIL (AI가 열렸을 때 제외)
- 드래그 핸들이 존재하면 FAIL
- `⤡`가 `position: fixed`면 FAIL
- `?detail=`이 URL에 없으면 FAIL / 새로고침 시 안 열리면 FAIL
- 로그 탭이 상세 패널에 있으면 FAIL
- disabled 버튼이 있으면 FAIL
- 사이드바가 `display:none`이 되면 FAIL (레일이어야 함)

**확인 체크리스트**
```
1. 표의 행 클릭 → 상세가 목록을 완전히 덮는가 (목록이 안 보이는가)
2. 사이드바가 아이콘 레일(56px)로 줄었는가 / 레일에서 메뉴 이동이 되는가
3. 좌상단 ⤡ 클릭 → 닫히고 사이드바가 200px로 돌아오는가
4. Esc → 닫히는가 / 포커스가 원래 행으로 돌아오는가
5. 브라우저 새로고침 → 상세가 그대로 열려 있는가 (?detail=)
6. 브라우저 뒤로가기 → 닫히는가
7. J / K → 상세를 닫지 않고 다음/이전 리소스로 넘어가는가
8. 상세 상단에 검색 칩이 브레드크럼으로 남아 있는가
```

### S7 · AI 패널 기하학 (1단계 애니메이션)

**백엔드 (BQ-052, BQ-053, BQ-066)**
```
POST /ai/chat { context: { screen, filters, selection, time }, message }
→ { answer, evidence: [{ type, id, label, link }] }   ← 근거 필수

GET /ai/suggestions?context=...   → 맥락 기반 제안 질문
GET /ai/resources/{kind}/...      → 토큰 최적화 데이터 (Radar 패턴)
```
- **근거 없이 답하지 않는다.** `evidence`가 비면 "그 데이터가 없습니다".

**프론트**
- 우하단 ✦ 플로팅 버튼 (56px, 최상위 레이어). **절대 자리를 옮기지 않는다.**
- 클릭 → **오른쪽에서 420px 슬라이드 인** (300ms, `--ease-spring`)
- **상세가 열려 있어도 1단계다.** 상세는 이미 전체화면이므로 확장 단계가 없다.
  AI가 들어오면 상세가 flex로 좁아진다 (별도 애니메이션 없음 — 한 번만 움직인다).
- AI 내부 콘텐츠는 **고정 420px** (`width` 트랜지션 중 리플로우 떨림 방지)
- AI 폭 드래그 리사이즈 360~640px
- 맥락 칩 표시 (현재 화면 · 필터 · 선택 항목)
- 좁은 화면(<896px)에서 상세 자동 닫힘 + 토스트

**회귀 가드**
- AI가 왼쪽에서 열리면 FAIL
- 상세가 열린 상태에서 AI를 열 때 **2단계 애니메이션이면 FAIL** (1단계여야 함)
- `evidence` 없이 답변을 렌더하면 FAIL
- ✦ 버튼 위치가 밀리면 FAIL
- AI 내부 콘텐츠가 가변 폭이면 FAIL

**확인 체크리스트**
```
1. ✦ 클릭 → 오른쪽에서 열리는가 (상세 없이도)
2. 상세가 열린 상태에서 ✦ → 상세가 왼쪽으로 좁아지며 AI가 붙는가 (한 번만 움직이는가)
3. ⤡ 버튼(왼쪽)과 AI(오른쪽)가 겹치지 않는가
4. AI 여는 동안 텍스트가 떨리지 않는가
5. 맥락 칩이 지금 보는 것을 정확히 반영하는가
6. 답변에 근거 링크가 붙는가
```

### S9 · 관계 뷰 — **뷰가 필터에서 파생된다** ★ 우녕 확정 2026-07-14

**백엔드 (BQ-075)**
```
GET /topology?view=relations&<filters>
→ { nodes: [{id, kind, name, status}], edges: [{from, to, type}] }
```

**프론트**
- `[물리 뷰] [관계 뷰]` 토글은 있지만, **기본값을 사람이 고르지 않는다.**
  필터가 뷰를 정한다 (VP-015 §4.4 표):
  ```
  클러스터/네임스페이스만          → 물리 뷰
  + 앱 칩                          → 관계 뷰
  + Pod 외 타입 칩 2종 이상        → 관계 뷰
  Issues 인시던트 선택             → 관계 뷰 (영향 범위)
  앱 칩 + Pod만                    → 물리 뷰
  ```
- **전환 시 파드는 FLIP 모프로 날아간다** (`data-morph-id="pod:<id>"`). `useCameraMorph` 재사용.
  화면이 갈리지 않는다.
- **조용히 안 바꾼다**: 1회성 힌트 + `[물리 뷰로 →]` 되돌리기 버튼 (6초 후 사라짐)
- **사람이 토글하면 핀 고정.** 그 뒤로 자동 전환 없음. **필터를 지우면 핀이 풀린다.**
- **URL 규칙**: 자동으로 정해진 뷰는 `view=` 파라미터를 **쓰지 않는다.**
  사람이 고르면 `view=physical` / `view=relations`가 URL에 박힌다. **명시가 자동을 이긴다.**
  → 링크를 공유하면 상대도 **정확히 같은 화면**을 본다.
- 오브젝트 타입 칩 (`[Pod ✓] [Service ✓] [Deployment] …`)

**회귀 가드**
- `view=`가 URL에 있는데 자동 전환이 덮어쓰면 FAIL (사용자 의도 우선 위반)
- 자동 전환인데 `view=`가 URL에 박히면 FAIL (핀이 걸려버린다)
- 전환 시 힌트가 안 뜨면 FAIL (조용한 전환 금지)
- 전환 시 파드가 모프 없이 사라졌다 나타나면 FAIL
- 사람이 토글한 뒤에도 자동 전환이 일어나면 FAIL

**확인 체크리스트**
```
1. [클러스터: prod-eks]만 → 물리 뷰인가
2. [앱: checkout-api] 칩 추가 → 관계 뷰로 바뀌는가
3. 바뀔 때 파드가 서버 위에서 관계 그래프 자리로 날아가는가 (안 사라지고)
4. "앱을 골라서 관계 뷰로 바꿨습니다 [물리 뷰로 →]" 힌트가 뜨는가
5. [물리 뷰로 →] 클릭 → 물리 뷰로 돌아가고, 그 뒤론 자동 전환이 안 되는가 (핀)
6. URL을 복사해서 새 탭에 붙여넣기 → 같은 뷰가 나오는가
7. 필터를 전부 지우면 → 핀이 풀리고 다시 자동으로 돌아가는가
```

### S13 · 변경 적용 진행 ★ (클라이맥스)

**백엔드 (BQ-076~079)**
```
POST /changes                     → change_id (모드는 정책이 결정)
SSE  /changes/{id}/progress       → 단계 이벤트 (실제 이벤트만, 추정 금지)
POST /changes/{id}/revert
GET  /changes/active
```

**프론트 — 진행 표현 세 가지. 프로그레스바는 만들지 않는다 (VP-017 §7)**

1. **낙관적 고스트 파드 ★** — 제출 즉시 물리 뷰에 **점선 유령 파드**가 뜬다 (숨쉬듯 opacity 왕복).
   `applied` 이벤트 수신 → 점선이 실선이 되고 채움색이 페이드 인. 실패 → 빨갛게 흔들리고 사라진다.
   **가장 중요한 화면이다.** "무엇이 생길 예정인가"를 정확히 말한다.
2. **단계 레일** — 하단 독 탭 안. 수평 6칸 체크포인트. 완료 칸 사이는 **실선 + 실제 소요시간**,
   진행 칸은 **흐르는 점선**, 미래 칸은 **점**(안 채운다).
3. **트레이스 워터폴** — 레일 클릭 시 펼침. **막대 폭 = 실제 시간.** 끝난 뒤에만 그린다.
   "어디가 느린지"를 사용자가 배운다.

- 6단계 (검증 → Git 커밋 → **Git 수신(웹훅)** → 클러스터 반영 → 롤아웃 → 안정화)
- **드리프트 되돌리기는 2·3단계(Git 커밋·수신)를 건너뛴다** (Git이 안 바뀌니까 — 그리면 거짓말)
- 실패 시: 어느 단계인지 + [되돌리기] + [✦ AI에게 묻기]
- 독 닫으면 **AI 버튼 왼쪽에 진행 배지** (`⟳ 3/6`)

**회귀 가드**
- 백엔드가 안 보고한 단계를 그리면 FAIL
- **시간 기반으로 채워지는 막대(프로그레스바)가 존재하면 FAIL**
- 미래 단계의 연결선이 채워져 있으면 FAIL
- 진행 배지가 AI 버튼을 밀면 FAIL
- 고스트 파드가 `applied` 이벤트 없이 실체가 되면 FAIL
- 소요시간 계약이 없는데 워터폴을 그리면 FAIL

**확인 체크리스트**
```
1. replicas를 3→5로 수정 → 물리 뷰에 점선 유령 파드 2개가 즉시 뜨는가
2. 독에 진행 탭이 자동으로 열리는가
3. 6단계 레일이 실제 이벤트로 하나씩 넘어가는가 (미래 칸은 안 채워지는가)
4. "Git 수신" 단계가 실제로 보이는가 (Git이 진실임의 증명)
5. 반영되면 유령 파드가 실선이 되며 색이 차는가
6. 레일 클릭 → 트레이스 워터폴이 펼쳐지고 롤아웃이 가장 긴가
7. 커밋에서 반영까지 5초 이내인가
8. 실패 주입 → 유령 파드가 빨갛게 흔들리고 사라지는가 / 어느 단계에서 멈추는지 보이는가
```

| 4 | **VP-015/016 착륙** | 기획 정본이 dev에 있어야 세션이 읽는다 |
| 5 | **Radar 서브트리 + NOTICE** | 라이선스 준수. 이식 전에 해야 한다 |

**1~3이 안 되면 S1도 시작할 수 없다. 이것부터.**

## 7. 금지 사항

- **계약을 다 만들고 프론트를 시작하는 것** (수직 슬라이스 위반)
- **배포 없이 슬라이스를 완료로 표시하는 것**
- **소비되지 않은 계약을 3개 이상 쌓는 것**
- **한 커밋이 30분을 넘는 것**
- **`deploy-status.md`를 갱신하지 않는 것** (팀원이 볼 수 없다)
- **회귀 가드 없이 슬라이스를 닫는 것**
- **S0(모션 기반)을 건너뛰고 S1부터 시작하는 것** — 나중에 얹으면 못 고친다
- **애니메이션을 컴포넌트 안에 인라인하는 것** — `web/src/motion/`에서만
