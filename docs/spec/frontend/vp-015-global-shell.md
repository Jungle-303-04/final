# VP-015 — 전역 화면 골격

## 0. 핵심 통찰 — **필터가 곧 줌이다**

이 한 문장이 나머지 모순을 전부 푼다.

```
필터 없음              →  클러스터 격자          (전체를 본다)
클러스터 1개 선택       →  그 클러스터의 서버들    (내려간다)
+ 네임스페이스 / 앱     →  해당 파드만 선명       (좁힌다)
+ 리소스 클릭           →  상세 패널             (들어간다)
```

**그래프는 하나의 컴포넌트다.** 화면이 다른 게 아니라 **필터가 다르다.**
"단일 클러스터일 때만 그래프" 같은 예외 규칙이 필요 없어진다.
필터를 지우면 자동으로 한 단계 올라간다. **사용자는 조작을 하나만 배우면 된다.**

## 1. 메뉴

```
┌──────────────┐
│  Opsia       │
├──────────────┤
│ Clusters     │  ← 첫 진입. 데모의 시작점.
│ Home         │  ← 위젯 대시보드 (VP-011). 골격 예외.
│ Resources    │
│ Applications │
│ Issues       │
│ GitOps       │
│ Checks       │
│ AI 채팅      │  ← 대화 이력·검색
│ Settings     │
└──────────────┘
                                              ✦  ← 우하단 상시 AI 버튼
```

**AI가 두 곳에 있는 것은 모순이 아니다:**
- **메뉴 `AI 채팅`** = 대화 **이력**을 보고 검색하고 이어간다
- **우하단 ✦** = 지금 보는 것을 물고 **즉석 질문**
- **같은 저장소를 공유한다.** 모든 대화에 **맥락 스냅샷**(화면·필터·선택 항목·시각)이
  함께 저장되고, 이력에서 클릭하면 **그 맥락으로 복원**된다.
  → "이 대화가 뭐였더라?"가 안 생긴다.

## 2. 공용 3층 골격

**적용: Clusters · Resources · Applications · Issues**

```
┌──────────────────────────────────────────────────────────────┐
│ 1층  🔍 검색…   [클러스터: prod-eks ✕] [앱: checkout ✕]      │  검색 — 항상 같은 자리
│      18 / 47 표시                          [비우기]  [⌃]     │
├──────────────────────────────────────────────────────────────┤
│ 2층                                                           │
│      ┌─ 서버 1 ─────┐  ┌─ 서버 2 ─────┐  ┌─ 서버 3 ─────┐    │  공간 뷰
│      │ ▣▣▣▣▣ +12   │  │ ▣▣▣          │  │ ▣▣           │    │  (고정 높이 320px)
│      │ CPU ████ 68% │  │ CPU ██   31% │  │ CPU ███ 94% ⚠│    │
│      └──────────────┘  └──────────────┘  └──────────────┘    │
├──────────────────────────────────────────────────────────────┤
│ 3층  NAME          STATUS      CPU     추세                   │  표
│      checkout-api  ● 정상      42%     ▁▁▂▅█▅▂               │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 절대 규칙

| 규칙 | 내용 |
|---|---|
| **검색은 항상 최상단 같은 자리** | 화면이 바뀌어도 눈이 움직이지 않는다 |
| **2층 높이는 320px 고정** | 화면 전환 시 표가 위아래로 튀지 않는다 |
| **필터 → 2층과 3층이 같은 결과** | 어긋나면 버그다 |
| **2층은 `⌃`로 접힌다** | 접힌 상태는 URL(`graph=0`)에 남고 화면 간 유지된다 |

### 2.2 2층 = **공간 뷰** (화면마다 그리는 게 다르지만 엔진은 하나)

| 화면 | 그리는 것 | 필터가 하는 일 |
|---|---|---|
| **Clusters** | 클러스터 격자 | provider·상태로 좁힘 |
| **Resources** | **물리 뷰**(서버+파드) / 관계 뷰 토글 | **§0의 줌** |
| **Applications** | 관계 뷰 (앱 필터 적용) | 앱 하나 고르면 그 앱의 리소스 관계 |
| **Issues** | 관계 뷰 (장애 리소스 강조) | 인시던트 하나 고르면 영향 범위 |

**같은 그래프 엔진**(@xyflow/react + ELK)에 **필터만 다르게 먹인다.**
Applications의 관계 뷰와 Issues의 영향 범위 뷰는 **같은 컴포넌트**다.
중복이 아니다 — `applications=checkout` 필터냐 `issue=17` 필터냐의 차이다.

### 2.3 클러스터 필터가 0개일 때 (모순 해소)

**물리 뷰를 못 그리는 게 아니라, 한 단계 위를 그린다.**

```
필터: (없음)
┌─ prod-eks ────┐  ┌─ staging-gke ─┐  ┌─ on-prem ─────┐
│ 서버 3 · 파드47│  │ 서버 2 · 파드18│  │ 서버 5 · 끊김  │   ← 클러스터 격자
│ ⚠ 인시던트 1   │  │ 정상           │  │               │
└───────────────┘  └───────────────┘  └───────────────┘

카드 클릭 = 필터에 [클러스터: prod-eks] 칩 추가
        ↓
필터: [클러스터: prod-eks ✕]
┌─ 서버 1 ─────┐  ┌─ 서버 2 ─────┐  ┌─ 서버 3 ─────┐        ← 물리 뷰로 내려감
```

**클러스터를 2개 이상 고르면?** 나란히 축소해서 보여준다 (각 클러스터가 하나의 그룹).
**5개 이상이면** 격자로 되돌아간다 (그려도 안 보인다).

**필터를 지우면 자동으로 올라간다.** 뒤로가기가 곧 줌아웃이다.

### 2.4 필터가 파드를 좁혔을 때 — 서버는 어떻게 되나 (모순 해소)

**서버는 물리적 사실이다. 항상 다 보인다. 파드만 필터된다.**

```
필터: [클러스터: prod-eks] [앱: checkout-api]

┌─ 서버 1 ─────┐  ┌─ 서버 2 ─────┐  ┌─ 서버 3 ─────┐
│ ▣▣▣ ░░░░░░  │  │ ▣ ░░░░       │  │ ░░░░░░       │
│  ↑    ↑      │  │              │  │              │
│ 선명  흐림   │  │              │  │  ← 이 서버엔  │
│              │  │              │  │    없음       │
│ 3 / 18       │  │ 1 / 12       │  │ 0 / 17       │
└──────────────┘  └──────────────┘  └──────────────┘
```

- **필터에 맞는 파드**: 선명 (100%)
- **나머지 파드**: 흐림 (20% opacity, 클릭 불가)
- **서버 카드 하단**: `3 / 18` — 필터 결과 / 전체

**왜 안 지우고 흐리게 두나:** "서버 3대인데 파드 0개"는 거짓말이다.
흐린 파드가 있어야 **"이 서버는 다른 앱으로 꽉 차 있구나"**를 안다. 맥락이 산다.

### 2.5 GitOps · Checks — 2층이 없다 (모순 아님)

**그릴 공간 데이터가 없다. 억지로 그리지 않는다.** (BE-Gap 규율의 확장)

```
┌────────────────────────────────┐
│ 🔍 검색…  [칩]      [비우기]   │  ← 1층 동일
├────────────────────────────────┤
│  표 / 카드 목록                 │  ← 3층 동일
└────────────────────────────────┘
```

GitOps는 **PR 목록**, Checks는 **위험 목록**이다. 시간·공간에 배치되는 물건이 아니다.
**1층(검색)과 3층(표)의 위치는 다른 화면과 완전히 동일하다.** 골격은 지켜진다.

### 2.6 Home — 골격 예외 (명시)

Home은 **위젯 조합 대시보드**(VP-011)다. 위젯이 그 자리를 쓴다.
Home에 그래프 위젯을 넣고 싶으면 **위젯으로** 넣는다 (`entity=resources, view=topology`).
**골격을 강제하지 않는다.**

## 3. 태그형 검색 (1층)

### 3.1 동작

빈 검색창을 클릭하면 **구조적 축만** 목록으로 뜬다 (유한하니까):
```
🔍 |
  클러스터        prod-eks · staging-gke · on-prem
  네임스페이스     default · prod · staging · kube-system
  애플리케이션     checkout-api · payment-api · auth-api
  ─────────────────────────────────────────────
  라벨·리소스는 입력하면 검색됩니다
```

**타이핑하면 서버가 매칭되는 것만** 반환한다 (라벨·리소스는 비유한하므로 검색만):
```
🔍 check|
  애플리케이션     checkout-api · checkout-worker
  라벨            app=checkout · team=checkout
  리소스          checkout-api-7d9f (Pod) · checkout-api (Service)
```

**선택 → 타입이 붙은 칩:**
```
[클러스터: prod-eks ✕]  [앱: checkout-api ✕]  [team=checkout ✕]
```

### 3.2 결합 규칙 (VP-010 §2.3 그대로)

| 조합 | 결합 |
|---|---|
| 같은 타입 칩 여러 개 | **OR** (prod-eks OR staging-gke) |
| 다른 타입 칩 | **AND** |
| **라벨 ↔ 라벨** | **AND** ← 블로그 태그와 다른 유일한 점 |
| 칩 0개 | 전체 (= 줌아웃) |

**라벨이 AND인 이유를 popover에 항상 고지한다.** ("선택한 라벨은 모두 만족해야 합니다")
이것만 다르므로, 한 번 배우면 끝이다.

### 3.3 타입 목록은 서버가 준다

`GET /filter-facets` (BQ-073). **프론트가 하드코딩하지 않는다.**
백엔드에 없는 축은 검색창에 나타나지 않는다 (BE-Gap 규율).

## 4. 그래프 — 물리 뷰 (코치 피드백 정확히 반영)

> "서버면 서버라고 아이콘 읽는 거잖아."
> "서버 3대로 운영하고 있네요. 그 위에 파드들이 이렇게 실행하고 있네요.
>  이게 제일 직관적이지 않아요?" — 코치

### 4.1 용어 — 쿠버네티스 말을 쓰지 않는다

| 쿠버네티스 | 화면에 쓰는 말 |
|---|---|
| Node | **서버** |
| Cluster | **(클러스터 이름 그대로)** + provider 로고 |
| Pod | **파드** (이건 유지. 대체어가 더 헷갈린다) |
| Namespace | 화면에 안 그린다. **필터일 뿐이다** (§4.5) |

### 4.2 파드 시각 인코딩 — **채널 하나에 의미 하나** (모순 완전 제거)

**코치가 잡아낸 모순:** "크기하고 색깔 두 개가 있는데 지금 제가 봤을 때는 일치해 보이거든요."

**우리가 만든 두 번째 모순:** 색이 사용률이면, **CrashLoop 파드(사용률 0%)가 회색 = 안전해 보인다.**
이건 더 위험하다.

**해결 — 채널을 셋으로 분리하고, 각 채널이 정확히 한 가지만 말한다:**

| 채널 | 뜻 | 값 |
|---|---|---|
| **크기** | **아무것도 안 뜻한다.** 전부 동일. | 고정 |
| **채움 색** | **사용률 (requests 대비)** | 0~60% 회색 / 60~80% 앰버 / 80%+ 빨강 |
| **배지 (우상단 작은 아이콘)** | **비정상 상태.** 정상이면 **없다.** | ✕ CrashLoop / ⏸ Pending / ⟳ 재시작 반복 |

```
정상 (낮은 부하)   ▢        회색 채움, 배지 없음
정상 (높은 부하)   ▣        빨강 채움, 배지 없음      ← "일 많이 하는 중"
CrashLoop         ▢✕       회색 채움(사용률 0), ✕ 배지 ← "죽었다"
과부하 + 재시작    ▣⟳       빨강 채움, ⟳ 배지        ← 둘 다
```

**왜 배지인가:** 색 채널 하나에 "부하"와 "죽음" 두 의미를 실으면 반드시 모순이 난다.
**배지는 있거나 없다.** 있으면 무조건 눈에 띈다. 색과 독립이다.

**크기는 절대 위험을 뜻하지 않는다.** 코치가 지적한 모순이 여기서 완전히 사라진다.
(요청량·제한량은 hover 툴팁과 3층 표에서 본다. 그래프는 개수와 상태만 말한다.)

### 4.3 파드가 많을 때 — 축약

> "100개씩 쌓이고 옆에는 1개밖에 없으면 어떻게 보여줘야 되지?"
> "다 보여주는 게 의미가 없어. 그냥 어느 정도 많다 이런 거지." — 코치

**서버당 12개까지 그린다. 나머지는 `+N개`.**

**축약 순서 — 값이 아니라 문제 우선:**
```
1. 배지가 있는 파드 (CrashLoop / Pending / 재시작 반복)   ← 절대 안 잘린다
2. 사용률 80%+ 파드
3. 나머지                                                 ← 여기서부터 자른다
```
**조용한 파드를 먼저 자른다.** 문제 있는 것은 100개 중 1개여도 보인다.

`+12개` 클릭 → **필터가 걸린 3층 표로 스크롤** (`?node=server-1`).
화면을 바꾸지 않는다. 같은 화면 안에서 표가 좁혀진다.

### 4.4 관계 뷰 — **뷰도 필터에서 파생된다** (우녕 확정 2026-07-14)

```
[물리 뷰]  [관계 뷰]        ← 토글은 있다. 하지만 기본값을 사람이 고르지 않는다.
```

**§0의 확장.** 필터가 줌 레벨을 정하듯, **필터가 뷰도 정한다.**
"지금 뭘 보고 있느냐"가 이미 "어떻게 그려야 하느냐"를 결정하고 있기 때문이다.

| 필터 상태 | 자동 뷰 | 왜 |
|---|---|---|
| 필터 0개 | **클러스터 격자** | §2.3 |
| 클러스터만 / +네임스페이스 | **물리 뷰** | "서버 몇 대에 파드가 어떻게" — 물리적 질문 |
| **+ 앱 칩** | **관계 뷰** | 앱은 논리 단위다. Ingress→Service→Deployment→Pod가 궁금한 거지, 어느 서버에 떨어졌는지가 아니다 |
| **+ 리소스 타입 칩이 Pod 외 2종 이상** (Service·Ingress·PVC…) | **관계 뷰** | 파드가 아닌 것을 물었으면 물리 뷰에 그릴 자리가 없다 |
| **Issues에서 인시던트 선택** | **관계 뷰** (영향 범위 강조) | "이게 뭘 망가뜨렸나"는 관계 질문 |
| 앱 칩 + **파드만** 타입 칩 | **물리 뷰** | 명시적으로 파드를 물었다 |

**전환은 애니메이션으로 이어진다.** 파드 노드는 두 뷰에 **둘 다 존재**하므로,
`data-morph-id="pod:<id>"`로 **FLIP 모프**한다 (VP-017 §4.2 같은 함수).
파드가 서버 위에서 → 관계 그래프의 제자리로 **날아간다.** 화면이 갈리지 않는다.

### 4.4.1 자동 전환의 유일한 위험 — 그리고 그 해결

**위험:** 내가 안 바꿨는데 화면이 바뀌면 사용자는 통제감을 잃는다.

**해결 두 가지. 둘 다 필수다.**

1. **조용히 바꾸지 않는다.** 전환 시 토글 옆에 **1회성 힌트**가 뜬다:
   ```
   [물리 뷰] [관계 뷰●]   앱을 골라서 관계 뷰로 바꿨습니다.  [물리 뷰로 →]
   ```
   힌트는 6초 후 사라진다. **되돌리는 버튼이 힌트 안에 있다.** 한 번의 클릭으로 원복된다.

2. **한 번이라도 사람이 토글하면, 그 뒤로는 자동 전환하지 않는다.** (핀 고정)
   - URL에 `view=physical` / `view=relations`가 **명시되면 그게 이긴다.**
   - 자동으로 정해진 뷰는 URL에 쓰지 않는다 (`view` 파라미터 없음 = 자동).
   - 그래서 **링크를 공유하면 상대도 같은 화면**을 본다 (자동이든 수동이든 재현된다).
   - 핀을 풀려면 토글을 `auto`로 (토글에 세 번째 상태 없이, **필터를 지우면 자동으로 풀린다**).

**"사용자 의도가 자동 규칙을 항상 이긴다."** 이 한 줄이 모순을 막는다.

### 4.4.2 관계 뷰의 내용

같은 필터, 다른 표현.

```
  Ingress ──▶ Service ──▶ Deployment ──▶ Pod ×5
                                    └──▶ ConfigMap
                                    └──▶ Secret
                                    └──▶ PVC ──▶ PV
```

**오브젝트 타입 칩** (블로그 태그처럼 겹쳐 고름):
```
[Pod ✓] [Service ✓] [Deployment] [ConfigMap] [Secret] [PVC] [Ingress]
```
선택한 타입만 그린다. **1층 검색 칩과 AND 결합.**

Radar `topology/TopologyGraph.tsx` + `layout.ts`(ELK) 이식.
[D-028]의 "Live Traffic 흡수"가 여기다. **트래픽 수치는 계약이 있을 때만** 엣지에 표시.

### 4.5 네임스페이스 — 그리지 않는다 (혼란의 근원 제거)

> "네임스페이스는 로지컬하게 격리만을 준거야." — 코치

**서버 위에 네임스페이스 상자를 겹쳐 그리지 않는다.**
물리(서버)와 논리(네임스페이스)를 한 그림에 겹치면 반드시 헷갈린다.

**네임스페이스는 필터 칩이다. 그게 전부다.**
`[네임스페이스: prod]`를 고르면 그 파드만 선명해진다 (§2.4).

### 4.6 줌은 **카메라 이동**이다 — SLG 상태창 수준의 다이나믹 (우녕 확정 2026-07-14)

> "필터 줌 의도는 맞는데 더 다이나믹해야 해. 게임 UI라고 생각해.
>  SLG 게임에서 표현하는 다이나믹한 상태창 같아야 한다는 거지." — 우녕

**정적으로 리렌더하지 않는다.** 줌 레벨이 바뀌면 **카메라가 내려가는 것처럼** 보여야 한다.
정확한 수치는 **VP-017 모션 규격**에 있다. 여기서는 원칙만 박는다.

| 원칙 | 내용 |
|---|---|
| **예고(foreshadow)** | 클러스터 카드 안에 **서버가 작은 블록으로 이미 보인다.** 줌인하면 그 블록이 **커져서 서버 카드가 된다.** 사용자가 "저기로 들어간다"를 미리 안다 |
| **착지(land)** | 노드는 아래에서 위로 14px 올라오며 스케일 0.94 → 1.0. **개별 딜레이 70ms 스태거.** 한꺼번에 안 나타난다 |
| **개체감(pop)** | 파드는 scale 0.3 → 1.14 → 1.0 오버슈트. **32ms 스태거.** "톡톡 튀어나온다" |
| **반응(react)** | 파드 hover → 1.25배 확대(120ms). 서버 카드 hover → 2px 부상 + 테두리 강조 |
| **연속(continuity)** | CPU 막대는 **width transition 500ms 스프링**. 값이 순간이동하지 않는다 |
| **되감기(rewind)** | 줌아웃은 줌인의 정확한 역재생. 서버 카드가 축소되어 클러스터 카드 안의 블록으로 되돌아간다 |

**브레드크럼이 줌 레벨이다:**
```
전체 › prod-eks › checkout-api
 ↑      ↑          ↑
 필터0  클러스터칩  앱칩        ← 브레드크럼 = 필터 칩의 다른 표현. 클릭하면 그 단계로 되감긴다.
```

**금지:**
- 줌 전환 시 **화면 전체가 흰색으로 깜빡이는 것** (스켈레톤 플래시). 이전 프레임을 유지한 채 전이한다.
- **모든 노드가 동시에 페이드 인**하는 것. 스태거가 없으면 SLG가 아니라 스프레드시트다.
- 데이터 로딩이 늦다고 **애니메이션을 데이터 도착까지 미루는 것.** 레이아웃은 즉시 착지하고,
  값(사용률·CPU)만 나중에 채운다. **골격 먼저, 살은 나중에.**
- `prefers-reduced-motion: reduce`를 무시하는 것 → 이 경우 **모든 스태거·오버슈트를 끄고 opacity만** 쓴다. (필수)

## 5. 상세 패널 + AI 패널 — 기하학 (모순 완전 제거)

### 5.1 사이드바는 "접히는" 게 아니라 "레일이 된다" (모순 해소)

**"전체화면 = 사이드바 접기"라고 하면 메뉴 이동을 못 하게 된다.**

```
펼침 (기본)          레일 (전체화면일 때)
┌──────────────┐     ┌───┐
│ Clusters     │     │ ▣ │   ← 아이콘만. 클릭하면 이동 가능.
│ Home         │     │ ⌂ │      hover하면 툴팁으로 이름.
│ Resources    │  →  │ ▤ │
│ …            │     │ … │
└──────────────┘     └───┘
   200px              56px
```

**항상 이동할 수 있다.** "접힌다"는 표현을 쓰지 않는다. **레일로 축소된다.**

### 5.2 상세 패널은 **2상태**다 — 열리면 곧바로 전체화면 (우녕 확정 2026-07-14)

**폐기: "① 살짝 480px → ② 드래그 확장 → ③ 전체" 3단계.**
이 3단계는 (a) 사용자가 배워야 할 조작이 셋이고, (b) 좁은 화면에서 상태 조합이 폭발하고,
(c) 480px에서는 YAML·차트가 어차피 안 읽힌다. **셋 다 손해였다.**

| 상태 | 정의 |
|---|---|
| **닫힘** | 목록만 보인다 |
| **열림 = 전체화면** | 상세가 **콘텐츠 영역 전체를 덮는다.** 목록은 보이지 않는다. 사이드바는 **56px 레일** |

```
닫힘                              열림 (= 전체화면)
┌──────┬──────────────────┐      ┌───┬────────────────────────────┐
│ 메뉴  │ 1층 검색          │      │ ▣ │ ⤡  checkout-api-7d9f       │
│ 200px│ 2층 그래프         │  →   │ ⌂ │ [개요][YAML][관련][이벤트] │
│      │ 3층 표            │      │ ▤ │                            │
│      │    ↑ 행/파드 클릭  │      │ … │   상세 전체 폭             │
└──────┴──────────────────┘      └───┴────────────────────────────┘
                                   56px 레일 — 메뉴 이동은 계속 된다
```

**전이:**
- **열기**: 표의 행 클릭 / 2층의 파드 클릭 → 우측에서 슬라이드 인하며 **목록을 덮는다** (`--motion-layout` 320ms, `--ease-spring`)
- **닫기**: 좌상단 `⤡` 또는 `Esc` → 오른쪽으로 슬라이드 아웃, 사이드바 200px 복귀
- **URL**: `?detail=<kind>/<ns>/<name>` — 열림 상태가 URL에 남는다. **새로고침해도 열려 있다. 링크 공유 가능.**
- **뒤로가기 = 닫기.** 브라우저 히스토리 push. (모바일 사파리에서도 자연스럽다)

**드래그 리사이즈 없음. 중간 폭 없음.** 조작이 하나로 줄었다.

**"목록을 덮으면 맥락을 잃지 않나?"** — 잃지 않는다. 세 가지가 맥락을 유지한다:
1. **1층 검색 칩이 상세 상단에도 그대로 남는다** (읽기 전용 브레드크럼)
2. **`⤡`가 항상 좌상단 같은 자리** — 나가는 문이 하나다
3. **상세 안에서 `J` / `K`** — 닫지 않고 **목록의 다음/이전 항목으로 이동**한다
   (상세를 열어둔 채 훑는다. 480px 패널의 유일한 장점이던 "목록과 동시에 보기"를 대체한다)

### 5.3 `⤡` 버튼은 상세 패널의 좌상단에 부착

```
┌⤡─────────────────────────────────────┬──────────┐
│  checkout-api-7d9f                    │ ✦ AI     │
```
**뷰포트 고정이 아니다.** 패널의 좌상단 모서리.
→ AI가 오른쪽에서 열려 패널이 좁아져도 **버튼은 패널을 따라간다. 절대 안 겹친다.**
아이콘은 `arrows-diagonal-minimize-2` (축소). "전체화면 만들기"가 아니라 **"나가기"**다.

### 5.4 AI 패널 — 전체화면 상세를 오른쪽에서 파고든다 (우녕 확정)

상세가 이미 전체화면이므로 **STEP 1(확장)이 사라졌다. 애니메이션이 1단계로 줄었다.**

```
AI 열기 (300ms, --ease-spring)
  AI가 오른쪽 가장자리에서 420px 슬라이드 인
  상세의 오른쪽 끝이 그만큼 왼쪽으로 밀린다 (flex 축소, 언마운트 없음)
```

**최종 배치:**
```
┌───┬────────────────────────────────┬────────────┐
│ ▣ │ ⤡ checkout-api-7d9f            │ ✦ Opsia AI │
│ ⌂ │  [개요][YAML][관련][이벤트]     │            │
│ ▤ │                                 │ 맥락:      │
│ … │   상세 (전체 − 420)             │ [prod-eks] │
│   │                                 │ [checkout] │
│   │                                 │ 질문…       │
└───┴────────────────────────────────┴────────────┘
 56px                                  420px (드래그 리사이즈 가능, 360~640)
 ⤡는 왼쪽. AI는 오른쪽. 물리적으로 겹칠 수 없다.
```

**모순이 없는 이유:** 상세는 "전체화면"이라는 **한 가지 상태**뿐이고, AI는 그 영역을 **분할**한다.
상태가 늘어나지 않는다. `⤡`는 왼쪽, AI는 오른쪽 — 기하학이 충돌을 막는다.

**AI를 닫으면** 상세가 300ms에 걸쳐 전체 폭 복귀. 사이드바는 레일 유지.
**상세 없이 AI만 열면** 오른쪽에서 420px 슬라이드 인. 목록이 좁아진다. **사이드바는 200px 그대로**
(상세가 없으니 전체화면이 아니다).

### 5.5 최소 폭 보장

```
상세 최소 폭 = 480px
AI  최소 폭 = 360px
뷰포트 < 56 + 480 + 360 = 896px 이면
  → AI를 열 때 상세가 자동으로 닫힌다 (AI 우선)
  → 토스트: "상세를 닫고 AI를 열었습니다"
```
**조용히 깨지지 않는다. 정직하게 알린다.**

### 5.6 하단 독 — 우측 패널과의 경계 (중복 모순 해소)

**규칙: 과거의 목록은 우측. 지금 흐르는 스트림은 하단.**

| | 우측 상세 패널 | 하단 독 |
|---|---|---|
| **성격** | 정적 사실 | 흐르는 것 |
| **탭** | 개요 · YAML · 관련 리소스 · 메트릭 차트 · **이벤트(최근 N개)** | **로그 스트림** · **터미널** · 워크로드 로그 |
| **동시 열림** | ✓ 둘 다 열려 있어도 된다 | ✓ |

**로그는 우측 패널에 절대 넣지 않는다.** 스트림이기 때문이다.
**이벤트는 우측에 넣는다.** 이산적인 목록이기 때문이다.
(실시간 이벤트 스트림이 필요하면 그때 독 탭을 만든다.)

```
┌───┬──────────────────────┬──────────┐
│ ▣ │  목록                 │ 상세 패널 │
├───┴──────────────────────┴──────────┤
│ [로그: checkout] [터미널] [로그: pay] │  ← 탭으로 여러 개
│ 10:23 ERROR connection refused        │
└───────────────────────────────────────┘
```
파드 선택 후 `l` → 하단 독에 로그. **화면 전환 없이.**
독 안에서도 **✦ AI 질문** 가능 — 지금 보는 로그를 물고 묻는다.

**제외:** Radar의 `LocalTerminalTab`(로컬 셸). 우리는 웹이라 불가능하다. 만들지 않는다.
**exec 터미널**은 에이전트 WS 터널이 필요하다 (BQ-067, P1). **계약이 없으면 탭 자체를 렌더하지 않는다.**

### 5.7 모바일 (명시)

**모바일에서는 한 번에 하나만 전체화면 시트로 연다.**
- 상세 → 전체화면 시트
- AI → 전체화면 시트 (상세 위에 겹침)
- 독 → 전체화면 시트
- 사이드바 → 햄버거 → 오버레이

**분할 레이아웃을 모바일에서 시도하지 않는다.**

### 7.1 두 모드

| 모드 | 동작 | 기본값 |
|---|---|---|
| **즉시 적용** | 수정 → **Git 자동 커밋** → 웹훅 → 클러스터 반영 | dev/staging |

**둘의 차이는 "승인 게이트가 있느냐" 하나뿐이다. 나머지 경로는 완전히 같다.**

**어느 모드든 지키는 불변식:**
1. **Opsia는 클러스터에 직접 쓰지 않는다.** 언제나 **Git → 웹훅 → 동기화**다.
   (`kubectl apply`를 하지 않는다. 단일 writer 불변식은 살아 있다.)
2. **모든 변경이 Git에 남는다.** 누가·언제·무엇을 → 롤백 가능.
3. **감사 원장에 기록된다.** (이벤트 소싱)

**"즉시"의 뜻은 "Git을 건너뛴다"가 아니라 "사람의 승인을 건너뛴다"다.**
이 구분이 모순을 없앤다.

### 7.2 모든 쓰기에 일관 적용

- Resources 상세의 YAML 편집 · 스케일 · 재시작 · 삭제 · 롤백
- Applications의 "Git대로 되돌리기" / "현재 상태를 Git에 반영"
- Checks의 "수정하기"
- Issues의 "복구 적용"

**한 곳만 PR이고 다른 곳은 즉시면 모순이다. 전부 같은 정책을 탄다.**
정책은 Settings > 정책에서 환경별로 정한다.

## 7-A. 변경 적용 진행 표시기 ★ (제품의 핵심 장면)

> "프로그레스 바를 보여주고 그 뒤에 반영된 걸 보면 디프로 이전 버전으로
>  바뀌었다는 거를 시각적으로 보여주고" — 코치

### 7-A.1 가짜 프로그레스바를 만들지 않는다

**우리는 이벤트 소싱이다. 진짜 단계를 진짜 이벤트로 보여줄 수 있다.**
채워지는 척하는 막대는 만들지 않는다. **각 단계가 실제 이벤트로 확정될 때만 넘어간다.**

이게 오히려 훨씬 강력하다 — 사용자가 **무슨 일이 일어나는지 배우게 된다.**
(코치의 "쿠버네티스가 어렵다"에 대한 우리의 답이 여기 있다.)

### 7-A.2 단계 (즉시 적용 모드)

수정 버튼을 누르면 **하단 독 위에 진행 시트가 슬라이드 인**한다.

```
┌ 변경 적용 중 — checkout-api · replicas 3 → 5 ─────────────┐
│                                                            │
│  ✓  검증          정책 스코프 통과 · dry-run OK      0.4s  │
│  ✓  Git 커밋      a3f9c2 "scale checkout-api to 5"  1.2s  │
│  ⟳  Git 수신      웹훅 대기 중…                            │  ← 지금 여기
│  ○  클러스터 반영                                          │
│  ○  롤아웃                                                 │
│  ○  안정화 확인                                            │
│                                                            │
│                                    [Git에서 보기 ↗] [닫기] │
└────────────────────────────────────────────────────────────┘
```

| 단계 | 무슨 일 | 완료 판정 |
|---|---|---|
| **1. 검증** | 정책 스코프 검사 + SSA dry-run | 서버가 `validated` 이벤트 발행 |
| **2. Git 커밋** | Opsia가 Git에 커밋 (또는 PR 생성) | commit SHA 확정 |
| **3. Git 수신** | **웹훅이 Opsia로 돌아온다** | `git.push` 이벤트 수신 |
| **4. 클러스터 반영** | 에이전트가 desired를 적용 | `applied` 이벤트 |
| **5. 롤아웃** | 파드 교체 진행 | `2/5 → 5/5` 실시간 |
| **6. 안정화 확인** | 헬스 복구 대기 | readiness 통과 |

**3단계(웹훅 수신)가 핵심이다.** 여기서 "Git이 진실이다"가 눈으로 증명된다.
UI가 클러스터를 직접 건드리지 않았다는 것을, 사용자가 **본다.**

### 7-A.3 승인 필요 모드에서는 단계가 하나 늘어난다

```
✓  검증
✓  PR 생성        #42
⏸  승인 대기      김민수에게 요청됨          [PR 보기 ↗]   ← 여기서 멈춘다
○  병합
○  Git 수신
○  클러스터 반영
○  롤아웃
○  안정화 확인
```

**멈춘 상태로 시트를 닫아도 된다.** 진행은 백그라운드로 계속되고,
GitOps 화면과 알림으로 추적된다. **시트는 관측 창이지 작업 창이 아니다.**

### 7-A.4 롤아웃 단계는 물리 뷰와 연동된다 ★

**5단계(롤아웃)가 진행되는 동안, 2층 물리 뷰에서 파드가 실제로 교체되는 게 보인다.**

```
서버 1                     서버 1
┌──────────────┐          ┌──────────────┐
│ ▣ ▣ ▣        │   →      │ ▣ ▣ ▣ ▢ ▢    │   ← 새 파드가 페이드 인
└──────────────┘          └──────────────┘      옛 파드가 페이드 아웃
```
- 새 파드: 페이드 인 (`--motion-layout`)
- 사라지는 파드: 페이드 아웃
- **가짜 애니메이션이 아니라 실제 이벤트 스트림**에 반응한다

**이게 데모의 클라이맥스다.** "고쳤다 → 실제로 파드가 늘어난다"를 한 화면에서 본다.

### 7-A.5 실패하면

```
✓  검증
✓  Git 커밋      a3f9c2
✓  Git 수신
✗  클러스터 반영   ImagePullBackOff: v2.5 태그가 레지스트리에 없습니다

   [ 원인 보기 ]  [ 이 커밋 되돌리기 ]  [ ✦ AI에게 묻기 ]
```

- **어느 단계에서 실패했는지 정확히 보인다.**
- **[이 커밋 되돌리기]** = revert 커밋을 만들어 같은 파이프라인을 다시 탄다.
  (직접 kubectl로 되돌리지 않는다. 불변식 유지.)
- **[✦ AI에게 묻기]** = 실패 맥락(단계·에러·로그·이벤트)을 물고 AI 패널이 열린다.

### 7-A.6 진행 시트의 위치 — **하단 독의 탭이다** (겹침 모순 해소)

**별도 시트를 만들지 않는다. 하단 독에 탭으로 들어간다.**

```
┌──────────────────────────────────────────────────────┐
│ [⟳ 적용: checkout-api] [로그: checkout] [터미널]      │  ← 독 탭
│                                                       │
│  ✓ 검증   ✓ Git 커밋   ⟳ Git 수신   ○ 반영 …         │
└───────────────────────────────────────────────────────┘
```

**왜 독인가:** 독은 "흐르는 것"이다. 적용 진행도 흐르는 것이다. **정의가 일치한다.**
별도 시트를 만들면 독과 겹치는 영역을 두고 규칙을 또 만들어야 한다. 그건 모순의 씨앗이다.

- 적용을 시작하면 **독이 자동으로 열리고 그 탭이 활성화**된다.
- 상세 패널·AI 패널과 **동시에 열려 있어도 된다** (§5.5의 최소 폭 규칙 적용).
- 독을 닫아도 진행은 계속된다.

### 7-A.7 진행 배지 — AI 버튼과 겹치지 않는다 (모순 해소)

독을 닫으면 **우하단 AI 버튼 왼쪽에** 진행 배지가 나란히 뜬다.

```
                          ⟳ 3/6    ✦
                          ↑        ↑
                       진행 배지   AI (고정 위치, 절대 안 밀린다)
```

**AI 버튼은 절대 자리를 옮기지 않는다.** 배지가 그 왼쪽에 추가될 뿐이다.
배지 클릭 → 독이 열리며 해당 탭 활성화.

### 7-A.8 여러 변경이 동시에 진행되면

```
⟳ 2건    ✦
```
클릭하면 독이 열리고 **탭이 여러 개**다:
```
[⟳ checkout-api 4/6] [⟳ payment-api 2/6] [로그: checkout]
```
**진행 중인 변경을 숨기지 않는다.**

### 7-A.9 드리프트 되돌리기는 Git을 건드리지 않는다 ★ (모순 해소)

**중요한 구분.** Applications의 두 액션은 **다른 파이프라인을 탄다.**

| 액션 | 상황 | 단계 |
|---|---|---|
| **[Git대로 되돌린다]** | 클러스터가 Git과 어긋남. **Git은 이미 옳다.** | **재동기화만.** Git 커밋 없음. **4~6단계만** 탄다 |
| **[현재 상태를 Git에 반영]** | 클러스터의 현실을 Git에 적는다 | **1~6단계 전부.** 새 커밋(또는 PR) |

```
[Git대로 되돌린다] 진행:
  ✓ 검증
  ⟳ 클러스터 반영     ← 3단계(Git 커밋·웹훅)를 건너뛴다. Git이 안 바뀌니까.
  ○ 롤아웃
  ○ 안정화 확인
```

**Git을 안 바꾸는데 커밋 단계를 그리면 거짓말이다.**
BE-Gap 규율과 같다 — **일어나지 않는 일을 그리지 않는다.**

(VP-014 §1.3의 "[Git대로 되돌린다] — 즉시 적용 가능"은 이 뜻이다. 명확히 한다.)

### 7-A.10 "즉시"가 진짜 즉시가 되려면 — 웹훅 → 에이전트 푸시

**Git 커밋 → 웹훅 → 에이전트 폴링 대기**면 수십 초가 걸린다. "급해 죽겠는데"의 답이 아니다.

**해결: 웹훅을 받는 즉시 에이전트에게 밀어준다.**
에이전트는 아웃바운드 롱폴링 연결을 유지하고 있으므로, **다음 폴링 주기를 기다리지 않는다.**
```
Git 커밋 → 웹훅 수신 → 열려 있는 에이전트 연결로 즉시 통지 → 적용
```
목표: **커밋에서 반영까지 5초 이내.** 이게 안 되면 "즉시 모드"라고 부르지 않는다.

### 7-A.11 백엔드 계약

| BQ | 계약 | 규칙 |
|---|---|---|
| BQ-076 | `POST /changes` — 변경 제출 (모드는 정책이 결정) | `change_id` 반환. **모드를 클라이언트가 정하지 않는다** |
| BQ-077 | `SSE /changes/{id}/progress` — **단계 이벤트 스트림** | 각 단계의 `pending/running/done/failed` + 소요시간 + 실패 이유. **추정치 금지, 실제 이벤트만** |
| BQ-078 | `POST /changes/{id}/revert` — 되돌리기 (revert 커밋 생성) | 같은 파이프라인을 탄다 |
| BQ-079 | `GET /changes/active` — 진행 중인 변경 목록 | 진행 배지용 |

**BE-Gap 규율:** 백엔드가 어떤 단계를 보고하지 못하면 **그 단계를 렌더하지 않는다.**
6단계를 억지로 채우지 않는다. 3단계만 보고되면 3단계만 그린다.

**Radar 컴포넌트를 가져오되 우리 shadcn 토큰으로 다시 칠한다.**

| `resources/renderers/*` (108) | 3층 표 컬럼 · 상세 |
| `checks/*, audit/*` | Checks (31개 감사 체크) |
| `applications/*` | Applications (+ 드리프트 탭) |
| `gitops/*` (23) | GitOps [동기화 상태] 탭 |
| `ui/*` (48) | **shadcn primitive로 매핑** (§9.1) |

### 9.1 primitive 매핑 — **정본은 `components/ui/` 한 곳뿐**

| Radar `ui/` | shadcn |
|---|---|
| Badge · Tooltip · Collapse · CardSection | `badge` `tooltip` `collapsible` `card` |
| ConfirmDialog · ForceDeleteConfirmDialog | `alert-dialog` |
| Toast | `sonner` |
| Input · SearchBox · SearchPillInput | `input` + `command` |
| SelectMenu · MultiSelectPicker | `select` `command` |
| **대응 없음**: YamlEditor(Monaco) · CodeViewer · HealthRing · DistributionBar · SummaryTile · Facet · FilterPill · SortableTh · MiddleEllipsis · ResourceBar | **shadcn primitive를 조합해서 만든다.** 새 primitive를 손으로 짜지 않는다. |

**금지:**
- Radar의 **색·간격·모서리·duration을 하드코딩**으로 가져오는 것 → 토큰만
- Radar의 theme CSS 변수를 그대로 쓰는 것 → 우리 `theme.css`로 치환
- primitive가 **두 곳에 존재**하는 것

**아이콘**: 둘 다 lucide. 그대로.
**차트**: 우리는 **recharts 단일화**. Radar `charts/`는 재작성.

### 9.2 라이선스 (필수)

Radar는 **Apache-2.0**. 반드시:
1. 루트 `NOTICE` — 원저작자(Skyhook) · 라이선스 · 출처 URL
2. 이식 파일 상단에 **원본 헤더 보존 + 수정 사실 표기**
3. `README.md`에 명시
4. `references/radar-upstream/` 고정 커밋 서브트리

**안 하면 오픈소스 공개 시 라이선스 위반이다.**

## 11. 금지 사항 (전역)

- 검색 위치가 화면마다 다른 것
- 2층 높이가 화면마다 다른 것
- 필터가 표에만 적용되고 그래프에 안 되는 것
- **파드 크기로 위험을 표현하는 것** (크기 = 고정, 채움 = 사용률, 배지 = 상태)
- **색 채널 하나에 두 의미를 싣는 것**
- 서버 위에 네임스페이스 상자를 겹쳐 그리는 것
- 파드를 100개 다 그리는 것 (12개 + `+N`, **문제 있는 것 우선**)
- 그래프에 "클러스터", "노드" 같은 용어를 쓰는 것 → **서버**
- 상세를 새 페이지(라우트 이동)로 여는 것 → **같은 라우트의 `?detail=` 오버레이**
- **상세 패널을 480px 사이드 패널로 여는 것** → 열면 곧바로 **전체화면으로 목록을 덮는다** (§5.2)
- **상세 패널에 드래그 리사이즈·중간 폭 상태를 만드는 것** → 상태는 닫힘/전체화면 **둘뿐**
- **닫기 버튼을 뷰포트에 고정하는 것** → 패널 좌상단 부착
- **AI 패널이 왼쪽에서 열리는 것** → 오른쪽에서 열려 상세를 왼쪽으로 민다
- **사이드바를 완전히 숨기는 것** → 레일(56px)로 축소
- **줌 전환을 정적 리렌더로 처리하는 것** → 카메라 이동 (§4.6, VP-017)
- **노드·파드를 스태거 없이 동시에 그리는 것**
- 로그를 우측 패널에 넣는 것 → 하단 독
- 좁은 화면에서 조용히 레이아웃이 깨지는 것 → 토스트로 알림
- 권한 없는 버튼을 disabled로 보여주는 것 → **렌더하지 않는다**
- 계약 없는 필드를 0·disabled로 렌더하는 것
- primitive가 두 곳에 존재하는 것
- Radar의 색·간격을 하드코딩으로 가져오는 것
