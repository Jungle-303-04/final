# VP-018 — 셸 정정

**VP-015 §5.2의 "열리면 곧바로 전체화면"은 잘못된 규정이었다. 철회한다.**
"상세가 이전 화면을 덮어야 한다"는 우녕의 말은 **확장 상태**를 뜻한 것이지,
**기본 상태**를 뜻한 게 아니었다. 조율 세션이 과잉 일반화했다.

---

## 1. 상세 패널 — **3상태**. 그리고 **AI와 완전히 독립**이다

### 1.0 레이아웃 — **사이드바만 불변이다. 나머지는 상세가 덮는다** ★

**앞선 초안의 "1층은 절대 덮이지 않는다"는 틀렸다. 철회한다.**
(그 규정을 지키면 사이드바 토글을 1층에 둬야 하는데, 상세가 1층을 덮는 순간 토글이 사라진다.
 규정 자체가 자기모순이었다.)

```
살짝 (peek) — 기본                       전체 (full)
┌──────┬──────────────────────┐        ┌──────┬───────────────────────┐
│      │ 🔍 [칩] 필터 추가…   │        │      │ ≫  checkout-api-7d9f ✕│
│ 사이 ├───────────┬──────────┤        │ 사이 │ [개요][YAML][이벤트]  │
│ 드바 │ 2층 그래프 │ 상세 480 │   ≪→   │ 드바 │                       │
│ [◧]  │ 3층 표     │          │   ←≫   │ [◧]  │  상세가 콘텐츠 전체    │
│      │            │          │        │      │  (검색바까지 덮는다)   │
└──────┴───────────┴──────────┘        └──────┴───────────────────────┘
   ↑ 사이드바는 어떤 상태에서도 그대로. 자기 토글 [◧] 로만 접힌다.
```

**불변식 (이것 하나만 지키면 모순이 안 생긴다):**

> **사이드바는 셸이다. 나머지 전부(검색·그래프·표)는 콘텐츠다.**
> **상세의 "전체화면"은 콘텐츠 영역 전체를 덮는다는 뜻이다. 셸은 안 덮는다.**

- **사이드바 토글 `[◧]` 는 사이드바 자신의 헤더 안**(로고 오른쪽)에 둔다.
  사이드바는 **절대 사라지지 않으므로** 토글도 절대 사라지지 않는다. 항상 누를 수 있다.
  (shadcn `SidebarTrigger` + `SidebarRail`. 접힌 rail을 클릭해도 펴진다.)
- **맥락은 상세가 스스로 말한다.** 검색바가 가려지는 대신, 상세 헤더 제목 아래에
  **`prod-eks / target / Pod`** 경로 한 줄을 둔다. 어디의 무엇인지 잃지 않는다.
- `≫` 를 누르면 즉시 살짝으로 돌아가 검색바와 목록이 다시 보인다. **되돌아가는 비용이 1클릭이다.**

### 1.1 두 축은 **독립**이다 — 서로를 닫지 않는다

```
detail ∈ { 닫힘, 살짝, 전체 }        ← 상세 확장/축소 버튼과 행 클릭이 바꾼다
ai     ∈ { 닫힘, 열림 }              ← ✦ 버튼만 바꾼다
```

**이 둘은 별개의 상태다.** 하나를 바꿔도 다른 하나는 **그대로 유지된다.**

| 조작 | detail | ai |
|---|---|---|
| 행/파드 클릭 | 닫힘 → **살짝** | **변화 없음** |
| **확장 버튼 `≪`** | 살짝 → **전체** | **변화 없음. AI가 열려 있으면 열린 채로 유지된다** ★ |
| **축소 버튼 `≫`** | 전체 → **살짝** | **변화 없음** ★ |
| 닫기 / `Esc` | → **닫힘** | **변화 없음. AI는 안 닫힌다** |
| **✦ AI 열기** | 살짝이면 → **전체**로 승격 (그 외엔 변화 없음) | 닫힘 → **열림** |
| ✦ AI 닫기 | **변화 없음.** 전체면 전체로 남는다 | 열림 → **닫힘** |

**지금 시안의 버그 두 개 — 여기서 원천 봉쇄된다:**
- ~~AI가 열린 상태에서 확장 버튼을 누르면 AI가 사라진다~~ → **확장/축소는 AI를 절대 건드리지 않는다.**
- ~~AI를 누르면 상세가 딸려 열린다~~ → **AI 열기는 detail이 `닫힘`이면 `닫힘` 그대로 둔다.**
  승격은 **`살짝`일 때만** 일어난다 (살짝 + AI = 너무 좁아서).

### 1.2 확장 버튼 아이콘 — **방향을 그린다**

상세는 **오른쪽 가장자리에 고정된 채 왼쪽 경계가 왼쪽으로 밀려서** 넓어진다.
대각선 화살표(`⤢`)는 **네 모서리로 퍼지는 창**을 뜻해서 이 동작과 안 맞는다.

| 동작 | 아이콘 (lucide) | 툴팁 |
|---|---|---|
| 살짝 → 전체 | **`ChevronsLeft`** (`≪`) | "넓게 보기" |
| 전체 → 살짝 | **`ChevronsRight`** (`≫`) | "좁게 보기" |
| 닫기 | `X` | "닫기 (Esc)" |
| 사이드바 토글 | `PanelLeft` — **사이드바 헤더 안** (§1.0) | "사이드바" |

**확장/축소 버튼은 상세 패널의 좌상단에 부착한다.** `position: fixed` 금지 —
AI가 열려 패널이 좁아지면 같이 따라간다.

### 1.1-a DOM 구조 — 이게 모순을 구조적으로 막는다 ★

```
shell    = [ Sidebar | Content ]              ← Sidebar는 셸. 절대 안 덮인다
Content  = [ Main    | AiPanel ]              ← AI는 Main의 형제. 상세 안에 넣지 않는다
Main     = [ ListColumn | DetailPanel ]       ← ListColumn = 1층 검색 + 2층 그래프 + 3층 표
```

| 상태 | ListColumn | DetailPanel | AiPanel |
|---|---|---|---|
| 기본 | `flex:1` | `w-0` | `w-0` |
| 살짝 | `flex:1` | `w-480` | `w-0` |
| 전체 | `w-0` (`opacity-0`) | `w-full` | `w-0` |
| 목록 + AI | `flex:1` | `w-0` | `w-420` |
| 전체 + AI | `w-0` | `w-full` | `w-420` |

**AI를 `DetailPanel` 안에 넣으면 안 된다.** 넣는 순간 "상세 없이는 AI를 못 연다"가 되는데,
그건 틀렸다. **목록만 보면서도 물을 수 있어야 한다** ("이 네임스페이스에 문제 있는 파드 있나?").
AI가 `Main`의 형제이므로 **상세가 열려 있든 없든 똑같이 열린다.** 축이 진짜로 독립이 된다.

**AI 맥락 칩은 지금 상태를 그대로 비춘다:**
- 상세가 열려 있으면 → `[리소스] [prod-eks] [checkout-api-7d9f]`
- 목록만 보고 있으면 → `[리소스] [prod-eks] [ns: target]`
추천 질문도 그 맥락 기준으로 서버가 만든다 (BQ-053).

### 1.2-a 전체 + AI 배치

```
전체 + AI
┌──────┬──────────────────────────────┬─────────────┐
│      │ ≫  checkout-api-7d9f       ✕ │ ✦ Opsia AI ✕│
│ 사이 │ [개요][YAML][이벤트]         │             │
│ 드바 │  prod-eks / target / Pod     │  대화 스레드 │
│ [◧]  │                              │             │
│      │  상세 (전체 − AI 폭)          │  [질문하세요]│
└──────┴──────────────────────────────┴─────────────┘
```
- **목록은 보이지 않는다.** 상세가 콘텐츠 전체를 덮은 상태에서 AI가 오른쪽을 나눠 가진다.
- `≫` 는 왼쪽, AI는 오른쪽. 물리적으로 겹칠 수 없다.
- **AI를 닫아도 상세는 전체로 남는다.** `≫` 를 눌러야 살짝으로 돌아간다.

### 1.3 공간이 모자랄 때 — **마지막 조작이 이긴다**

`사이드바(180) + 목록최소(360) + 상세(480) + AI(420) = 1440px`.
이보다 좁으면 셋을 동시에 못 놓는다.

**규칙: 사용자가 방금 한 조작을 존중하고, 물러나는 쪽을 토스트로 알린다.**

| 상황 | 결과 |
|---|---|
| `살짝` 상태에서 **AI를 열었다** | 상세가 `전체`로 승격 (목록이 물러난다). 토스트 없음 — 예상된 동작 |
| `전체 + AI` 에서 **축소를 눌렀다**, 그런데 폭이 1440px 미만 | 축소가 이긴다 → **AI가 닫힌다.** 토스트: "AI를 닫고 상세를 좁혔습니다" |
| 뷰포트 < 896px | 어떤 조합이든 **하나만** 전체화면 시트 (VP-015 §5.7 모바일 규칙) |

**조용히 깨지지 않는다. 무엇이 물러났는지 항상 말한다.**

### 1.1 사이드바는 **절대** 자동으로 접히지 않는다 ★

**지금 코드의 가장 큰 잘못.** `useDetailSidebarRail`이 상세를 열면 사이드바를 강제로 접는다.

> "사이드바는 해당 접기 버튼 아니면 절대로 접히면 안 된다." — 우녕

- **사이드바 접힘은 오직 사이드바 자신의 토글 버튼으로만 일어난다.**
- 상세 열림 / 전체화면 / AI 열림 — **무엇도 사이드바를 건드리지 않는다.**
- 상세의 "전체화면"은 **콘텐츠 영역 전체**를 뜻한다. 사이드바는 콘텐츠 영역이 아니다.
- `useDetailSidebarRail` 은 **삭제한다.**

```
전체화면 상세 (사이드바 펼침 유지)
┌──────────┬────────────────────────────────────────┐
│ 메뉴 200 │ ⤡  checkout-api-7d9f                   │
│          │  [개요][YAML][관련][이벤트]             │
│          │                                         │
└──────────┴────────────────────────────────────────┘
        ↑ 사이드바는 그대로. 사용자가 접기 전엔 안 접힌다.
```

### 1.2 AI를 열면

```
상세가 ② 살짝 상태 → AI 클릭
  STEP 1 (320ms)  상세가 ③ 전체화면으로 확장 (목록을 덮는다)
  STEP 2 (300ms)  AI가 오른쪽에서 420px 슬라이드 인. 상세가 그만큼 좁아진다
```
**사이드바는 두 단계 어디서도 움직이지 않는다.**
(VP-015 §5.4의 "1단계 애니메이션"은 상세가 이미 전체화면일 때만 해당. ②에서 열면 2단계다.)

### 1.3 URL

- `?detail=<kind>/<ns>/<name>` — 유지 (새로고침 복원, 링크 공유, 뒤로가기=닫기)
- **`?detail.full=1`** — ③ 전체화면 상태도 URL에 남는다. peek(②)은 파라미터 없음.
- 폐기 예정이던 `full` 코덱을 **되살려 정본화한다.**
- `J`/`K` 목록 이동 — 유지 (② ③ 둘 다에서 동작)

## 2. 사이드바

### 2.1 순서 (우녕 확정)

```
지금 (잘못됨)            확정
─────────────────       ─────────────────
클러스터                 홈
홈                       클러스터
리소스                   리소스
인시던트                 인시던트
메트릭                   애플리케이션
애플리케이션             GitOps
워크플로우               체크
카탈로그                 AI 채팅
                        ─────────  (구분선)
                        설정
                        ─────────
                        [프로필 · 워크스페이스]   ← 하단 고정
```

- **홈이 최상단.** (VP-015 §1의 "Clusters 최상단"을 정정한다)
- `메트릭`·`카탈로그`는 기획에 없는 화면이다. **메뉴에서 뺀다.**
  (메트릭 = 리소스 상세의 탭 / 카탈로그 = 미정)
- `워크플로우` → **`GitOps`**로 이름 통일. 두 이름이 같은 것을 가리키면 안 된다.
- `체크`·`AI 채팅`은 아직 화면이 없다. **화면이 생길 때 메뉴에 넣는다** (BE-Gap 규율).

### 2.2 하단 — 프로필 · 워크스페이스 (지금 없다)

```
┌────────────────────────┐
│ …메뉴…                 │
│                        │
├────────────────────────┤
│ ⌂ 워크스페이스: default │  ← 클릭 → 워크스페이스 전환 popover
├────────────────────────┤
│ (아바타) 우녕           │  ← 클릭 → 프로필 · 설정 · 로그아웃
│          woonyong.dev@…│
└────────────────────────┘
```

**지금은 `user-bf4f9d6a-acf5-…` 라는 UUID가 잘려서 나온다. 사람이 읽을 수 없다.**
- 표시 이름은 `display_name` → 없으면 `email` → 없으면 UUID 앞 8자 + `…`
- 툴팁에 전체 값
- **UUID를 그대로 이름 자리에 넣지 않는다.**

레일(56px)로 접었을 때는 아바타만 남고, 클릭하면 같은 메뉴가 popover로 열린다.

## 3. 검색 (1층) — 칩은 **입력창 안에** 들어간다

### 3.1 지금의 잘못

```
[네임스페이스: target ✕]   🔍 클러스터, 앱, 라벨, 리소스 필터
 ↑ 칩이 입력창 밖 왼쪽에 떠 있다. 두 개가 서로 다른 컨트롤처럼 보인다.
```

칩이 늘어나면 **두 줄로 흐르고**, 검색창이 밀린다. 자리가 고정되지 않는다.

### 3.2 확정 — 하나의 컨트롤

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍 [네임스페이스: target ✕] [앱: checkout ✕] 필터 추가…   ✕비우기│
└──────────────────────────────────────────────────────────────┘
        ↑ 칩이 입력창 안. 커서는 칩 오른쪽. 태그 입력창의 표준 패턴.
```

- **칩·입력·비우기가 하나의 border 안에 있다.** (shadcn `command` + `badge` 조합)
- **절대 두 줄이 되지 않는다.** 칩이 넘치면 **가로 스크롤**, 또는 `+N개` 로 접고 클릭 시 popover.
- 검색창의 **높이가 고정**이다. 칩 개수와 무관하게 아래 레이아웃이 안 밀린다.
- `Backspace`(빈 입력에서) → 마지막 칩 삭제. 표준 동작.

### 3.3 모든 목록 화면에 같은 자리 (우녕 확정)

**홈을 제외한 모든 화면**에 1층 검색이 **정확히 같은 위치·같은 컴포넌트**로 있다.

| 화면 | 1층 검색 | 상태 |
|---|---|---|
| 홈 | **없음** (위젯 대시보드. 골격 예외) | — |
| 클러스터 | 있어야 함 | **없다. 추가** |
| 리소스 | 있음 | 위 §3.2로 교정 |
| 인시던트 | 있어야 함 | **없다. 추가** |
| 애플리케이션 | 있어야 함 | **없다. 추가** |
| GitOps | 있어야 함 | **없다. 추가** |
| 체크 | 있어야 함 | 화면 자체가 미구현 |

**화면마다 검색이 있다 없다 하면 눈이 매번 그 자리를 다시 찾는다.** 골격이 깨진다.

## 4. 그래프 (2층) — 잘리면 안 된다

### 4.1 지금의 잘못

```css
/* ResourcesGraphShell.tsx:136 */
h-96 sm:h-80          /* 384px → 데스크톱에서 오히려 320px로 줄어든다 */
```
그리고 캔버스가 `absolute inset-x-0 bottom-0 top-20`(툴바 아래) 로 **고정 높이 상자 안**에
갇혀 있어서, 노드가 많아지면 **밖으로 잘린다.**

### 4.2 확정

| 항목 | 확정 |
|---|---|
| **높이** | **720px** — 지금(320px)의 **2.25배.** `--product-graph-height: 45rem` 토큰 |
| **높이 조절** | 하단 가장자리 드래그로 **480~1040px**. 값은 로컬에 저장(사용자별로 기억) |
| **잘림** | **금지.** ELK 레이아웃 후 `fitView({ padding: 0.12 })`. 컨테이너 `ResizeObserver`에 반응해 재-fit |
| **넘칠 때** | 잘라내지 말고 **줌 아웃**한다. 최소 줌 0.4까지. 그래도 안 들어오면 **`+N개` 축약**(§4.4) |
| **모바일** | `sm` 미만에서만 400px. **데스크톱이 더 작아지는 지금 규칙(`h-96 sm:h-80`)은 버그다** |
| **접기** | `⌃` 로 접힘. 접힌 상태는 URL(`graph=0`)에 남는다 (VP-015 §2.1) |

**720px면 3층 표가 접힘 아래로 밀린다. 그게 맞다.**
- **그래프가 주인공이다.** 표는 스크롤해서 본다.
- 표의 **헤더 행은 sticky**. 스크롤해도 컬럼 이름이 남는다.
- 표만 보고 싶으면 **`⌃` 로 그래프를 접는다.** 그 상태가 URL에 남으니 다음에도 유지된다.
- **VP-015 §2.1의 "2층 높이 320px 고정"은 폐기.** 대신 **"2층 높이는 모든 화면에서 같다"**가 규칙이다.
  (사용자가 조절한 값이 모든 목록 화면에 동일하게 적용된다. 화면마다 다르면 안 된다.)

### 4.3 오버레이가 그래프를 가리지 않는다 ★

> "플레이바는 거의 투명으로. 실제 화면을 가리면 안 되는데 많이 가리네." — 우녕

지금 그래프 위 툴바가 `absolute top-0` + `bg-background/80 backdrop-blur` 로 **캔버스를 덮고 있다.**

**확정:**
- **툴바는 캔버스 위에 겹치지 않는다.** 그래프 셸을 **flex column**으로 바꿔 툴바가 자기 높이를 차지하고,
  캔버스가 **남은 공간 전부**를 쓴다. `absolute` 오버레이를 없앤다.
- 캔버스 위에 **꼭 떠 있어야 하는 것**(자동 전환 힌트, 줌 컨트롤, 범례)만 오버레이로 두되:
  - 배경 **`bg-background/40`** 이하 (거의 투명)
  - `pointer-events: none` (내부 버튼만 `auto`)
  - **캔버스 중앙을 절대 덮지 않는다.** 모서리에만.
  - 힌트는 6초 후 사라진다 (이미 구현됨)

### 4.4 파드 12개 상한 — **정의만 있고 안 쓰인다** (미구현)

`MAX_VISIBLE_PODS_PER_SERVER = 12` 상수가 있는데 아무 데서도 참조하지 않는다.
VP-015 §4.3대로 **문제 우선 정렬 후 12개 + `+N개`** 를 실제로 적용한다.
(백엔드가 이미 `truncated`를 주므로 프론트는 서버 순서를 신뢰하되, **상한은 프론트가 강제**한다.)

## 9. AI 패널 — 지금은 **채팅이 아니라 폼이다** ★

> "AI 창도 이상해. 실제 AI 인터페이스도 아니고." — 우녕

### 9.1 지금의 잘못 (실물 기준)

```
┌────────────────────────────┐
│ ✦ Opsia AI              ✕  │
│ 현재 화면의 정확한 맥락을… │  ← 설명문이 자리를 차지한다
├────────────────────────────┤
│ 현재 맥락                   │
│ (resources)(cluster-1)…    │
│ 추천 질문                   │
│ [선택 리소스 상태]          │  ← 질문이 아니라 **명사구**다
│ [리소스 건강도]             │
│ [현재 상태 요약]            │
│                            │
│         (거대한 공백)       │  ← 대화가 없으니 화면 절반이 빈다
│                            │
├────────────────────────────┤
│ [입력창]                    │
│                    [질문]   │  ← 버튼이 입력창 밖 오른쪽 아래
└──────────────────────  ✦ ──┘  ← FAB이 입력 영역을 덮는다
```

문제 여섯 가지:
1. **대화 스레드가 없다.** 질문/답변이 말풍선으로 쌓이지 않는다. 한 번 묻고 끝나는 폼이다.
2. **스트리밍이 없다.** 답이 통째로 나타난다. 기다리는 동안 아무 일도 안 일어난다.
3. **추천 질문이 질문이 아니다.** "선택 리소스 상태"는 명사구다. 누르면 뭐가 되는지 모른다.
4. **거대한 공백.** 빈 상태에 아무것도 없다.
5. **FAB(✦)이 입력창을 덮는다.** 패널이 열려 있으면 FAB은 사라져야 한다.
6. **이력·새 대화·중단이 없다.** VP-015 §1이 약속한 "대화 이력 공유"가 UI에 없다.

### 9.2 확정 — 진짜 대화 인터페이스

```
┌──────────────────────────────────────────┐
│ ✦ Opsia AI     [＋ 새 대화] [⟲ 이력]  ✕ │  ← 설명문 삭제. 액션이 그 자리를 쓴다
├──────────────────────────────────────────┤
│ 맥락  [resources][cluster-1][Service/…]  │  ← 한 줄. 접힘 가능
├──────────────────────────────────────────┤
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ 이 서비스에 파드가 안 붙어 있어? │  │  ← 사용자 (오른쪽 정렬)
│  └────────────────────────────────────┘  │
│                                          │
│  ✦ loki Service의 셀렉터 app=loki 와     │  ← AI (왼쪽 정렬)
│    일치하는 파드가 0개입니다.            │
│    ▍  ← 스트리밍 커서                    │
│                                          │
│    근거                                   │
│    ▸ Service/target/loki  (셀렉터)  ↗    │  ← 클릭 = 그 리소스 상세로
│    ▸ Pods in target (0 matched)     ↗    │
│                                          │
├──────────────────────────────────────────┤
│ ┌──────────────────────────────────┐     │
│ │ 지금 보고 있는 것에 대해 물어보세요│  ▶ │  ← 전송 버튼이 입력창 **안**
│ └──────────────────────────────────┘     │
│  Enter 전송 · Shift+Enter 줄바꿈          │
└──────────────────────────────────────────┘
   (FAB 없음 — 패널이 열려 있으면 숨긴다)
```

| 항목 | 확정 |
|---|---|
| **대화 스레드** | 사용자/AI 메시지가 **쌓인다.** 스크롤. 새 메시지 오면 하단으로 자동 스크롤 (사용자가 위로 올렸으면 안 한다 + "새 메시지 ↓" 버튼) |
| **스트리밍** | 토큰 단위로 흘러나온다. 커서 `▍` 표시. **응답이 끝날 때까지 [중단] 버튼**이 전송 자리에 뜬다 |
| **빈 상태** | 공백이 아니라 **맥락에 맞는 실제 질문 3개.** 명사구 금지 |
| **추천 질문** | **완전한 문장이어야 한다.** 서버(BQ-053)가 맥락 기반으로 생성. 예: "이 Service에 왜 파드가 안 붙어 있나요?" / "최근 1시간 안에 이 네임스페이스에 무슨 변경이 있었나요?" |
| **근거** | 답변 아래 접히지 않은 목록. **클릭하면 그 리소스의 상세가 열린다** (`?detail=`). evidence 없으면 **답변을 렌더하지 않는다** (이미 구현됨 — 유지) |
| **전송 버튼** | 입력창 **안쪽 오른쪽**. 밖에 두지 않는다. `Enter` 전송 / `Shift+Enter` 줄바꿈 |
| **FAB** | 패널이 열려 있으면 **숨긴다.** 지금은 입력창을 덮고 있다 |
| **＋ 새 대화** | 스레드를 비운다. 이전 대화는 이력에 남는다 |
| **⟲ 이력** | 지난 대화 목록. 각 항목에 **맥락 스냅샷**(화면·필터·선택·시각). 클릭 = 그 맥락으로 복원 (VP-015 §1) |
| **설명문** | **삭제.** "현재 화면의 정확한 맥락을 질문하고 근거를 확인합니다"는 자리만 먹는다. 빈 상태의 추천 질문이 그 역할을 한다 |
| **에러** | 실패하면 그 말풍선 자리에 **재시도 버튼**. 스레드를 잃지 않는다 |

**백엔드**
- `SSE POST /ai/chat` — **스트리밍 필수.** 지금은 단발 응답(BQ-052). **스트리밍 계약을 추가한다 (BQ-080).**

- 추천 질문은 **완전한 문장**으로 반환하도록 BQ-053 응답 규격을 조인다.

**회귀 가드**

- 전송 버튼이 입력창 밖에 있으면 FAIL

### 10.1-a shadcn Blocks / Create 를 **써도 된다. 오히려 써야 한다.** ★

> "https://ui.shadcn.com/create 여기 깔끔한 레퍼런스 많네. 이런 거 이용하면 안 되는 건가?

**써도 된다.**

- shadcn은 라이브러리가 아니라 **"코드를 내 저장소로 복사해 오는" 배포 방식**이다.

### 10.1-b shadcn **문법 규칙**을 그대로 따른다 (필수)

**`ui.shadcn.com` 의 컴포넌트 작성 규약을 우리 코드의 문법으로 채택한다.**
"비슷하게 생기게"가 아니라 **"같은 문법으로 쓴다".** 그래야 Blocks를 가져다 붙였을 때
우리 코드와 이질감 없이 붙고, 다음 사람이 shadcn 문서를 그대로 읽으면 우리 코드를 안다.

| 규약 | 내용 | 위반 예 |
|---|---|---|
| **`cn()` 유틸** | 모든 `className`은 `cn(...)` 을 통과한다. `clsx` + `tailwind-merge` | 문자열 템플릿으로 클래스 조립 |
| **`cva` 변형** | 변형(variant/size)은 `class-variance-authority` 로 선언한다. 컴포넌트 안에서 `if`로 클래스 분기 금지 | `className={isDanger ? "bg-red-500" : "bg-gray-200"}` |
| **`data-slot`** | 모든 primitive의 루트에 `data-slot="<name>"`. **테스트와 스타일 훅은 이걸로 잡는다** | 테스트가 클래스명이나 텍스트로 요소를 찾는 것 |
| **`asChild` / Radix `Slot`** | 합성이 필요한 곳(버튼→링크 등)은 `asChild`. 래퍼 div를 새로 만들지 않는다 | `<div onClick>` 으로 버튼 흉내 |
| **시맨틱 토큰만** | `bg-background` `text-foreground` `text-muted-foreground` `border` `bg-accent` `bg-destructive` `ring` `bg-card` `bg-popover` | `bg-zinc-900` `text-gray-400` `bg-[#18181b]` — **팔레트 색 직접 사용 금지** |
| **Tailwind v4 + CSS 변수** | 색은 `oklch()` 로 `:root` / `.dark` 에 선언. `@theme inline` 으로 매핑 | 색을 컴포넌트에 하드코딩 |
| **임의값 금지** | `w-[437px]` `text-[13px]` 같은 arbitrary value를 쓰지 않는다. 스케일(`size-9`, `text-sm`)을 쓴다 | 눈대중 픽셀 |
| **`size-*`** | 정사각형은 `h-4 w-4` 가 아니라 `size-4` | |
| **포커스 링** | `focus-visible:ring-ring/50 focus-visible:ring-[3px]` 표준 패턴 | 포커스 스타일 제거 |
| **`aria-invalid`** | 폼 에러는 `aria-invalid` 로 표현하고 스타일은 `aria-invalid:ring-destructive/20` | 빨간 테두리만 |
| **RSC 친화** | `forwardRef` 없이 `ref` 를 prop으로 받는 React 19 스타일 | 불필요한 `forwardRef` 래핑 |
| **파일 위치** | primitive = `shared/ui/primitives/<name>.tsx`, 블록 = `shared/ui/blocks/`. **정본은 두 곳뿐** | 화면 폴더에 primitive 복제 |
| **커스텀 CSS 파일 금지** | 스타일은 유틸리티 클래스 + 토큰. 컴포넌트별 `.css` 파일을 만들지 않는다 | `ResourceTable.css` |

**회귀 가드:**
- `.tsx` 에서 Tailwind **팔레트 색 클래스**(`bg-zinc-*`, `text-gray-*`, `border-slate-*` 등)가
  하나라도 등장하면 **FAIL** (시맨틱 토큰만 허용)
- **arbitrary value**(`[...]` 대괄호 클래스)가 허용목록 밖에서 등장하면 FAIL
  (허용: `ring-[3px]` 같은 shadcn 표준 패턴만)
- primitive 루트에 `data-slot` 이 없으면 FAIL
- 컴포넌트별 `.css` 파일이 생기면 FAIL

**Radar 이식도 이 문법을 통과해야 한다.** Radar 원본의 클래스를 그대로 붙여넣지 않는다.

**규칙 (이어서):**
- **shadcn에 있는 것을 손으로 다시 만들지 않는다.** primitive는 `shared/ui/primitives/` 한 곳뿐.
- **차트는 반드시 `ChartContainer`를 통과한다.** recharts를 직접 쓰지 않는다.
  → 색·툴팁·범례·반응형이 전부 토큰으로 통일된다. 지금 `ResourceSparkline.tsx`는 recharts 직접 사용 → **교정.**
- Radar에서 이식한 컴포넌트도 **이 primitive 위에 다시 올린다.** (VP-015 §9.1)

### 10.2 크기가 흔들리지 않는다 — **레이아웃 안정성 계약**

**지금 화면이 어색한 진짜 원인은 색이나 폰트가 아니라, 무엇이 나타날 때마다 다른 게 밀린다는 것이다.**
(검색 칩이 붙으면 두 줄이 되고, 그래프가 데스크톱에서 오히려 작아지고, AI가 열리면 FAB이 겹친다)

| 규칙 | 내용 |
|---|---|
| **자리를 먼저 잡는다** | 데이터가 오기 전에 **최종 크기의 상자**를 그린다. 스켈레톤은 **실제 크기와 같아야 한다** |
| **높이 고정** | 1층 검색바 / 2층 그래프 / 표 행 / 상세 헤더 — **높이가 내용에 따라 변하지 않는다** (토큰으로 고정) |
| **칩·배지가 줄을 늘리지 않는다** | 넘치면 가로 스크롤 또는 `+N`. **절대 줄바꿈하지 않는다** (§3.2) |
| **숫자 폭 고정** | 수치는 `font-variant-numeric: tabular-nums`. 42% → 100% 로 바뀔 때 칸이 안 흔들린다 |
| **스크롤바 보정** | `scrollbar-gutter: stable`. 스크롤이 생겼다 없어질 때 콘텐츠가 좌우로 안 뛴다 |
| **이미지·아이콘** | 폭·높이를 항상 명시. 로고는 고정 박스 안에 `object-contain` |
| **애니메이션은 `transform`/`opacity`만** | 레이아웃 속성 애니메이션 금지 (VP-017 §10). 예외는 패널·AI의 `width` |

**회귀 가드 (CLS 계약):**
- Playwright로 주요 화면에서 **Cumulative Layout Shift < 0.05**. 넘으면 FAIL.
- 검색 칩 0개 → 5개로 늘렸을 때 **2층 그래프의 `getBoundingClientRect().top`이 변하면 FAIL.**
- 로딩 → 로딩 완료 시 **표의 첫 행 y좌표가 변하면 FAIL.**

**이 세 가지 가드가 "사이즈가 막 바뀐다"는 문제를 구조적으로 막는다.**
사람이 매번 눈으로 확인할 수 없다. 테스트가 잡아야 한다.
