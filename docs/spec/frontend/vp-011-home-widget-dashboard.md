# VP-011 — Home 대시보드 · 범용 위젯 조합 시스템

## 0. 설계 목표

**사용자가 위젯을 조립할 수 있어야 한다. 그러면서 논리적으로 모순된 위젯은 애초에
만들 수 없어야 한다.**

이 두 요구는 보통 충돌한다. 자유도를 주면 사용자가 말이 안 되는 조합을 만들고
(예: "파드 목록"을 "게이지"로 그리기), 자유도를 막으면 고정된 위젯 몇 개만 남는다.

해법은 **자유 조합을 허용하되, 조합의 유효성을 타입으로 강제**하는 것이다.
Grafana가 쓰는 방식이다 — 쿼리 결과의 **형태(shape)** 가 표현 방식을 결정하고,
Grafana는 데이터 형태에 맞는 시각화를 제안한다.

**우리는 한 걸음 더 간다: 유효하지 않은 표현은 UI에 아예 나타나지 않는다.**
그리고 **무엇이 유효한지는 서버가 선언한다** (§5 capability 카탈로그). 프론트가
백엔드가 답할 수 없는 조합을 제시하는 일이 구조적으로 불가능해진다. 이것이 BE-Gap
규율의 대시보드 버전이다.

**Opsia는 멀티 클러스터 도구다.** 따라서 "클러스터"는 필터의 한 축이 아니라
**모든 위젯에서 1급 쪼개기 축**이다 (§3.3).

## 1. 위젯의 정의

```
위젯 = 엔티티 × 측정 × 쪼개기 × 필터 × 시간 × 표현 × 범위 × 크기
```

이 8개가 전부다. 위젯 "종류"를 하드코딩하지 않는다. 지금 카탈로그에 있는 6개
기본 위젯도 실은 이 조합의 **프리셋**이다.

```json
{
  "id": "w_7f3a",
  "entity": "incidents",
  "measure": "count",
  "breakdown": "cluster",
  "filter": { "clusters": [], "namespaces": [], "applications": [], "labels": [],
              "severity": ["critical","high"], "status": ["open"] },
  "time": { "range": "24h" },
  "view": "bar",
  "scope": "inherit",
  "size": 6,
  "title": null
}
```

## 2. 8개 축

### 2.1 엔티티 (무엇에 대한 위젯인가)

계약이 있는 것만. 서버 카탈로그가 정본이다.

| 엔티티 | 설명 | 시간축 있음 |
|---|---|---|
| `incidents` | 인시던트 | O |
| `resources` | 쿠버네티스 리소스 (Pod/Deployment/Service/…) | O (스냅샷) |
| `applications` | 배포 단위 | O |
| `deployments` | 배포 이벤트 (GitOps 적용 이력) | O |
| `remediation_prs` | 복구 PR | O |
| `checks` | 점검 결과 | O |
| `clusters` | 클러스터 / 에이전트 연결 | O |
| `events` | 감사·타임라인 이벤트 | O |

**계약 없는 엔티티(비용, 사용자 등)는 카탈로그에 넣지 않는다.** disabled로도 표시하지
않는다.

### 2.2 측정 (어떻게 셀 것인가)

| 측정 | 뜻 | 산출 형태 |
|---|---|---|
| `count` | 개수 | scalar |
| `ratio` | n / m (예: 정상 노드 / 전체 노드) | ratio |
| `timeseries` | 시간에 따른 개수 변화 | series |
| `list` | 항목 목록 (최근 N개) | table |
| `latest` | 가장 최근 1건 | record |

### 2.3 쪼개기 (breakdown)

| 값 | 엔티티 제약 |
|---|---|
| `none` | 전부 |
| `cluster` | **전부 — 1급 축** |
| `namespace` | resources, applications, incidents, checks |
| `application` | resources, incidents, deployments, prs |
| `severity` | incidents, checks |
| `status` | 전부 (엔티티마다 status 도메인이 다름) |
| `kind` | resources |
| `node` | resources (단일 클러스터 필터 필요 — §4 규칙 6) |

### 2.4 필터

**VP-010 필터 문법을 그대로 쓴다.** 새 문법을 만들지 않는다.
공통 4축(cluster / namespace / application / labels) + 엔티티별 축.
같은 축 내 OR, 축 간 AND, label 끼리는 AND — VP-010 §2.3 그대로.

### 2.5 시간

- `range`: `15m | 1h | 6h | 24h | 7d | 30d`
- 시간축이 없는 조합(예: `clusters` + `latest`)에서는 **시간 컨트롤을 렌더하지 않는다.**
  회색으로 비활성화하지 않는다. 없는 것은 없는 것으로 둔다.

### 2.6 표현 — **선택이 아니라 파생**

**형태(shape)가 먼저 결정되고, 그 형태에서 유효한 표현만 제시된다.**

| 측정 | 쪼개기 | 형태 | 허용 표현 | 기본값 |
|---|---|---|---|---|
| `count` | `none` | scalar | 큰 숫자 / 게이지* | 큰 숫자 |
| `count` | 있음 | categorical | 가로 막대 / 도넛 / 트리맵 / 표 | 가로 막대 |
| `ratio` | `none` | ratio | `n / m` 큰 숫자 / 도넛 / 진행 바 / 게이지 | `n / m` |
| `ratio` | 있음 | categorical-ratio | 누적 막대 / 히트맵 / 표 | 누적 막대 |
| `timeseries` | `none` | series | 선 / 영역 / 막대 / **스파크라인** | 선 |
| `timeseries` | 있음 | multi-series | 다중 선 / 누적 영역 / **스몰 멀티플** / 히트맵 | 다중 선 |
| `list` | `none` | table | 표 / 리스트 | 리스트 |
| `list` | 있음 | grouped-table | 그룹 표 | 그룹 표 |
| `latest` | — | record | 단일 카드 | 단일 카드 |

\* 게이지는 **최대값 계약이 있을 때만** 제시된다. 임계값을 사용자가 지어내게 하지
않는다 (BE-Gap).

**측정이나 쪼개기를 바꿔서 현재 표현이 무효가 되면**, 새 형태의 기본 표현으로
자동 전환하고 **그 사실을 한 줄로 알린다** ("표현을 '가로 막대'로 바꿨습니다").
조용히 바꾸지 않고, 무효 상태로 두지도 않는다.

### 2.7 범위 (scope) — 대시보드 필터와의 관계

| 값 | 동작 |
|---|---|
| `inherit` (기본) | 대시보드 필터 ∩ 위젯 필터 |
| `pinned` | 대시보드 필터를 **무시**하고 위젯 필터만 적용 |

`pinned` 위젯은 카드에 **핀 아이콘**을 상시 표시한다. 사용자가 대시보드 필터를 걸었는데
어떤 카드는 안 좁혀지는 상황을 **절대 조용히 두지 않는다**.

### 2.8 크기

`4` (작게) / `6` (보통) / `12` (크게). 12칼럼 그리드에 순서대로 흘려 담는다.
좌표는 저장하지 않는다 (§6).

**크기가 표현을 제약한다:**
- `4`: 범례가 있는 다중 시리즈, 트리맵, 히트맵, 스몰 멀티플 **불가**
- `6`: 스몰 멀티플은 클러스터 4개까지
- 크기를 줄여서 현재 표현이 불가능해지면 §2.6과 같은 방식으로 자동 강등 + 고지

## 3. 멀티 클러스터 — 1급 시민

Opsia의 존재 이유다. 대시보드에서 이게 드러나야 한다.

### 3.1 세 가지 시점

| 시점 | 설정 | 예 |
|---|---|---|
| **합산** | breakdown `none` | "전체 클러스터 열린 인시던트 7건" |
| **비교** | breakdown `cluster` | 클러스터별 막대 / 히트맵 |
| **집중** | filter `clusters=[A]` | "prod-eks만" |

### 3.2 스몰 멀티플

`timeseries` + breakdown `cluster` + 표현 `스몰 멀티플` = **클러스터마다 작은 차트가
격자로 반복**된다. 멀티 클러스터 상태를 한 눈에 비교하는 가장 강력한 표현이며,
경쟁 제품 데모에서 잘 안 보여주는 그림이다.

- 클러스터 수가 크기 대비 많으면 상위 N개 + "+3 more"로 축약한다. 축약 기준은
  값이 아니라 **심각도/이상치 우선**이어야 한다 (조용한 클러스터를 먼저 자른다).

### 3.3 클러스터 헬스 매트릭스

`resources`/`clusters` + `ratio` + breakdown `cluster` + 표현 `히트맵`
= 행 = 클러스터, 열 = 지표(노드 정상률·파드 정상률·에이전트 연결). 멀티 클러스터
운영자가 아침에 가장 먼저 보고 싶은 그림. **프리셋으로 기본 제공**한다.

### 3.4 클러스터 축약 규칙

클러스터가 많아지면 어떤 표현도 무너진다. 규칙:
- 막대/도넛: 상위 8개 + `기타`로 묶음. `기타`는 클릭하면 전체 목록.
- 히트맵: 스크롤 없이 12행까지. 초과 시 "정렬 기준"을 사용자가 고를 수 있게 하고
  상위 12개만.
- 스몰 멀티플: §3.2.

## 4. 모순 방지 규칙 (핵심)

사용자가 논리적으로 말이 안 되는 위젯을 만들 수 **없어야** 한다.

1. **표현은 형태에서 파생된다.** 유효하지 않은 표현은 목록에 나타나지 않는다 (§2.6).
2. **엔티티가 지원하지 않는 쪼개기/필터 축은 나타나지 않는다.** 서버 카탈로그가 선언한
   것만 제시한다 (§5). 예: `clusters` 엔티티에 `kind` 쪼개기는 없다.
3. **필터로 클러스터 1개만 고른 상태에서 클러스터로 쪼개기**는 막대 1개짜리 차트가 된다.
   막지는 않되 **"쪼개기가 의미 없습니다 — 필터가 클러스터 1개입니다"**를 설정 패널에
   경고로 띄우고, 쪼개기를 `none`으로 바꾸는 원클릭 버튼을 제공한다.
4. **대시보드 필터 ∩ 위젯 필터 = ∅** 이면 **0을 렌더하지 않는다.**
   "현재 필터에 해당하는 항목이 없습니다"를 표시한다. 0건과 "필터 밖"은 다른 사실이다.
5. **`pinned` 위젯은 핀 아이콘을 상시 표시**한다 (§2.7).
6. **`node` 쪼개기는 클러스터 필터가 정확히 1개일 때만** 제시된다. 여러 클러스터의
   노드를 한 축에 섞으면 이름이 충돌한다.
7. **게이지는 최대값 계약이 있을 때만** 제시된다 (§2.6 각주).
8. **시간축 없는 조합에서 시간 컨트롤을 렌더하지 않는다** (§2.5).
9. **크기 강등 시 표현 자동 강등 + 고지** (§2.8).
10. **서버가 완전성을 증명하지 못한 수치는 만들지 않는다.** `Showing N of M`의 M을
    서버가 못 주면 partial/unavailable 상태를 표시한다 (VP-010 §2.2와 동일 규율).

## 5. 서버 capability 카탈로그 — 모순 불가능성의 근거

**프론트가 조합의 유효성을 스스로 판단하지 않는다. 서버가 선언한다.**

`GET /dashboard/catalog` 응답 (예시, 축약):
```json
{
  "revision": "2026-07-14T00:00:00Z",
  "entities": [
    {
      "id": "incidents",
      "label": "인시던트",
      "measures": ["count", "timeseries", "list", "latest"],
      "breakdowns": ["none", "cluster", "namespace", "application", "severity", "status"],
      "filters": [
        { "key": "severity", "type": "enum", "values": ["critical","high","medium","low"] },
        { "key": "status",   "type": "enum", "values": ["open","acknowledged","resolved"] }
      ],
      "time": { "supported": true, "ranges": ["15m","1h","6h","24h","7d","30d"] },
      "gauge_max": null
    }
  ],
  "views": {
    "scalar":            ["number", "gauge"],
    "ratio":             ["ratio_number", "donut", "progress", "gauge"],
    "categorical":       ["bar", "donut", "treemap", "table"],
    "categorical_ratio": ["stacked_bar", "heatmap", "table"],
    "series":            ["line", "area", "bar", "sparkline"],
    "multi_series":      ["multi_line", "stacked_area", "small_multiples", "heatmap"],
    "table":             ["table", "list"],
    "grouped_table":     ["grouped_table"],
    "record":            ["record_card"]
  },
  "size_view_limits": {
    "4":  ["number","gauge","ratio_number","progress","sparkline","list","record_card","donut"],
    "6":  ["...전부 − small_multiples(>4) − treemap"],
    "12": ["...전부"]
  },
  "presets": [ ... §7 ... ]
}
```

**이 응답에 없는 조합은 UI에 나타나지 않는다.** 새 엔티티·측정이 백엔드에 생기면
카탈로그에 추가되고, 프론트는 코드 변경 없이 새 조합을 제시하게 된다. 반대로 백엔드가
아직 못 하는 것은 프론트가 제시할 방법이 없다. **BE-Gap이 구조적으로 강제된다.**

`gauge_max`가 `null`이면 게이지 표현이 목록에서 빠진다 (§4 규칙 7의 집행 지점).

## 6. 배치 모델 — 순서 기반 12칼럼

좌표(x/y/w/h)를 저장하지 않는다. **순서 + 크기**만 저장하고 CSS Grid 12칼럼에 흘려
담는다.

- 빈 구멍·어긋난 정렬이 구조적으로 불가능
- 반응형에서 좌표가 깨지지 않음 (12 → 8 → 4 칼럼, span은 clamp)
- 계약이 단순 (문자열 배열 + 숫자)
- 나중에 자유 좌표가 필요하면 `layout` 필드를 **추가**하면 되므로 하위 호환 유지

## 7. 프리셋 — 조립을 강요하지 않는다

빈 대시보드에서 8개 축을 조립하라고 하면 아무도 안 쓴다. **"위젯 추가"는 프리셋
갤러리를 연다.** 프리셋을 고른 뒤 필요하면 커스터마이즈한다.

프리셋 정본은 **서버 카탈로그**에 있다 (프론트 하드코딩 금지).

| 프리셋 | 조합 |
|---|---|
| 열린 인시던트 | `incidents` · `count` · `none` · status=open · 큰 숫자 · 12 |
| 클러스터별 인시던트 | `incidents` · `count` · `cluster` · 가로 막대 · 6 |
| **클러스터 헬스 매트릭스** | `resources` · `ratio` · `cluster` · 히트맵 · 12 |
| 인시던트 추이 | `incidents` · `timeseries` · `none` · 24h · 선 · 6 |
| **클러스터별 추이 (스몰 멀티플)** | `incidents` · `timeseries` · `cluster` · 24h · 스몰 멀티플 · 12 |
| 최근 배포 | `deployments` · `list` · `none` · 리스트 · 6 |
| 열린 복구 PR | `remediation_prs` · `count` · `none` · 큰 숫자 · 4 |
| 점검 실패 | `checks` · `count` · `severity` · 도넛 · 4 |
| 에이전트 연결 | `clusters` · `ratio` · `none` · 진행 바 · 4 |
| 심각도별 인시던트 | `incidents` · `count` · `severity` · 도넛 · 6 |

**기본 대시보드**(첫 사용자)는 이 중 5개: 열린 인시던트(12) · 클러스터 헬스 매트릭스(12)
· 최근 배포(6) · 인시던트 추이(6) · 열린 복구 PR(4).

## 8. 편집 UX

### 8.1 두 층

- **대시보드 편집** — `[편집]` / `[완료]`. 순서 드래그, 크기, 제거, 추가. `[취소]` 없음.
- **위젯 설정** — 카드의 조절 메뉴 → `설정` → **우측 Sheet**. 8개 축을 여기서 만진다.

### 8.2 대시보드 편집 모드

평소 Home은 완전히 정적이다. 드래그 핸들도 제거 버튼도 없다. 우상단 `[편집]` 하나.

**모드 전환 신호** (iOS식 지속 흔들림은 채택하지 않는다 — 넓고 글자 많은 카드에서는
읽기 어렵고 피로하다):
- 카드 배경이 한 단계 내려앉음 (`bg-card` → `bg-muted`)
- 테두리가 점선으로
- **카드 내용(데이터)이 dim** (opacity 0.4)

iOS 홈 화면이 직관적인 진짜 이유는 흔들림이 아니라 **드래그 중 실시간 재배치**다.
그것은 그대로 가져온다.

**드래그**: `motion` v11 `Reorder.Group`/`Reorder.Item` + `layout`.
손으로 FLIP을 구현하지 않는다 (좌표 누적 오차로 카드가 튀는 문제가 실증됐다).
드래그하는 즉시 다른 카드가 미끄러져 자리를 비켜준다. 드롭까지 반응 없는 구현은 실패다.

**카드 조절 메뉴** (shadcn `dropdown-menu`):
```
설정…                 ← 우측 Sheet 열기
──────────────
◉ 작게 (4)
○ 보통 (6)
○ 크게 (12)
──────────────
🗑 제거                ← destructive
```
- hover로 열리고, 카드 밖으로 나가면 **180ms 유예 후** 닫는다 (유예가 없으면
  아이콘→메뉴 이동 중에 닫혀버린다).
- **터치·키보드에서는 클릭/Enter로도 열려야 한다.** hover 전용 금지.
- 용어는 **"제거"**. "숨김"이 아니다.

### 8.3 위젯 설정 Sheet (shadcn `sheet`)

우측에서 밀려 들어오고, 뒤의 카드가 **실시간으로 미리보기**를 갱신한다.

```
┌ 위젯 설정 ────────────────────┐
│ 제목  [열린 인시던트        ]  │  비우면 자동 생성
├───────────────────────────────┤
│ 데이터                         │
│   대상   [인시던트        ▾]  │  ← entity
│   측정   [개수            ▾]  │  ← measure
│   쪼개기 [클러스터별      ▾]  │  ← breakdown
├───────────────────────────────┤
│ 필터                           │
│   [클러스터 ▾][네임스페이스 ▾] │  ← VP-010 문법 그대로
│   [애플리케이션 ▾][Labels (2)] │
│   심각도 [critical ✕][high ✕] │  ← 엔티티별 축
│   ⚠ 쪼개기가 의미 없습니다 —   │  ← §4 규칙 3
│      필터가 클러스터 1개입니다 │
│      [쪼개기 해제]             │
├───────────────────────────────┤
│ 시간   [24시간 ▾]              │  시간축 없으면 이 절 자체가 없음
├───────────────────────────────┤
│ 표현   [가로막대][도넛][트리맵][표] │  ← ToggleGroup, 유효한 것만
├───────────────────────────────┤
│ 범위   ( ) 대시보드 필터 따름   │  ← inherit
│        (•) 이 위젯만 고정 📌   │  ← pinned
├───────────────────────────────┤
│ 크기   [작게][보통][크게]      │
└───────────────────────────────┘
```

사용 컴포넌트: `sheet`, `select`, `command`(필터 검색), `toggle-group`(표현·크기),
`radio-group`(범위), `badge`(칩), `alert`(경고), `separator`, `input`(제목).
**전부 shadcn primitive. 새 컴포넌트를 손으로 만들지 않는다** (VP-013).

### 8.4 저장

- 대시보드 편집: **`[완료]`에서만 PUT.** 조작마다 저장하지 않는다.
- 위젯 설정 Sheet: **닫을 때 대시보드 편집 상태에 반영**되고, 서버 저장은 여전히
  `[완료]` 시점.

## 9. Home과 필터의 관계

**Home에는 필터 바를 두지 않는다.** Home은 전체를 훑는 화면이다.

단, VP-010 공통 축(cluster/namespace/application/labels)이 URL에 있으면
`scope: inherit` 위젯들이 그것을 적용한다. 이때 Home 상단에 **읽기 전용 칩 줄**을
표시해 "지금 좁혀진 상태"임을 정직하게 알린다. 칩은 제거만 가능하고 추가는 불가능하다
(추가는 목록 화면에서). 필터가 0개면 칩 줄을 렌더하지 않는다.

## 10. 백엔드 계약 (신규)

| ID | 계약 | 규칙 |
|---|---|---|
| GAP-016 | `GET /dashboard/catalog` | §5. 엔티티·측정·쪼개기·필터축·표현·크기제약·프리셋의 **정본**. 프론트는 여기 없는 조합을 제시하지 않는다 |
| GAP-017 | `GET /settings/dashboard` | 사용자×workspace의 배치. 저장 전이면 **404가 아니라 기본 배치** 반환 |
| GAP-018 | `PUT /settings/dashboard` | 저장. 아래 검증 필수 |
| GAP-019 | `POST /dashboard/query` | 위젯 스펙 → 결과. 여러 위젯을 **배치로** 질의 가능해야 한다 |

### 10.1 `PUT /settings/dashboard` — 서버 검증 (전부 필수)

```json
{ "order": ["w_7f3a","w_9c11"], "widgets": { "w_7f3a": { ...위젯 스펙... } }, "revision": 3 }
```
- 모든 위젯 스펙이 **카탈로그에 대해 유효**해야 한다. 카탈로그에 없는
  엔티티/측정/쪼개기/표현/필터축 → **400**. 클라이언트가 임의 조합을 저장하게 두지 않는다.
- `view`가 해당 형태의 허용 목록에 없으면 400. `size`가 `{4,6,12}` 밖이면 400.
- `size_view_limits` 위반 400.
- `order`와 `widgets` 키가 정확히 일치 (고아·중복 400).
- **workspace 격리**: `workspace_id`를 통과시켜 다른 workspace의 배치를 읽거나 쓸 수
  없다 (BOLA 방지).
- `revision` 낙관적 동시성. 불일치 시 **409 + 현재 값** 반환.

### 10.2 `POST /dashboard/query` — 결과 형태를 서버가 선언

```json
// 요청
{ "widgets": [ { "id":"w_7f3a", "entity":"incidents", "measure":"count",
                 "breakdown":"cluster", "filter":{...}, "time":{"range":"24h"} } ],
  "dashboard_filter": { "clusters":["c1"], "labels":["team=checkout"] } }

// 응답
{ "results": [
    { "id":"w_7f3a",
      "shape":"categorical",
      "data":[ {"key":"prod-eks","label":"prod-eks","value":5},
               {"key":"staging-gke","label":"staging-gke","value":2} ],
      "completeness":"complete",     // complete | partial | unavailable
      "total": 7,
      "scope_empty": false           // 필터 교집합이 공집합인가 (§4 규칙 4)
    } ] }
```

**필수 규칙:**
- `shape`를 **서버가 선언**한다. 프론트가 데이터 모양을 보고 추측하지 않는다.
- `completeness`가 `partial`/`unavailable`이면 프론트는 숫자를 만들지 않고 그 상태를
  표시한다.
- **`scope_empty: true`와 `value: 0`은 다른 사실이다.** 서버가 구분해 준다.
- 시계열의 데이터 없는 구간은 **명시적 `gap`**으로 표시한다. 보간 금지 (VP-012와 동일).
- 배치 질의는 **위젯 하나가 실패해도 나머지는 반환**한다. 실패한 위젯은 그 항목에
  에러를 담는다 (전체 500 금지).
- `dashboard_filter`와 위젯 `filter`의 교집합 연산은 **서버가 수행**한다. 프론트가
  두 필터를 합성해 보내지 않는다 — 합성 규칙이 두 곳에 존재하면 반드시 어긋난다.

## 11. 구현 순서

1. **VP-013 S0~S2 착륙 대기.** 그 전에는 시작하지 않는다.
2. **GAP-016 카탈로그 착륙 후** 설정 Sheet를 만든다. 카탈로그 없이 축 목록을
   하드코딩하지 않는다.
3. 정적 Home — 기본 프리셋 렌더 (GAP-019로 데이터 조회). 목업 데이터 금지.
4. 대시보드 편집 모드 — `Reorder` + 카드 메뉴 + 프리셋 갤러리. 저장은 로컬 상태.
5. 위젯 설정 Sheet — 8개 축 + 모순 방지 규칙(§4) 전부.
6. **GAP-017/018 착륙 후** 저장·복원 배선.
7. 필터 칩 줄 (VP-010 URL 상태 소비).

## 12. 금지 사항

- 자유 좌표 드래그를 만들지 않는다 (순서 기반이 확정안).
- iOS식 지속 흔들림을 넣지 않는다.
- `[취소]` 버튼을 만들지 않는다.
- **축 목록·표현 목록·프리셋을 프론트에 하드코딩하지 않는다.** 서버 카탈로그가 정본.
- **유효하지 않은 표현을 disabled로 보여주지 않는다.** 아예 렌더하지 않는다.
- `scope_empty`를 0으로 렌더하지 않는다.
- 데이터 값에 카운트업 애니메이션을 넣지 않는다.
- 위젯 카드·설정 UI를 직접 만든 컴포넌트로 짓지 않는다 — shadcn primitive 조합만.
- 편집 상태를 매 조작마다 서버에 저장하지 않는다.
- 대시보드 필터와 위젯 필터를 프론트에서 합성해 보내지 않는다.
