# VP-020 — 알림

데모③의 서사: **"CPU가 일정 수준을 넘으면 알려줘"를 AI 채팅으로 걸고, 관객 부하로 실제로 울린다.**
이 장면이 우리 제품의 차별점(AI가 운영을 **대신 한다**)을 4분 안에 증명하는 유일한 지점이다.

---

## 0. 불변식의 경계 — 이걸 안 그으면 반드시 헤맨다 ★

> **클러스터의 상태를 바꾸면 → Git → 웹훅 → 에이전트** (단일 writer. 변함없다)
> **Opsia 자신의 설정을 바꾸면 → Opsia DB에 직접** (Git 안 간다)

| 무엇 | 어디로 | 왜 |
|---|---|---|
| Deployment · Service · ConfigMap … | **Git** | 클러스터의 상태다 |
| 클러스터 안의 **`PrometheusRule` CRD** | **Git** | ★ **이것도 클러스터 리소스다.** 함정 |
| **Opsia 알림 규칙** | **Opsia DB** | Opsia가 소유하고 Opsia가 평가한다. 클러스터 리소스가 아니다 |
| 위젯 · 워크스페이스 · 채널 · 정책 | **Opsia DB** | 같은 이유 |

**알림 규칙은 Git을 거치지 않는다. 그래서 데모에서 30초 안에 걸 수 있다.**
그리고 그것이 불변식을 깨지 않는다 — **클러스터를 건드리는 게 아니기 때문이다.**

**`/webhooks/alertmanager`(이미 있다)는 외부에서 들어오는 알림 수신구다.**
우리 규칙과 병존한다. 들어온 것도 "알림 발생"으로 같은 목록에 쌓이고, `source` 만 다르다.

---

## 1. 개념 셋 — 중복이 아니다. 섞지 마라

```
알림 규칙 (Alert Rule)    내가 미리 건 감시 조건            ← 사전
알림 발생 (Alert Event)   조건이 충족돼 울린 것              ← 사건
인시던트 (Incident)       "장애다"라고 판단된 것. RCA 대상    ← 진단
```

**알림이 울린다고 전부 장애는 아니다.**
→ 알림 발생 카드의 **`[인시던트로 승격]`** 버튼이 둘을 잇는 다리다. (수동. 자동 승격은 나중에)

---

## 2. 지금 있는 것 / 없는 것 (실측)

| | 상태 |
|---|---|
| `/alert-channels` · `/alert-channels/test` · `/alert-channels/{id}` | **있다.** 어디로 보낼지(슬랙·이메일) |
| `/webhooks/alertmanager` | **있다.** 외부 알림 수신구 |
| `/rca/rules` · `/rca/rules/validate` | **있다.** RCA **진단** 규칙. 알림 규칙이 아니다 |
| **알림 규칙(임계값 조건) API** | **없다** ← BQ-083~087 신설 |
| **알림 화면** | **없다** |
| **AI 액션 계약** | **없다.** AI는 지금 읽기 전용이다 ← BQ-088 신설 |

**채널은 있는데 규칙이 없다. 새로 만들지 말고 채널은 그대로 쓴다.**

## 3. 백엔드 계약

### BQ-083 · `POST /alert-rules`
```
{ name,
  scope: { clusters[], namespaces[], applications[], labels[] },   ← ★ 1층 필터와 같은 canonical 형식
  metric: "cpu_pct" | "mem_pct" | "restart_count" | "pod_not_ready",
  comparator: ">" | ">=" | "<" | "<=",
  threshold: number,
  for_seconds: number,        ← ★ "N초 이상 지속될 때만". 플래핑 방지. 필수다
  severity: "critical" | "high" | "medium" | "low",
  channels: [channel_id],     ← 기존 /alert-channels 재사용
  enabled: bool }
→ { rule_id }
```
**`scope` 는 1층 검색과 같은 형식을 쓴다. 새 필터 문법을 만들지 마라.**

### BQ-084 · 규칙 관리
```
GET    /alert-rules          목록 (마지막 발생 시각 · 발생 횟수 포함)
PATCH  /alert-rules/{id}     수정 · 활성/비활성
DELETE /alert-rules/{id}
```

### BQ-085 · `GET /alert-events?from=&to=&rule_id=&severity=&status=`
```
[{ event_id, rule_id, rule_name,
   source: "opsia" | "alertmanager",
   fired_at, resolved_at?,
   status: "firing" | "resolved" | "acked",
   subject: { cluster, namespace, kind, name },
   observed_value, threshold,
   evidence: [...],          ← ★ 근거 없이 알림을 만들지 않는다
   incident_id? }]           ← 승격됐으면 연결
```

### BQ-086 · 발생 처리
```
POST /alert-events/{id}/ack
POST /alert-events/{id}/promote-incident   → { incident_id }
```

### BQ-087 · `SSE /alert-events/stream`
실시간. 울리면 즉시 화면에 뜬다.

### BQ-088 · `POST /ai/actions/propose` ★
```
→ { action: "create_alert_rule",
    payload: <BQ-083의 body>,
    rationale,
    evidence: [...] }
```
**AI는 제안만 한다. 실행 엔드포인트가 아니다.** (§5)

### 3.1 평가 엔진 규칙

- Opsia가 메트릭을 주기적으로 평가한다 (5~15초)
- **`for_seconds` 를 반드시 지킨다.** 한 번 튀었다고 울리면 **아무도 안 믿는다**
- 같은 규칙·같은 대상은 **중복 발생시키지 않는다** (firing 중이면 갱신만)
- **해소되면 `resolved` 로 바꾸고 해소 알림도 보낸다.**
  울리기만 하고 안 꺼지면 신뢰를 잃는다

## 4. 화면 — 사이드바에 **`알림`** 메뉴 신설

```
홈 → 클러스터 → 리소스 → 인시던트 → 알림 → 애플리케이션 → GitOps ─── 설정
```

**1층 검색은 다른 화면과 같은 자리에 있다.** 골격(VP-015 §2)은 지켜진다.

### [발생] — 기본 탭. 데모에서 여기가 열린다

- 울린 알림이 최신순. **SSE로 실시간으로 위에 쌓인다**
- 카드: 심각도 · 규칙 이름 · 대상(클러스터/네임스페이스/리소스) ·
  **관측값 vs 임계값** · 울린 시각 · 지속 시간 · 출처
- 액션: `[확인]` `[인시던트로 승격]` `[리소스 보기 →]`(`?detail=` 로 상세를 연다)
- **해소된 것은 회색으로 남는다. 사라지지 않는다** — 사라지면 뭐가 있었는지 모른다
- 심각도 · 상태(firing/resolved/acked) 필터 칩

### [규칙]

- 목록: 이름 · 범위(칩으로) · 조건 · 지속 · 채널 · 마지막 발생 · 발생 횟수 · 켜기/끄기
- `＋ 규칙 추가` → 다이얼로그.
  **범위는 1층 검색과 같은 태그 칩 UI를 쓴다. 새로 만들지 마라**
- 규칙 행 클릭 → 그 규칙의 발생만 필터된 [발생] 탭으로

### [채널]

- **기존 `/alert-channels` 를 그대로 붙인다. 새로 만들지 마라. 이미 있다**
- 슬랙/이메일 등 · `[테스트 발송]`(`/alert-channels/test` 도 이미 있다)

### 전역

- 사이드바 `알림` 메뉴에 **미확인 발생 수 배지**
- 새 알림 → **sonner 토스트**(이미 도입됨). 클릭 → 그 알림으로

## 5. AI가 알림을 건다 ★ 데모의 결정적 장면

> **AI는 제안한다. 실행은 사람이 한 번 누른다.**

지금까지 AI는 **근거 없으면 답도 안 하는 읽기 전용**이었다. 그 규율을 깨지 마라.
**조용히 실행하는 경로를 만들지 마라.**

```
사용자: "이 클러스터에서 파드 CPU가 80% 넘으면 알려줘"
   ↓
AI 응답 안에 액션 카드가 붙는다 (BQ-088)

┌────────────────────────────────────────────┐
│ 알림 규칙을 만들까요?                       │
│                                            │
│  이름   파드 CPU 과부하                      │
│  범위   [클러스터: prod-eks]                 │  ← 지금 화면의 필터에서 가져온다
│  조건   CPU 사용률 > 80%                     │
│  지속   2분 이상                             │  ← AI가 기본값을 제안 (플래핑 방지)
│  심각도 높음                                 │
│  채널   #ops-alerts                          │  ← 기존 채널에서 고른다
│                                            │
│           [수정]        [알림 만들기]        │
└────────────────────────────────────────────┘
   ↓ 사용자가 [알림 만들기]
POST /alert-rules → 토스트 "알림 규칙을 만들었습니다  [규칙 보기 →]"
```

| 규칙 | 내용 |
|---|---|
| **범위** | **지금 화면의 필터 맥락에서 가져온다.** AI가 "이 클러스터"를 추측하지 않는다 |
| **`for_seconds`** | **AI가 기본값을 반드시 제안한다.** 이걸 빼면 알림이 튄다 |
| **`[수정]`** | 규칙 다이얼로그가 **값이 채워진 채로** 열린다. 사용자가 고칠 수 있다 |
| **권한** | capability 없으면 **액션 카드를 렌더하지 않는다** (disabled 금지. 기존 규율) |
| **감사** | 실행하면 원장에 남는다: 누가 · 언제 · **AI 제안으로** · 무엇을 |
| **화이트리스트** | AI가 만들 수 있는 액션은 **`create_alert_rule` 하나뿐이다.**
임의의 클러스터 변경을 액션 카드로 만들지 마라 — 그건 GitOps 파이프라인이다 |

## 6. 선행 조건 — 이게 없으면 데모③이 성립하지 않는다

1. **실시간(VP-018 §7)이 먼저다.** 파드 CPU가 실시간으로 오르는 게 안 보이면
   "부하가 걸리고 있다"를 증명할 수 없다. 알림만 울려봐야 소용없다.
2. **파드 채움색(VP-015 §4.2)이 먼저다.** 부하가 오르면 **파드가 빨개지는 게 보여야** 한다.
   지금은 전부 똑같은 톱니바퀴 아이콘이다.
3. 알림에서 **그 파드로 바로 갈 수 있어야** 한다 (`?detail=`).

## 7. 데모③ 동선 (이대로 동작해야 한다)

```
1. AI 채팅: "prod-eks에서 파드 CPU 80% 넘으면 알려줘" → 액션 카드 → [알림 만들기]
2. 관객이 QR로 게임 접속 → 부하
3. 물리 뷰에서 파드가 실시간으로 빨개진다 (SSE)
4. 지속 조건 충족 → 알림이 울린다 → 토스트 + 사이드바 배지 + 슬랙
5. 알림 클릭 → 그 파드 상세가 열린다
6. [인시던트로 승격] → RCA로 이어진다
```

**4번에서 2분을 기다릴 수 없다.** 데모에서는 `for_seconds` 를 **20초**로 건다.
(규칙 자체는 사용자가 정한다. 데모에서 짧게 거는 것뿐이다)

## 8. 금지

- 알림 규칙을 **Git으로 보내는 것** (클러스터 리소스가 아니다)
- 클러스터의 `PrometheusRule` 을 **우리 알림 규칙과 같은 목록에 섞는 것**
- **AI가 확인 없이 실행하는 것**
- `for_seconds` 없이 즉시 울리는 규칙 (플래핑 → 아무도 안 믿는다)
- 해소된 알림을 **목록에서 지우는 것** (회색으로 남긴다)
- **근거 없는 알림** (`evidence` 필수)
- 계약이 없는데 화면을 그리는 것 (BE-Gap)
- 알림 범위에 **새 필터 문법을 만드는 것** (1층 검색과 같은 canonical 형식)
