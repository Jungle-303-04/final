# Maintainers (Publication Draft)

> No public maintainer identities are designated by this draft. Human owners must obtain consent,
> select public handles, approve roles, and publish the initial roster before repository publication.

## Required initial coverage

The public roster should identify accountable people for each responsibility:

| Responsibility | Minimum coverage | Publication requirement |
| --- | ---: | --- |
| Repository administration | 2 | Protected branches, recovery access, and least privilege tested |
| Release and supply chain | 2 | Signed release, artifact, SBOM, and provenance workflow tested |
| Security response | 2 | Private reporting and conflict-free escalation tested |
| RCA and evidence contracts | 2 | Catalog and evidence compatibility review defined |
| Remediation and policy safety | 2 | Approval, blast-radius, rollback, and harmful-action review defined |
| KubeHealBench | 2 | Scenario ground-truth and metric review defined |
| Community conduct | 2 | Confidential conduct reporting and appeal path configured |

One person may cover multiple areas, but no critical credential or emergency action should depend on a
single person.

## Roster format after approval

Publish only information each maintainer has consented to make public:

- public handle;
- role and review areas;
- start date;
- active, inactive, or emeritus status; and
- conflict disclosures relevant to project decisions.

Do not publish personal contact details. Security and conduct reports must use dedicated private
channels, not an individual's inbox.

## Expectations

Maintainers review changes promptly, document safety decisions, disclose conflicts, protect embargoed
reports, keep release access secure, mentor reviewers, and step back when they cannot participate.
Authority should be reevaluated on a published cadence after governance is adopted.

## Bootstrap decision

Before publication, human owners must approve the roster, role thresholds, nomination and removal
process, inactivity period, CODEOWNERS mapping, and emergency access recovery. Until then this file is a
staffing checklist, not proof that maintainers have accepted responsibility.
