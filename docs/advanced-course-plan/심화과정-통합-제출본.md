# 크래프톤 심화과정 프로젝트 계획서

**교육생: 최우녕**

## 목표

3개월 뒤에는 Python과 Kubernetes 중심으로 쌓은 운영 시스템 경험을
Java/Spring 기반의 백엔드·플랫폼 설계 역량으로 전환하고자 합니다.

- 기존 프로젝트의 핵심 기능을 Java/Spring Boot로 포팅하며 언어와 프레임워크의
  차이를 이해합니다.
- 트랜잭션, 도메인 이벤트, outbox, 재시도와 멱등성을 설명하고 구현합니다.
- 네 명 모두가 같은 아키텍처를 설명하고 서로의 모듈을 디버깅할 수 있도록
  공통 설계와 검증 기준을 만듭니다.
- 개발 중 흩어지는 문서·프롬프트·코드 조각·명령어·의사결정 기록을 한곳에서
  다시 찾고 재사용하는 개발자 도구를 직접 사용하고 오픈소스로 공개합니다.
- 프로젝트 완료 후 플랫폼·Java 백엔드·DevOps 직무에 지원할 수 있는 이력서와
  포트폴리오를 완성합니다.

## 기존 경험과 보완 방향

기존 Opsia 프로젝트에서 Kubernetes evidence 수집, 장애 원인 분석(RCA),
GitOps 기반 Safe PR, 실시간 전송, 배포와 복구 검증을 경험했습니다. 이벤트
계약, outbox, 처리 ledger, retry와 dead letter 구조를 실제 운영 흐름에
적용한 것이 강점입니다.

이번 과정에서는 많은 서비스를 추가하기보다 Java/Spring 환경에서 명확한
모듈 경계와 트랜잭션을 설계하고, 로컬 데이터와 선택형 클라우드
동기화·호스팅을 배포·관측·복원할 수 있는 작은 플랫폼으로 완성하는 데
집중합니다.

## 프로젝트 후보안과 시장성 검토

현재 후보안은 범용 노트 앱이 아니라 **개발자의 작업 지식을 재사용 가능한
자산으로 만드는 로컬 우선 오픈소스 도구**입니다. 설계 문서, 프롬프트,
코드 조각, 명령어, 오류 해결 기록, ADR과 링크를 프로젝트 맥락·출처·버전과
함께 저장하고, 전문 검색·RAG·MCP를 통해 IDE와 AI 도구에서 다시 사용합니다.

Obsidian·Logseq·Anytype 같은 범용 지식 도구, Gisto·KlipCode 같은 코드 조각
관리 도구, Knowit 같은 AI agent memory 도구가 이미 있어 단순한
`마크다운+검색+동기화`만으로는 차별화가 어렵습니다. 따라서 다음을 제품
가설로 둡니다.

- 1차 사용자: 네 명의 팀원과 문서·프롬프트·코드가 여러 저장소와 AI 대화에
  흩어져 반복 탐색하는 개인 개발자
- 핵심 가치: 30초 안에 기록하고, 프로젝트·출처·버전을 보존하며, IDE나 AI
  agent에서 근거와 함께 다시 찾고 안전하게 갱신
- 로컬 기본값: 가입 없이 SQLite와 plain Markdown으로 즉시 사용
- 선택형 클라우드: 계정 기반 증분 동기화·백업, 여러 기기 접근, 선택한
  문서의 읽기 전용 호스팅, Docker 기반 self-hosting
- 차별화 후보: 문서·프롬프트·코드를 같은 schema로 연결하고, RAG citation,
  MCP 도구별 권한, 쓰기 전 승인과 감사 이력 제공

1주 차에는 개발자 10명 이상(팀 외부 5명 이상)을 인터뷰하고 기존 도구로
같은 작업을 수행해 전환 비용과 빈틈을 기록합니다. `문제 반복성 30%,
기존 대안의 불편 20%, 팀의 일일 사용 가능성 20%, 외부 pilot 의사 15%,
3개월 구현 가능성 15%`로 후보를 평가합니다. 70점 이상이고 외부 pilot
의사 5명 이상을 확보했을 때 진행하며, 미달이면 가장 점수가 높은 인접
문제로 전환합니다.

제품명과 범위는 확정안이 아닙니다. 8월 23일까지 문제 인터뷰와 경쟁 제품
대체 실험을 수행해 반복되는 문제가 확인되지 않거나 팀이 매일 쓰지 않으면
기능을 축소하거나 인접한 개발자 도구 주제로 변경합니다. 이때 Java 포팅,
공동 아키텍처 학습, 오픈소스 공개라는 과정 목표는 유지합니다.

## 성공 기준

- 팀원이 10분 안에 로컬 demo를 실행할 수 있습니다.
- 팀원이 실제 개발 자료를 4주 이상 dogfooding하고 1인당 30개 이상의
  artifact와 20회 이상의 검색·재사용 기록을 남깁니다.
- 외부 개발자 10명 이상이 설치 또는 hosted demo를 사용하고, 그중 5명
  이상이 다음 주에도 다시 사용하거나 자신의 자료를 추가합니다.
- 두 기기 간 증분 동기화, 선택 문서 hosting과 새 환경 backup restore가
  재현 가능한 테스트를 통과합니다.
- 같은 동기화 요청을 재전송해도 중복 revision이 생기지 않습니다.
- transaction과 outbox의 원자성이 실 DB 통합 테스트로 검증됩니다.
- 핵심 요청·동기화·검색·AI 흐름을 trace로 추적할 수 있습니다.
- backup을 새 환경에 복원하는 drill을 통과합니다.
- 주 담당자가 아닌 팀원도 플랫폼 모듈을 실행하고 설명할 수 있습니다.

# 크래프톤 심화과정 프로젝트 계획서

**교육생: 이민정**

## 목표

3개월 뒤에는 팀장으로서 기능을 나누는 데 그치지 않고, 사용자 흐름과
아키텍처·API 계약을 연결해 네 명의 결과물을 하나의 제품으로 완성할 수 있는
개발자가 되고자 합니다.

- 기존 프로젝트의 핵심 기능을 Java/Spring Boot로 포팅하며 서버 구조와
  클라이언트 계약을 함께 이해합니다.
- React·Tauri에서 편집, 자동 저장, 오프라인, 동기화 충돌 상태를 예측
  가능하게 관리합니다.
- 팀원이 같은 목표·용어·Definition of Done을 공유하도록 설계와 의사결정을
  기록합니다.
- 개발 중 흩어지는 문서·프롬프트·코드 조각·명령어·의사결정 기록을
  빠르게 모으고 다시 쓰는 개발자 도구를 팀의 실제 작업에 적용하고
  오픈소스로 공개합니다.
- 프로젝트와 팀 리딩 경험을 Java 백엔드·풀스택 직무의 이력서와
  포트폴리오로 완성합니다.

## 기존 경험과 보완 방향

기존 Opsia 프로젝트에서 Kubernetes metadata와 evidence,
Prometheus·Loki·Tempo, 내부 MCP의 권한·필터 경계, inventory API,
React 화면과 상태 흐름을 구현했습니다. 백엔드와 프론트 사이의 계약 문제를
실제 기능으로 연결한 것이 강점입니다.

이번 과정에서는 기능 수보다 사용자 흐름, 실패 상태, API contract, E2E
검증을 먼저 정의하고, 팀 전체가 같은 우선순위와 아키텍처로 움직이게 하는
제품 통합 역량을 보완합니다.

## 프로젝트 후보안과 시장성 검토

현재 후보안은 범용 노트 앱이 아니라 **개발자의 작업 지식을 재사용 가능한
자산으로 만드는 로컬 우선 오픈소스 도구**입니다. 설계 문서, 프롬프트,
코드 조각, 명령어, 오류 해결 기록, ADR과 링크를 프로젝트 맥락·출처·버전과
함께 저장하고, 전문 검색·RAG·MCP를 통해 IDE와 AI 도구에서 다시 사용합니다.

Obsidian·Logseq·Anytype 같은 범용 지식 도구, Gisto·KlipCode 같은 코드 조각
관리 도구, Knowit 같은 AI agent memory 도구가 이미 있어 단순한
`마크다운+검색+동기화`만으로는 차별화가 어렵습니다. 따라서 다음을 제품
가설로 둡니다.

- 1차 사용자: 네 명의 팀원과 문서·프롬프트·코드가 여러 저장소와 AI 대화에
  흩어져 반복 탐색하는 개인 개발자
- 핵심 가치: 30초 안에 기록하고, 프로젝트·출처·버전을 보존하며, IDE나 AI
  agent에서 근거와 함께 다시 찾고 안전하게 갱신
- 로컬 기본값: 가입 없이 SQLite와 plain Markdown으로 즉시 사용
- 선택형 클라우드: 계정 기반 증분 동기화·백업, 여러 기기 접근, 선택한
  문서의 읽기 전용 호스팅, Docker 기반 self-hosting
- 차별화 후보: 문서·프롬프트·코드를 같은 schema로 연결하고, RAG citation,
  MCP 도구별 권한, 쓰기 전 승인과 감사 이력 제공

1주 차에는 개발자 10명 이상(팀 외부 5명 이상)을 인터뷰하고 기존 도구로
같은 작업을 수행해 전환 비용과 빈틈을 기록합니다. `문제 반복성 30%,
기존 대안의 불편 20%, 팀의 일일 사용 가능성 20%, 외부 pilot 의사 15%,
3개월 구현 가능성 15%`로 후보를 평가합니다. 70점 이상이고 외부 pilot
의사 5명 이상을 확보했을 때 진행하며, 미달이면 가장 점수가 높은 인접
문제로 전환합니다.

제품명과 범위는 확정안이 아닙니다. 8월 23일까지 문제 인터뷰와 경쟁 제품
대체 실험을 수행해 반복되는 문제가 확인되지 않거나 팀이 매일 쓰지 않으면
기능을 축소하거나 인접한 개발자 도구 주제로 변경합니다. 이때 Java 포팅,
공동 아키텍처 학습, 오픈소스 공개라는 과정 목표는 유지합니다.

## 성공 기준

- 네트워크 없이 개발 artifact를 작성·조회·검색할 수 있습니다.
- 자동 저장 실패, 동기화 충돌, 권한 거절이 사용자에게 명확히 표시됩니다.
- Java API와 클라이언트 contract가 CI에서 함께 검증됩니다.
- 편집→저장→재시작→동기화→검색의 E2E가 통과합니다.
- 팀원이 4주 이상 실제 개발에 사용하며 1인당 30개 이상의 artifact와
  20회 이상의 검색·재사용 기록을 남깁니다.
- 외부 개발자 10명 이상이 설치 또는 hosted demo를 사용하고, 5명 이상이
  다음 주에도 다시 사용하거나 자신의 자료를 추가합니다.
- 두 기기 간 동기화와 선택 문서 hosting을 포함한 사용자 E2E가 통과합니다.
- 주 담당자가 아닌 팀원도 클라이언트 상태 흐름을 설명할 수 있습니다.

## 기존 계획과 보완 방향

## 프로젝트 후보안과 시장성 검토

현재 후보안은 범용 노트 앱이 아니라 **개발자의 작업 지식을 재사용 가능한

함께 저장하고, 전문 검색·RAG·MCP를 통해 IDE와 AI 도구에서 다시 사용합니다.

Obsidian·Logseq·Anytype 같은 범용 지식 도구, Gisto·KlipCode 같은 코드 조각
관리 도구, Knowit 같은 AI agent memory 도구가 이미 있어 단순한
`마크다운+검색+동기화`만으로는 차별화가 어렵습니다. 따라서 다음을 제품

같은 작업을 수행해 전환 비용과 빈틈을 기록합니다. `문제 반복성 30%,
기존 대안의 불편 20%, 팀의 일일 사용 가능성 20%, 외부 pilot 의사 15%,
3개월 구현 가능성 15%`로 후보를 평가합니다. 70점 이상이고 외부 pilot
의사 5명 이상을 확보했을 때 진행하며, 미달이면 가장 점수가 높은 인접
문제로 전환합니다.

제품명과 범위는 확정안이 아닙니다. 8월 23일까지 문제 인터뷰와 경쟁 제품
대체 실험을 수행해 반복되는 문제가 확인되지 않거나 팀이 매일 쓰지 않으면
기능을 축소하거나 인접한 개발자 도구 주제로 변경합니다. 이때 Java 포팅,

## 성공 기준

- 권한 없는 사용자의 artifact가 API, 검색, RAG, MCP 결과에 포함되지 않습니다.
- 같은 동기화 요청을 재전송해도 중복 revision이 생기지 않습니다.
- 동시 수정은 숨겨진 덮어쓰기가 아니라 명시적 충돌 상태로 처리됩니다.
- MCP 쓰기 작업은 사용자 승인과 감사 이력 없이 실행되지 않습니다.
- secret과 PII가 API 응답, log, trace, audit에 원문으로 남지 않습니다.
- 권한·중복·동시성·복원 시나리오가 Testcontainers 통합 테스트를 통과합니다.
- 팀원이 4주 이상 실제 개발에 사용하며 1인당 30개 이상의 artifact와
  20회 이상의 검색·재사용 기록을 남깁니다.
- 외부 개발자 10명 이상이 설치 또는 hosted demo를 사용하고, 5명 이상이
  다음 주에도 다시 사용하거나 자신의 자료를 추가합니다.
