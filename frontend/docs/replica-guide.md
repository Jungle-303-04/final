# Plural 복제 UI 가이드

두 앱이 무엇을 보여주고, 실제로는 무엇을 하는 화면인지, 복제본에서 어떻게 눌러보는지 정리한 문서.

- **/plural** — app.plural.sh 복제. "계정·구독 관리" 앱. 콘솔 인스턴스를 만들고 팀/결제를 관리하는 곳.
- **/console** — Plural Console 복제. "클러스터 운영" 앱. 실제 운영자가 하루 종일 보는 화면.
- 모든 데이터는 mock이지만 시나리오("dashboard-worker OOM 장애")로 서로 연결되어 있다.

---

## /plural (앱 관리)

| 메뉴 | 보여주는 것 | 실제로 하는 일 | 복제본에서 눌러볼 것 |
|---|---|---|---|
| Management planes | 내 콘솔 인스턴스 목록 (클라우드/자체 호스팅) | 관리 평면 생성·접속. "콘솔로 이동"이 인스턴스별 콘솔을 엶 | 인스턴스 생성 모달, 행 클릭 상세, **콘솔로 이동 → /console 연결** |
| Marketplace | 설치 가능한 OSS 앱 카탈로그 | `plural bundle install`로 클러스터에 앱 배포 | 카테고리 필터, 앱 카드 → 상세 탭 6개, 설치 모달 |
| Cloud shell | 브라우저 CLI | 로컬 설치 없이 plural CLI 실행 | 터미널 화면 |
| Audits | 계정 활동 기록 | 보안 감사·이상 로그인 추적 | 행 클릭 상세, 지역 분포 |
| Account | 사용자/그룹/역할/도메인/청구 | 조직 권한 관리(RBAC), DNS, 플랜 결제 | 초대·그룹 생성·역할 생성(권한 토글)·토큰 발급 모달, 삭제류는 확인 모달 |
| Profile | 내 프로필/보안/토큰/키 | 2FA, CLI 토큰, 암호화 키 백업 | 토큰 생성·폐기, 키 추가·삭제 |

## /console (클러스터 운영)

### 홈
- **보여주는 것**: 20개 클러스터의 건강 점수 히트맵 + 업그레이드 분포 + 클러스터 테이블.
- **실제 용도**: 출근해서 처음 보는 화면. "어디가 아픈가"를 10초 안에 파악.
- **사용법**: 히트맵 필터(모두/건강/보통/불량) → 빨간 셀 클릭 → 해당 클러스터 상세로 이동.

### 지속 배포 (CD) — 콘솔의 심장
- **보여주는 것**: 클러스터·서비스가 Git 정의와 일치하는지(GitOps 동기화 상태).
- **실제 용도**: "Git에 적힌 대로 클러스터가 돌아가게" 유지. 서비스가 '실패'면 Git과 실제가 어긋났다는 뜻.
- **사용법**:
  - 클러스터 행 클릭 → 우측 플라이오버 → "클러스터 상세로 이동"
  - 클러스터 상세 11개 탭: 서비스 / **메트릭**(기간 선택·차트 토글·차트 클릭 확대) / 상세(컨디션·용량) / 노드·팟(페이지네이션·NS 필터) / 네트워크(실시간 이벤트 피드) / 인사이트(AI 분석) / 알림(필터·음소거) / 업그레이드(사전 점검·호환성 매트릭스·PR 생성) / **로그**(실시간 스트리밍·레벨 필터·일시정지) / 애드온
  - 서비스 배포: 서비스 탭 → "서비스 배포" → 4단계 위저드(속성→저장소→Helm 값→시크릿)
  - 파이프라인: dev→staging→prod 승격 게이트. 행 클릭으로 스테이지 진행 확인.

### 스택 (Infrastructure-as-Code)
- **보여주는 것**: Terraform 실행 이력(plan diff `+3 ~1 -0`), state, 출력값, 변수.
- **실제 용도**: 인프라 변경을 로컬에서 terraform apply 하지 않고 콘솔이 대신 실행+기록. PR 머지가 트리거가 됨.
- **사용법**: 스택 생성 위저드(저장소→유형→변수) → 상세에서 "실행 트리거" → 실행 행 클릭 → plan diff 확인.

### 플로우
- **보여주는 것**: 관련 서비스·파이프라인·알림을 "제품 기능" 단위로 묶은 뷰.
- **실제 용도**: 마이크로서비스 수십 개 중 "결제 기능에 관련된 것만" 모아보기.

### 워크벤치 (AI 작업 공간)
- **보여주는 것**: 도구(kubectl, PromQL, GitHub, Slack)를 연결한 AI 에이전트 워크스페이스와 작업 이력.
- **실제 용도**: "이 장애 원인 조사하고 수정 PR 만들어줘"를 AI가 도구를 직접 써서 수행.
- **사용법**: 생성 위저드에서 도구 토글 선택. 우측 상단 "채팅" 버튼의 AI 패널에서 대화 → 확인 버튼으로 PR 생성 승인.

### 셀프 서비스
- **보여주는 것**: 카탈로그(개발자용 템플릿) + 대기 중 PR 큐 + PR 자동화 규칙.
- **실제 용도**: 개발자가 인프라팀 티켓 없이 DB를 셀프 프로비저닝. AI·자동화가 만든 PR을 사람이 최종 승인하는 관문.
- **사용법**: 대기 PR 행 클릭 → "승인 및 머지". (AI 채팅에서 만든 PR#128이 여기 떠 있음 — 시나리오 연결)

### 쿠버네티스 (리소스 브라우저)
- **보여주는 것**: kubectl로 보던 원시 리소스 전부 — 워크로드/네트워크/스토리지/구성/클러스터/RBAC.
- **실제 용도**: GitOps 밖의 실제 상태를 직접 확인·응급 수술하는 곳.
- **사용법**: 좌측에서 클러스터 선택(20개) → 리소스 종류 선택 → 행 클릭 → 정보/이벤트/**YAML 편집·적용** 탭 + **스케일/삭제** 버튼. 팟 1,000개는 50개씩 페이지네이션.

### Plural AI
- **보여주는 것**: 에이전트 실행 이력(단계·로그), 대화 스레드, 센티널(정기 점검), 인프라 리서치.
- **실제 용도**: RCA(근본 원인 분석) 자동화. 알림 → AI 분석 → 수정 PR까지의 파이프라인.
- **사용법**: 실행 행 클릭 → 4단계 진행 로그. 알림 탭에서 알림 클릭 → "AI 인사이트" 모달.

### 엣지 / 보안 / 비용 관리
- **엣지**: 매장·공장의 소형 디바이스 클러스터 원격 관리 + OS 이미지 배포.
- **보안**: 정책 위반(OPA), 이미지 취약점(실제 CVE ID), CIS 컴플라이언스 점수. 행 클릭 → CVE 목록·영향 리소스.
- **비용**: 클러스터별 CPU/메모리/스토리지 비용 분해 + 절감 추천. 카드 클릭 → 네임스페이스 분해.

### 설정
- **보여주는 것**: 전역(권한·저장소·관찰성·OIDC·SMTP), 사용자 관리(사용자/그룹/서비스 계정/페르소나), AI 설정, 프로젝트, 웹훅, 알림 라우팅, 감사 로그.
- **실제 용도**: 콘솔 자체의 동작을 구성. 페르소나는 역할별로 메뉴를 숨기는 기능.
- **사용법**: 각 행 클릭 → 상세 모달, 편집 버튼 → 편집 모달, 폼은 저장 → "저장됨 ✓". 생성 버튼들은 전부 위저드/폼 연결됨.

## 시나리오 따라가기 (추천 데모 경로)

1. `/plural` → 클러스터01 "콘솔로 이동" → 콘솔 헤더에 인스턴스 칩 표시
2. 홈 → 히트맵에서 빨간 **클러스터02(34)** 클릭
3. 알림 탭 → PodCrashLooping 클릭 → AI 인사이트(OOM 원인)
4. 메트릭 탭 → 실시간 출렁임 확인 → 24시간으로 전환(일간 파형)
5. 로그 탭 → ERROR 필터 → OOMKilled 라인 스트리밍
6. 우측 상단 채팅 → "PR 생성 확인" 클릭 → PR#128 생성
7. 셀프 서비스 → 대기 PR에서 PR#128 확인 → 승인
8. 업그레이드 탭 → 사전 점검 → "업그레이드 PR 생성" → PR#129
9. 설정 → 감사 로그 → 방금의 모든 행동이 기록된 것 확인
