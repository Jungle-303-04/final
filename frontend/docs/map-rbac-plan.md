## 0. 불변식 (모순 방지 계약)

| # | 불변식 | 막는 모순 |
|---|---|---|
| I1 | **단일 트리**: 한 시점에 하나의 그룹핑만 (서비스별 XOR 노드별 XOR 네임스페이스별) | 같은 팟의 이중 집계 |
| I2 | **크기=규모(느린 값), 색=상태(빠른 값)**. 레이아웃 재계산은 렌즈/그룹핑 변경 시에만 | 실시간 값으로 셀이 재배치되어 지도가 출렁임 |
| I3 | **상향 집계**: 모든 수치는 팟 레벨에서 생성 → 위로 합산. 비율은 가중평균(사용량합÷용량합) | 부모 34%인데 자식들 산수가 안 맞는 거짓 지도 |
| I4 | **레벨×탭 매트릭스** 밖의 탭은 렌더하지 않음 | 팟의 "업그레이드 탭" 같은 무의미 화면 |
| I5 | **유효 권한 = 역할(기능 축) ∩ 접근 바인딩(리소스 축)**. 읽기 없음=숨김, 쓰기 없음=비활성+사유 툴팁 | 권한 없는 버튼이 눌리거나, 이유 없이 사라짐 |
| I6 | **가시 범위 집계**: 모든 합계·히트맵은 뷰어가 읽을 수 있는 리소스만으로 계산 + "접근 가능 n/전체 N" 배지 | 셀은 15개인데 합계는 20개분인 불일치 |
| I7 | **참조 무결성 삭제 가드**: 참조되는 리소스는 삭제 불가(사유 표시) | 서비스가 쓰는 Git 저장소가 삭제되는 모순 |
| I8 | **목록 3종 세트**: 모든 목록 화면 = [생성] + [행 클릭 상세] + [행 액션(편집·제어·삭제)] | 보기만 되고 제어 불가한 반쪽 화면 |
| I9 | **위젯 스코프 주입**: 위젯 쿼리에는 현재 페이지 스코프 변수($cluster 등)가 자동 주입, 가시 범위 밖 데이터 조회 불가 | 팟 페이지에 플릿 전체 위젯이 뜨는 스코프 모순 |
| I10 | **URL이 상태의 진실**: 렌즈/그룹핑은 쿼리 파라미터(`?lens=cpu&group=node`) — 뒤로가기·공유 가능 | 새로고침하면 보던 지도가 사라짐 |
| I11 | **수집기 종속**: 메트릭은 해당 클러스터의 수집 파이프라인(에이전트→수집기→저장소)이 정상일 때만 존재. 비정상이면 값을 지어내지 않고 회색 "데이터 없음" 셀 + 집계 제외 + 배지 | 수집기 없는 클러스터에서 팟 CPU가 나오는 조작된 데이터 |
| I12 | **모션 토큰**: 모든 애니메이션은 중앙 모션 토큰(duration·easing)만 사용 — 고정값 사용 금지. `prefers-reduced-motion` 존중. 애니메이션은 상태의 결과만 연출(진실은 URL·상태, I10) | 화면마다 다른 손맛, 접근성 위반, 연출과 데이터 불일치 |

## 1. 히트맵 드릴다운 탐색 체계

### 1.1 레벨 구조 (히트맵은 각 페이지 상단의 "탐색 레이어")

```
L0 홈(플릿)          셀 = 클러스터 20개        셀 클릭 → 클러스터 상세
L1 클러스터 상세      셀 = 서비스|노드|NS (토글)  셀 클릭 → 서비스 상세 / 노드 상세(신설)
L2 서비스·노드 상세   셀 = 팟                   셀 클릭 → 팟 상세(신설)
L3 팟 상세           히트맵 없음(리프)          정보/이벤트/로그/YAML
```

- 기존 탭·테이블은 히트맵 **아래** 유지. 히트맵은 대체가 아니라 탐색 레이어.
- 신설 페이지 2개: **노드 상세**(현재 모달뿐), **팟 상세**(현재 모달뿐). 모달은 빠른 확인용으로 유지, "페이지로 열기" 버튼으로 연결.
- 브레드크럼이 트리 경로를 그대로 반영: `홈 / 클러스터02 / 노드별 / ip-10-0-8 / dashboard-worker-q9r4`

### 1.2 렌즈(상단 탭) — I2 적용

| 렌즈 | 크기 (5분 집계, 레이아웃) | 색 (라이브) | 셀 텍스트 | 정렬 |
|---|---|---|---|---|
| 전체 | 팟 수 | 건강 점수 (초록70+/노랑50+/빨강) | 이름 · 점수 | 건강 오름차순(아픈 것 먼저) |
| CPU | CPU 요청량(코어) | 사용률 % | 이름 · 71.2% | 사용률 내림차순 |
| 메모리 | 메모리 요청량 | 사용률 % | 이름 · 84.0% | 사용률 내림차순 |
| 비용 | 월 비용 | 전주 대비 증감 % (빨강=증가) | 이름 · $182 (+4%) | 비용 내림차순 |

- **범례 고정 표시**: 히트맵 우상단에 색 스케일 바 + 현재 렌즈의 의미("색 = CPU 사용률").
- 색만 라이브 티커 연결(60fps), 크기·배치는 고정.

### 1.3 레벨×탭 가용성 매트릭스 — I4

| 탭 | L0 플릿 | L1 클러스터 | L2 서비스/노드 | L3 팟 |
|---|---|---|---|---|
| 히트맵(다음 레벨) | ✅ | ✅ | ✅ | — (리프) |
| 메트릭 | ✅ 플릿 집계 | ✅ | ✅ | ✅ |
| 알림 | ✅ 전체 | ✅ | ✅ 해당 리소스만 | ✅ |
| 로그 | — (과다) | ✅ | ✅ | ✅ **원본** |
| 네트워크 | ✅ 요약 | ✅ | ✅ | ✅ 연결 목록 |
| 인사이트 | ✅ | ✅ | ✅ | — |
| 업그레이드 / 애드온 | ✅ 요약(분포) | ✅ **원본** | — | — |
| 이벤트 / YAML | — | — | ✅ | ✅ **원본** |

### 1.4 셀 라벨 가시성 규칙

- 셀 내부 텍스트는 **절대 줄바꿈·오버플로하지 않는다**.
- 셀이 임계 크기보다 작으면 단계적 생략: `이름+값` → `값만` → `숨김`. 숨겨진 정보는 **호버 툴팁**으로 제공 (finviz와 동일 문법).
- 임계값은 매직넘버가 아니라 토큰으로 관리 (`--map-label-min-w` 등), 셀 실측 기반으로 판정.

### 1.5 메트릭 가용성 모델 — I11

- 클러스터마다 `collector: { installed, healthy, lastScrape }` 상태를 가진다 (마켓플레이스의 Prometheus/Alloy 설치 세계관과 연동).
- 수집기 비정상 클러스터: 히트맵 셀 **회색 "데이터 없음"** + 렌즈 합계에서 제외 + "메트릭 없는 클러스터 1개" 배지 + 셀 클릭 시 "수집기 설치/복구" 안내.
- 시나리오: cluster17은 수집기 미설치, cluster09는 스크레이프 실패(마지막 수집 34분 전) — 조작된 값 대신 결측을 보여주는 것이 신뢰의 근거.

### 1.6 집계 규칙 — I3

- 팟 레벨에서 생성: `pod = { cpuReq, cpuUse, memReq, memUse, cost }` (시드 기반)
- 노드 = Σ(소속 팟) + 시스템 오버헤드(명시된 상수), 서비스 = Σ(소속 팟)
- 클러스터 = Σ(노드), 플릿 = Σ(가시 클러스터)
- 사용률 = Σ사용량 ÷ Σ용량 (단순평균 금지)
- 비용 = 팟 요청량 × 단가표(문서화된 상수) → 상향 합산. 현재 클러스터별 독립 생성 방식은 폐기.

## 2. 권한 기반 UI (RBAC 가시성)

### 2.1 뷰어 컨텍스트와 역할 시뮬레이터

- 세션의 현재 사용자는 `/auth/session` 응답의 `user_id`, `roles`, `workspace_id`를 기준으로 둔다.
- **역할 시뮬레이터**(프로필 메뉴 → "다른 역할로 보기"): 관리자(우녕) / sre(쓰기) / developers(읽기) / 신입(바인딩 없음) 4개 프리셋 전환. GitHub의 "View as"와 동일한 문법 — RBAC 동작을 시연 가능하게 만드는 장치.
- 유효 권한 계산 훅 `usePermission(resource)` → `{ canRead, canWrite, canCreate, reason }` (직접 > 프로젝트 > 전역, 기능 축은 역할에서).

### 2.2 가시성 3원칙 — I5

1. **canRead=false → 숨김**: 목록 행, 히트맵 셀, 검색 결과에서 제외. (존재 자체를 노출하지 않음)
2. **canRead=true, canWrite=false → 표시 + 변경 액션 비활성**: 버튼은 보이되 disabled + 툴팁 "쓰기 권한 필요 — 프로젝트 default의 sre 그룹에 요청". 숨기지 않는 이유: 사용자가 "왜 안 되는지"를 학습해야 함.
3. **canCreate**: 생성 버튼은 스코프(프로젝트/전역)의 생성 권한 기준. 없으면 비활성+사유.

예외: 파괴적 액션도 같은 규칙(비활성+사유). 단 **설정 메뉴 전체**(사용자 관리 등)는 역할에 관리 기능이 없으면 사이드바에서 숨김(기능 축이므로).

### 2.3 가시 범위 집계 — I6

- 플릿 히트맵: developers가 platform 프로젝트 읽기 없음 → logo-mgmt 셀 미표시, 플릿 합계도 19개 기준.
- 배지: "접근 가능한 19/20개 클러스터 표시 중" (ⓘ: 나머지는 platform 프로젝트 소속).

### 2.4 역할 시뮬레이터별 기대 화면 (검증 시나리오)

| 프리셋 | 보이는 것 | 달라지는 것 |
|---|---|---|
| 관리자 | 전부 | 전부 활성 |
| sre | 전 클러스터 | 설정>사용자 관리 숨김(기능), 나머지 쓰기 활성 |
| developers | default 프로젝트만 (mgmt 숨김) | 모든 쓰기 버튼 비활성+사유, 생성 비활성 |
| 신입(바인딩 없음) | 빈 목록 + "접근 권한이 없어요" 빈 상태 | 관리자에게 요청 안내 |

## 3. 인터랙션 완결성 — I7, I8

### 3.1 목록 3종 세트 감사 (스크린샷 지적 반영)

## 4. 위젯 = 쿼리 시스템 — I9

- **위젯 스키마**: `{ id, 제목, 폼(스탯|라인|게이지|바|도넛|테이블), 쿼리, 단위, 임계값(경고/위험), 스팬(1|2|3|4) }`
- **4열 그리드 배치** (아이폰 위젯·플로우 문법): 화면을 4등분, 위젯이 1~4칸을 차지. 폼별 허용 스팬 — 스탯·게이지·도넛=1, 바=2, 라인=2~4, 테이블=2~4. 좌→우 채움.
- **추가 플로우**: `[+ 위젯]` → ①폼 갤러리(미리보기 카드) → ②스코프·메트릭 선택(폼 빌더) 또는 고급 쿼리 → ③스팬 선택 → ④미리보기 → 추가. 편집·삭제는 위젯 호버 액션.
- 위젯도 I11 적용: 수집기 비정상 스코프의 위젯은 "데이터 없음" 상태 표시.
- **스코프 변수 자동 주입**: 페이지 컨텍스트에서 `$cluster / $group / $service / $node / $pod` 주입. 드릴다운하면 변수가 따라 바뀜. 위젯 카드에 현재 스코프 칩 표시.
- **편집 2단계**: 폼 빌더(메트릭 드롭다운 + 집계 선택 + 임계값) ↔ 고급(PromQL 직접 입력, render validate + command 결과 미리보기). 참고 모델: Grafana 패널/변수, Datadog Host Map.
- **프리셋**: 레벨별 기본 위젯 (플릿: 총 팟 수/평균 건강/월 총비용/활성 알림, 클러스터: CPU/메모리/재시작/p99 …)
- **배치**: 히트맵 아래 1~2줄, 추가(+카드)/삭제(호버 ✕)/편집(연필). 드래그 정렬은 후순위.
- **저장**: `localStorage(viewer+페이지레벨 키)` → 백엔드 연결 시 사용자 설정 API로 이관.
- **권한**: 위젯 편집은 개인 화면 설정이므로 읽기 사용자도 가능. 단 쿼리 결과는 가시 범위 데이터만(I6·I9).

## 5. 모션 사양 — I12

- **라이브러리**: `motion`(구 framer-motion). 선정 이유: `layoutId` 기반 shared-element 전환이 드릴다운 연출(셀 → 페이지로 확대되는 느낌)의 핵심.
- **모션 토큰** (`src/shared/motion`과 디자인 토큰 단일 출처, 고정값 사용 금지):
  - duration: `fast 0.12s / base 0.2s / slow 0.32s`
  - easing: `standard [0.4,0,0.2,1] / decelerate [0,0,0.2,1] / spring(부드러운 확대용)`
- **일관 문법**: 페이지 진입 = fade + 8px rise · 리스트/그리드 = 20ms stagger · 드릴다운 = 셀 `layoutId` 확대 전환 · 모달 = scale 0.98→1 · 값 변경 = 숫자 티커 · 히트맵 색 = crossfade (레이아웃은 I2에 따라 불변).
- `prefers-reduced-motion` 사용자는 전환 즉시 완료(duration 0).
