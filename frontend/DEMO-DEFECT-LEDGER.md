# 데모 대조 제품 결함 원장

기준 화면은 읽기 전용 `demo/motion-animations`의 `demo-freeze-v3`이다. 데모 브랜치는 수정하지 않되 겹치는 UI 소스는 제품 `dev`로 직접 이식하고 fixture·mock만 제품 토큰·i18n·권한·실 API 어댑터로 교체한다. 항목은 동일 후보 SHA의 자동 테스트, 라이브 화면, 숫자 교차 대조, 클릭 경로가 모두 일치할 때만 제거한다.

## 미해소

### D-1 · 배포 GitOps 정보·흐름 소실 · 블로커

- 관측: 라이브 `/deploy`의 저장소·동기화 탭에서 구 `/gitops`가 제공하던 저장소 목록, 연결 흐름, 애플리케이션별 동기화 상태가 보이지 않고 플랜 선택 빈 상태만 노출된다.
- 원칙: D19 병합은 정보와 동작의 소유권을 `/deploy`로 옮기는 것이며 삭제가 아니다.
- 완료 조건: 저장소 목록·연결 진입·연결 진행/완료·동기화 상태/health/revision/coverage가 `/deploy` 탭 안에서 실제 API로 표시되고, demo 대조·죽은 컨트롤 0·동일 SHA 라이브 증거를 남긴다.
- 상태: 로컬의 overview 바인딩과 authoritative reflection은 구현됐으나 전체 구 GitOps 정보 요소 복원과 라이브 검증 전이므로 미해소다.

### D-2 · 애플리케이션 빈 상태의 죽은 순환 참조 · 블로커

- 관측: 애플리케이션 탭의 `GitOps에서 애플리케이션 연결` 행동이 연결 흐름이 없는 화면으로 이동한다.
- 완료 조건: 행동이 `/deploy` 저장소·동기화 탭의 실제 연결 흐름을 열고, 연결 완료 뒤 애플리케이션 목록·동기화 상태에 한 사건으로 반영된다.
- 상태: 미해소. D-1과 같은 배포 서피스 배치에서 검증한다.

### D-3 · 서피스별 라이트/다크 혼재 · 블로커

- 관측: 라이브 서피스 사이에서 배경·카드·텍스트·상태색의 라이트/다크 문법이 섞인다.
- 기준: demo의 라이트 화면과 제품 단일 테마 토큰을 사용하며 서피스 로컬 색상·임의 그림자·리터럴 duration을 허용하지 않는다.
- 완료 조건: 홈부터 설정까지 8개 canonical 서피스를 같은 라이트 토큰으로 촬영하고 `check:design`, reduced-motion, 키보드 포커스와 3개 viewport를 통과한다.
- 상태: 미해소. 홈 → 배포 → 리소스 → 인시던트 → 타임라인 → 점검 → 비용 → 설정 순으로 소거한다.

### D-4 · 홈 데이터 미연결·3층 보드 부재 · 블로커

- 최초 관측: 이전 라이브 홈은 클러스터 지표가 모두 `—`이고 W2~W8 3층 보드가 없었다. `e84748b06`에는 보드가 생겼지만 1440 직접 대조에서 selected scope, 헤더/카드 숫자, 편집 tray와 차트 문법이 demo와 달랐다.
- 완료 조건: 선택 없음에서도 접근 가능한 전체 플릿을 bounded fan-out으로 집계하고, 헤더·클러스터 카드·W2~W8이 실제 API 수치 또는 정직한 부분 상태를 표시한다. 임계 칩 수는 `/resources?health=critical` 착지 행수와 같아야 한다.
- 상태: `b184fd49e`까지 라이브 반영했으나 2026-07-20 07:07 KST 사용자 대조에서 선택된 단일 클러스터 카드만 남고 보드에 큰 빈 공간이 발생했다. demo의 고정 grid·W2~W8 밀도와 다르므로 시각 불합격이며, demo 구조를 고정한 채 실데이터 view-model만 주입하도록 재구현 중이다.

### D-5 · 알림 독립 서피스 소실 · 블로커

- 관측: 제품 `/alerts`는 `/issues?section=rules`로 전환되어 규칙 빈 상태만 보인다. demo의 진행 중 알림 카드, 분류·요약 수, 이벤트 표, 자원 착지 흐름과 전역 벨 2단 구조가 없다.
- 보존 조건: 현재 규칙 생성 대화상자는 알림 서피스의 보조 탭으로 유지하고, 실시간 이벤트·토스트·확인 흐름은 단일 알림 원장으로 합친다.
- 완료 조건: 주 내비 `알림`, 진행 중 스트림, 분류 가능한 페이지 목록, 벨 배지와 동일 숫자, 행 클릭 착지가 실제 API로 동작하고 demo 1440·숫자·클릭 증거가 같은 SHA를 가리킨다.
- 상태: 미해소. Home 합격 다음 첫 서피스 배치다.

### D-6 · AI 대화 내역 서피스 부재 · 블로커

- 관측: 제품은 420px 전역 보조 패널만 있고 `/ai`, `/ai/conversations` 등 독립 라우트와 주 내비가 없다. demo의 제목·2줄 미리보기·컨텍스트 pill·저장된 대화 재개·새 대화 흐름을 제공하지 않는다.
- 완료 조건: 주 내비 `AI 대화`, 대화 목록·저장 계약, 행 클릭 재개와 새 대화가 실동작하고 기존 보조 패널은 같은 대화 원장을 소비한다.
- 상태: 미해소. 알림 합격 뒤 별도 소배치로 처리한다.

### D-7 · 리소스 3관점·트래픽 작업공간 불일치 · 블로커

- 관측: 제품은 demo의 `인프라 | 쿠버네티스 | 트래픽` 3관점 어휘, 집계 칩, 서비스 RPS·오류 요약, 클릭 포커스와 우측 스티키 관계 패널을 완결하지 못했다. CPU/MEM 등 핵심 값도 일부 `—`다.
- 완료 조건: 관점 전환 시 스코프를 보존하고, 트래픽 행 클릭·더블클릭과 토폴로지 focus가 동기화되며, 모든 핵심 값은 실제 계약 또는 명시적 불완전 상태를 보인다.
- 상태: `b184fd49e` 라이브는 구형 `지도|목록|흐름`과 API 리소스 종류 패널을 노출해 demo와 직접 불일치한다. `인프라|쿠버네티스|트래픽` 구조와 sticky 관계 패널로 교체하고 실제 관측 API를 매핑하는 P0 작업 중이다.

### D-8 · 이슈 상세 RCA·복구 흐름 단절 · 블로커

- 관측: 제품 목록은 demo의 밀도와 다르고 상세 RCA/복구 작업공간 진입이 안정적으로 이어지지 않는다. 상세 실패 상태에 재시도나 실행 가능한 다음 행동도 없다.
- 완료 조건: 카드·상세·RCA 근거·복구 실행 흐름을 단일 이슈 원장에 병합하고, 실패/부분 상태에도 재시도 또는 안전한 다음 행동을 제공한다.
- 상태: 미해소. 리소스 합격 뒤 처리한다.

### D-9 · 타임라인·점검·비용·설정 정보 밀도와 실행성 불일치 · 블로커

- 관측: 타임라인은 데이터 로드 뒤에도 필터가 화면을 과점유하고 미번역 라벨이 남는다. 점검은 수집기·discovery가 전부 unavailable, 비용은 관측 불가인데 수집 연결 행동이 없고, 설정은 알림 토글과 Prometheus/AWS/GitHub/version 상태가 빠지거나 `준비 중` 컨트롤로 남는다.
- 완료 조건:
  - 타임라인: 필터 밀도와 번역을 demo 문법으로 맞추고 지연·실패 상태에 재시도를 제공한다.
  - 점검: 수집기·discovery 수치와 불완전성 근거, 실행 가능한 복구 행동을 같은 원장에 연결한다.
  - 비용: 관측값 또는 명시적 unavailable 사유와 비용 수집 연결 행동을 제공한다.
  - 설정: 알림 토글과 Prometheus/AWS/GitHub/version 상태를 실계약에 연결하고 `준비 중` 가짜 컨트롤을 0으로 만든다.
- 상태: 미해소. 각 서피스 완료 배치에서 분리해 소거한다.

### D-10 · 갱신 시 locale·사이드바·줄바꿈 이동 · 블로커

- 관측: `b184fd49e` 라이브에서 첫 paint 뒤 서버 UI preference가 locale을 다시 적용해 영문/한글 글자폭이 바뀌고, 로딩 셸의 260px 확장 폭과 실제 compact rail 상태가 달라 본문·카드·텍스트가 이동한다.
- 원칙: locale·rail·theme은 첫 paint 전에 하나의 렌더 권위로 확정하며 데이터 갱신은 기존 슬롯의 값만 바꾼다. refresh·인증·API 완료가 레이아웃 크기나 줄바꿈을 바꾸면 안 된다.
- 완료 조건: hard reload와 30초 refresh 전후 1280/1440/1920에서 sidebar/content bounding box와 주요 텍스트 line count가 동일하고, locale이 한 번도 전환되지 않으며 CLS가 0에 수렴한다.
- 상태: prepaint persisted locale/compact rail을 로딩 셸과 실제 셸의 공통 권위로 만드는 P0 수정 중이다.

## 배포 단위

1. 첫 배치: 홈 이식·데이터 연결만 검증해 단일 후보로 배포한다.
2. 다음 UI 배치: 배포 D-1·D-2와 GitOps 아카이브 기능을 현행 D19 구조에 이식한다.
3. 이후: 알림 → AI 대화 → 배포 워크플로우 → 리소스 3관점·트래픽 → 이슈 상세 순으로 한 서피스씩 demo 대조 증거를 남긴다.
4. 타임라인·점검·비용·설정은 각 배치에서 정보 밀도·실행 가능한 빈 상태·번역·죽은 컨트롤을 함께 소거한다.
